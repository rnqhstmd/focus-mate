# PRD: W08 완료 기록·선택 메모 저장 모델

## 배경과 목표
웹의 하차 성공 완료 기록·200자 선택 메모 계약을 iOS 타입 모델과 실제 로컬 저장소로 옮긴다. W00의 버전 2와 state.records.items를 유지한다. W09 화면은 제외한다.

## 요구사항
- [Must] FR-5: 완료 기록과 연결 메모 저장·수정, 최신순 복원.
- [Must] NFR-1: 날짜·시간대 경계의 정확한 일합계, 실제 저장소 재시작 복원, 손상·중복·메모 연결 검증.

## 비즈니스 규칙
1. 하차 성공만 완료 기록을 만든다. 진행·미완료·포기는 완료 횟수/시간에 포함하지 않는다.
2. 여행 식별자로 중복을 막는다. 재요청은 기존 기록·시간·메모를 유지한다.
3. 기록 필드: 여행 식별자, 완료 시각, 완료 당시 로컬 날짜, 버스, 태그, 태그 색상, 할 일, 1~360분 완료 시간, 소리, 출발지, 도착지, 메모.
4. 선택 메모는 앞뒤 공백 제거 후 처음 200자를 저장하며 공백만 입력하면 빈 문자열로 지운다. 같은 여행 메모만 변경한다.
5. 완료 날짜는 완료 당시 로컬 YYYY-MM-DD로 확정한다. 현재 시간대가 바뀌어도 다시 계산하지 않는다. 일합계는 저장된 날짜로 합산한다.
6. 필수 정보 누락·유효하지 않은 날짜·시간 범위 위반·200자 초과 저장 메모는 손상으로 판정한다. 일부 복원 없이 전체 읽기 실패 및 원본 덮어쓰기 차단.
7. v2 및 다른 저장 영역 보존. v1 마이그레이션은 기존 W00처럼 빈 기록 영역을 갖는다.
8. 실제 파일 저장 후 새 앱 상태로 모든 필드를 동일 복원한다. 저장 실패·손상·미지원 버전에서는 파일을 보존한다.

## 수용 기준
### AC-1 정상 완료 기록 [FR-5]
Given: journey-001, 2026-10-13T01:00:00Z, Asia/Seoul, 버스2014, 독서 태그, 책 한 챕터 읽기, 25분, 성수역→서울숲 입구인 하차 성공 여행.
When: 완료 기록 저장을 한 번 수행한다.
Then: 기록1건, date=2026-10-13, minutes=25, memo="", 모든 여행 정보 동일.
### AC-2 미완료·포기 제외 [FR-5,NFR-1]
Given: 진행 journey-active, 포기 journey-abandoned와 완료0건.
When: 하차 성공 없이 두 여행의 저장 상태를 확인한다.
Then: 기록0건, 완료0회, 날짜별0분.
### AC-3 중복 완료 [FR-5,NFR-1]
Given: journey-001,25분,첫 메모인 저장 기록1건.
When: 같은 식별자로 완료를 다시 저장한다.
Then: 기록1건,25분,첫 메모 유지, 일합계25분.
### AC-4 메모 제한·연결 [FR-5]
Given: journey-001 완료1건, 공백 제거 후 가201자인 메모.
When: 해당 여행 메모를 저장한다.
Then: 가200자, 기록1건, 다른 완료 정보 불변.
### AC-5 메모 수정·삭제 [FR-5]
Given: journey-001에 첫 메모가 있다.
When: "  수정 메모  " 저장 후 공백만 다시 저장한다.
Then: 수정 메모 이후 빈 문자열, 각 기록1건.
### AC-6 시간 범위 [FR-5]
Given: 완료시간1,360,0,361인 입력.
When: 유효성을 판정한다.
Then: 1과360만 유효,0과361은 기록과 합계에 추가되지 않는다.
### AC-7 자정 경계 [NFR-1]
Given: Asia/Seoul 2026-10-13 23:59:59 완료25분,2026-10-14 00:00:00 완료35분.
When: 저장 후 날짜별 집계한다.
Then: 날짜 각각2026-10-13/2026-10-14, 합계각각25분/35분.
### AC-8 같은 날 합산 [NFR-1]
Given: 2026-10-13 완료25분/35분, 진행40분, 포기50분, 첫 완료 중복입력.
When: 해당 날짜 집계한다.
Then: 완료2회,60분.
### AC-9 시간대 변경 [NFR-1]
Given: date=2026-10-13,25분 저장 후 현재 시간대를 Seoul에서 Los_Angeles로 바꾼다.
When: 다시 읽고 날짜 집계한다.
Then: 날짜2026-10-13과 해당 일합계25분 유지.
### AC-10 실제 파일 복원 [FR-5,NFR-1]
Given: 실제 임시 app-state.json에 journey-001,2026-10-13,25분,오늘 계획을 마쳤다 메모 저장.
When: 새 앱 상태로 같은 파일에서 시작한다.
Then: 정확히1건, 모든 필드 동일 복원.
### AC-11 손상 기록·원본 보존 [NFR-1]
Given: 실제 파일에 메모201자 또는 여행 식별자 누락인 기록과 보관된 원본 바이트.
When: 읽고 정상 기록 새 저장 시도한다.
Then: 전체읽기 실패, 저장거부, 원본바이트 동일.
### AC-12 미지원 버전 보존 [NFR-1]
Given: 실제 파일의 버전3과 보관된 원본 바이트.
When: 읽고 완료·메모 저장을 시도한다.
Then: 미지원 판정, 저장거부, 원본바이트 동일.
### AC-13 다른 영역 보존 [FR-5]
Given: v2 자료의 카드·현재 정류장·진행여행 값과 빈 records.items.
When: journey-001 완료 저장한다.
Then: version2, state.records.items에1건, 다른영역 값 불변.
### AC-14 기존 자료 호환 [FR-5]
Given: W00 v1 자료 및 빈 records인 v2 자료.
When: 각각 읽는다.
Then: 기록0건, 기존 카드발급·정류장 값 동일.
### AC-15 최신순 [FR-5]
Given: 2026-10-13T01:00:00Z/03:00:00Z/02:00:00Z인 서로 다른 여행.
When: 저장 후 읽는다.
Then: 03:00/02:00/01:00 순.
