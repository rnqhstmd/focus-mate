# PRD: W17 Live Activity 디자인·집중 시간 눈금

## 배경

집중 중 앱을 열지 않고 노선·목적지·남은 시간과 상태를 확인한다. 현재 W15는 시스템 카운트다운, 일시정지 고정 시간, stale 운행의 도착 대체를 제공한다. 확장 Island에는 시간 눈금이 없고 minimal은 전체 시간 문자열을 표시하며 compact 시간 폭은 56pt다. 이 문서는 journey FR-14(미반영)를 다루는 초안이며 구현·실기기 검증 완료를 뜻하지 않는다.

## 목표

- 집중 세션 진행 정도를 가로 시간 눈금과 시스템 진행 막대로 전달한다.
- 15~360분과 running·paused·stale를 표면별 공간에 맞춰 구분한다.
- 기존 시간 진행·일시정지·완료 정책을 유지한다. 사용자 규모·출시 성공률은 기존 미확인 상태를 유지한다.

## 요구사항

### 기능 요구사항

- [Must] FR-14 / R1: 확장 Island에 노선·목적지·남은 집중 시간·상태와 가로 눈금·시스템 진행 막대와 트랙 밖 고정 버스 심볼를 제공한다. 잠금 화면에는 노선·목적지·남은 시간·상태를 제공한다.
- [Must] FR-14 / R2: compact는 짧은 시간과 상태, minimal은 상태 심볼을 제공한다. running·paused·stale를 구분하며 눈금은 확장형에만 제공한다.
- [Must] FR-14 / R3: 긴 노선·한국어 목적지는 화면에서 축약할 수 있지만 접근성에는 전체 이름을 유지한다. 상태와 남은 시간은 각각 한 번만 읽히게 한다.

### 비즈니스 규칙

- [Must] BR-1: 진행률은 집중 시간 기준 `clamp(1 - remainingSeconds / totalSeconds, 0…1)`이다. GPS·정류장 위치·실제 버스 ETA로 설명하지 않는다.
- [Must] BR-2: 일시정지 중 남은 시간과 진행 채움을 고정하고 재개 시 정지한 시간을 진행량에 포함하지 않는다.
- [Must] BR-3: 백그라운드에서도 시간은 계속 흐른다. 표시를 위해 매초 ActivityKit 갱신을 보내지 않으며 running 시간·진행 막대는 시스템 날짜 기반 표시로 자동 갱신하며 버스는 고정 여정 심볼이다. 수치 진행률은 관찰 시각의 값으로 검증한다.
- [Must] BR-4: stale 운행은 도착 상태·'도착했어요'로 대체한다. paused는 stale이어도 고정 시간을 유지한다. 정상 완료는 즉시 종료하며 취소·재실행 정리 계약을 보존한다.
- [Must] BR-5: 총 시간 누락·0·음수에서는 진행 막대·눈금를 생략하고 유효한 시간·상태를 유지한다. 유효한 총 시간의 계산 결과는 0~1로 제한한다.
- [Must] BR-6: 전체 시간과 compact 시간은 모든 길이에 시스템 분:초 카운트다운을 사용한다. 120:00·360:00을 유지한다. minimal에는 시각적인 전체 시간 문자열을 넣지 않는다.

### 품질 기대

- [Must] QE-1: 동작 줄이기에서도 시간·상태·진행 정보를 제공한다. 색·이동 애니메이션만으로 상태를 구별하지 않는다.
- [Must] QE-2: 자동 검사·미리보기·실기기 렌더링·VoiceOver 청취 결과를 구분하고 미확보 증거는 유예 사유를 기록한다.

## 사용자 시나리오

정상: 30분 집중 중 확장 Island에서 남은 시간과 집중 진행를 확인한다. 일시정지/재개: 멈춘 동안 시간·진행 채움이 고정되고 재개 후 집중한 시간만 진행한다. 장시간/긴 이름: 360분과 긴 목적지에도 축소형은 짧은 정보, 확장/잠금은 상세 정보를 제공한다. 예외: stale 운행은 도착으로 대체하고 진행 정보 없는 기존 활동은 시간·상태만 제공한다.

## 영향 범위

확장·compact·minimal Island와 잠금 화면 표시를 변경한다. 앱의 타이머 계산·저장·완료 기록은 변경하지 않는다. 변경 이전 활동에 진행 정보가 없어도 잘못된 진행률을 표시하거나 앱 여정 상태를 바꾸지 않는다.

## 수용 기준

### AC-1: 집중 시간 진행 [R1 / BR-1 / BR-3]

Given: 총 1,800초인 운행 중 세션과 고정 관찰 시각이 있다.
When: 남은 시간이 각각 1,122초와 135초인 표시 정보를 계산한다.
Then: 진행률은 각각 0.3766667과 0.925(오차≤0.000001), 전체 시간은 18:42와 2:15다. 시스템 진행 막대는 종료시각에서 총1,800초를 뺀 시각부터 종료시각까지를 사용하며, 버스는 트랙 밖 고정 여정 심볼이다. 진행은 GPS·정류장·ETA 입력을 요구하지 않는다. 백그라운드60초 후 1,122초는1,062초가 되며 시간 경과만으로 추가 활동 갱신 요청은 발생하지 않는다.

### AC-2: 일시정지·재개 [R1 / R2 / BR-2 / BR-4]

Given: 총1,800초, 남은1,122초에서 일시정지했다.
When: 300초 뒤 정지 표시를 확인하고 재개 후60초를 진행한다.
Then: 정지 중18:42·진행률0.3766667이 유지된다. 재개60초 뒤 잔여1,062초·진행률0.41이다. paused는 stale 입력에서도 유지되며 compact/minimal의 상태는 일시정지로 판별된다.

### AC-3: 만료·종료·호환성 [R2 / BR-4 / BR-5]

Given: stale 운행, 정상 완료, paused와 총 시간 누락·0·음수 사례가 있다.
When: 표시 상태와 기존 종료/정리 조건을 평가한다.
Then: stale 운행은 도착 상태·'도착했어요', paused는 고정 시간을 반환한다. 정상 완료는 즉시 종료 대상이다. 유효하지 않은 총 시간은 진행률·진행 막대·눈금를 제공하지 않고 유효한 시간·상태를 보존한다. 총1,800초에서 잔여1,900초의 진행률은0, 잔여-5초는1이다. 기존 취소·재실행 정리 사례의 종료/유지 대상은 동일하다.

### AC-4: 공간별 시간·정보 [R1 / R2 / R3 / BR-6]

Given: 잔여0:05·9:59·99:59·120:00·360:00과 긴 한국어 노선·목적지가 있다.
When: 확장·잠금·compact·minimal 표시 정보를 생성한다.
Then: 확장/잠금은 위 전체 시간을 제공한다. compact도 다섯 값을 모두 시스템 분:초로 유지한다. minimal은 상태 심볼만 제공한다. 접근성에는 전체 노선·목적지가 포함되고 각 표면의 상태와 남은 시간은 각각 한 번만 제공된다.

### AC-5: 접근성·검증 증거 [R3 / QE-1 / QE-2]

Given: 동일 running·paused·stale 사례에 동작 줄이기를 켠 경우와 끈 경우가 있다.
When: 표시 정보·접근성 요소와 검증 기록을 비교한다.
Then: 시간·상태·진행률이 같고 이동 애니메이션 없이 상태가 판별된다. 접근성 상태·시간이 중복되지 않는다. 검증 기록에는 자동 검사, 미리보기 시각 대조, 실제 Island/잠금 화면, 실제 VoiceOver 청취의 결과 또는 미확보 사유가 각각 존재한다.

## 시각 디자인 인계

차콜·오프화이트, 콘텐츠 중심. 확장형 상단 노선·남은 시간, 하단 눈금·버스·목적지, 카메라 영역 비우기. 일시정지 심볼은 한 번만, 반복 앱 아이콘·장식 곡선 제외. `designs/system-surfaces-2026-10-16/island-timeline-v2.png`와 실제 캡처를 직접 비교한다. 생성 이미지 비율·눈금 밀도·오자는 규격으로 쓰지 않는다. 긴 한국어·큰 글자·장시간·카메라 여백·잘림은 자동 동작 AC와 별도의 시각 판정으로 기록한다.
