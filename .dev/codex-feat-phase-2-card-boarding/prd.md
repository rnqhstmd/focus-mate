## PRD: Phase 2 카드·여행 준비·승차 인식

> 상태: **승인됨 — 제품 범위 및 세 TDD 검증 경계 확정**
> 기준점: PR2 병합 완료, squash `733b92c`
> 이 문서는 승인된 Phase 2 제품 요구사항이다. 테스트부터 구현·검증·PR까지 전체 과정을 진행한다.

### 배경

- 현재 iOS 제품은 저장 상태에 따라 카드 진입, 최초 정류장 설정, 현재 정류장 메인을 구분한다. 실제 카드 발급·정류장 선택·여행 준비·승차 인식은 아직 제공하지 않는다. (AppSnapshot, AppModel, RootView에서 확인)
- 현재 보존되는 값은 카드 발급 여부와 최초·현재 정류장이다. 카드 ID, 여행 준비값, 승차 인식 결과는 아직 보존되지 않는다. (AppSnapshot에서 확인)
- 손상되었거나 지원하지 않는 저장 데이터는 초기 상태로 덮어쓰지 않는다. 저장 실패도 성공으로 안내하지 않고 기존 상태를 유지한다. (LocalSnapshotStore, RootView에서 확인)
- 승인된 제품 흐름은 1회 카드 발급, 최초 정류장 설정, 15~360분 여행 선택, 태그·할 일·소리 준비, 승차권 확인, 카드 접촉 순서다. (FLOWS, MVP, animation-preview에서 확인)
- Phase 2는 승차 접촉 성공과 Phase 3 인계까지를 다룬다. 지도 이동, 실제 시간 타이머, 일시정지·재개, 하차, 완료 기록은 이후 Phase에 속한다. (DEVELOPMENT-PHASES에서 확인)
- 카드 도메인 FR-3은 Phase 2에서 발급·공통 카드·승차 접촉까지만 부분 반영한다. 사진 입력과 카드 꾸미기가 Phase 5에 남으므로 FR-3 전체 완료로 처리하지 않는다.
- 여정 도메인도 시간·준비·승차 범위만 반영한다. 실제 분 타이머, 지도, 앱 생명주기 기반 진행·복원 요구사항은 완료로 처리하지 않는다.

### 목표

- 신규 사용자가 카드 발급과 최초 정류장 설정을 한 번만 완료하고 첫 여행 준비로 이어지게 한다.
- 재방문 사용자가 저장된 현재 정류장과 방면을 유지한 채 바로 메인에서 여행을 시작하게 한다.
- 사용자가 유효한 시간·버스·도착지와 태그·할 일·소리를 확정한 뒤 승차권과 승차 인식을 완료하게 한다.
- 승차 인식 성공 결과를 한 번만 보존하여 앱 재실행 후에도 Phase 3가 동일한 준비값을 이어받게 한다.
- Phase 2가 실제 여행 진행, 도착 또는 완료 기록을 만든 것처럼 보이지 않게 한다.

### 요구사항

#### 기능 요구사항

- [Must] **P2-FR-1: 집중동행카드 1회 발급**
  - 카드가 없는 사용자는 집중동행카드를 한 번 발급받을 수 있어야 한다.
  - 카드 ID는 `FM-`과 숫자 8자리로 구성한다.
  - 발급한 카드 ID는 재실행 및 승차 인식에서도 동일하게 유지한다.
  - 이미 카드가 발급된 사용자에게 재발급을 요구하지 않는다.

- [Must] **P2-FR-2: 최초 정류장 1회 설정**
  - 카드 발급을 마친 사용자는 제공된 가상 정류장의 이름과 진행 방면을 선택해야 한다.
  - 확정값은 최초 정류장과 현재 정류장에 동일하게 보존한다.
  - 최초 설정 직후에는 현재 프로토타입과 FLOWS에 따라 첫 여행의 시간 선택으로 이동한다.
  - 최초 설정 이후에는 정류장 검색·변경·워프·초기화를 제공하지 않는다.

- [Must] **P2-FR-3: 재방문 메인과 여행 준비 진입**
  - 최초 정류장 설정을 마친 사용자가 앱을 다시 실행하면 현재 정류장 메인으로 진입해야 한다.
  - 메인에서 현재 정류장 이름과 방면을 읽기 전용으로 확인할 수 있어야 한다.
  - 여행 시작 행동을 통해 시간 선택으로 이동할 수 있어야 한다.
  - 실제 위치 추적이나 정류장 변경을 제공하지 않는다.

- [Must] **P2-FR-4: 시간·버스·도착지 확정**
  - 여행 시간은 15~360분 범위에서 1분 단위로 선택할 수 있어야 한다.
  - 선택 시간과 정확히 일치하는 가상 버스·도착지 후보만 보여줘야 한다.
  - 후보 중 하나를 명시적으로 선택해야 다음 단계로 이동할 수 있어야 한다.
  - 시간을 변경하면 기존 버스·도착지 선택을 해제해야 한다.
  - 후보가 없거나 선택하지 않은 경우 진행을 차단하고 필요한 선택을 안내해야 한다.

- [Must] **P2-FR-5: 태그와 할 일 준비**
  - 여행 준비는 태그 미선택 상태로 시작해야 한다.
  - 태그 선택 화면에서는 기존 태그 선택과 새 태그 추가만 제공해야 한다.
  - 태그 편집, 최근 할 일 예시, 기본 여행 시간 정보는 표시하지 않아야 한다.
  - 태그 선택 또는 새 태그 저장 후에는 바로 이번 여행의 할 일 입력으로 이어져야 한다.
  - 새 태그 이름은 공백일 수 없고 최대 20자여야 한다.
  - 태그 이름은 문자 표현을 통일하고 대소문자를 구분하지 않았을 때 같은 이름이면 추가할 수 없어야 한다.
  - 할 일은 공백만으로 확정할 수 없고 최대 80자여야 한다.

- [Must] **P2-FR-6: 여행 소리 선택**
  - 선택지는 `소리 없음`, `핑크 노이즈`, `빗소리`, `숲 소리`, `버스 주행`이어야 한다.
  - 최초 선택값은 현재 프로토타입과 동일하게 `소리 없음`이어야 한다.
  - 사용자는 소리를 미리 들은 뒤 확정하거나 `소리 없음`을 유지할 수 있어야 한다.
  - 소리 크기는 별도의 앱 음량이 아니라 기기 볼륨을 따라야 한다.
  - 미리듣기에 실패해도 다른 준비값이 사라지지 않아야 한다.
  - 준비 화면과 하위 선택 화면을 오가는 동안 확정값과 작성 중인 초안을 유지해야 한다.

- [Must] **P2-FR-7: 간결한 승차권**
  - 필수 준비가 완료된 경우에만 승차권에 진입할 수 있어야 한다.
  - 승차권에는 버스 번호, 출발 정류장, 도착 정류장, 여행 시간, 정류장 수, 이동 거리만 표시해야 한다.
  - 태그, 할 일, 선택 소리, 발급 상태나 출발 상태 문구는 표시하지 않아야 한다.
  - 승차권을 보는 것만으로 진행 여정이나 완료 기록을 만들지 않아야 한다.
  - 구체적인 색상·간격·글꼴·아이콘 형태는 이번 수용 기준에서 판정하지 않는다.

- [Must] **P2-FR-8: 승차 접촉 인식**
  - 사용자는 카드를 단말기 접촉 영역으로 옮기거나 카드 자체를 눌러 승차 인식을 시작할 수 있어야 한다.
  - 접근 가능한 대체 입력에서도 같은 결과를 얻을 수 있어야 한다.
  - 잘못된 위치에 카드를 놓은 경우 성공으로 처리하지 않아야 한다.
  - 인식 성공 전 뒤로 가기·화면 이탈·앱 숨김이 발생하면 승차 인계를 만들지 않아야 한다.
  - 인식 성공 후 앱이 숨겨진 경우에는 이미 성공한 인계는 보존하되 늦은 화면 전환은 실행하지 않아야 한다.
  - 같은 접촉을 중복 처리하지 않아야 한다.

- [Must] **P2-FR-9: 지속 가능한 1회 인계와 기존 사용자 보호**
  - 승차 인식 성공 순간에 카드 ID, 출발 정류장과 방면, 시간, 버스, 도착지, 태그, 할 일, 소리, 승차 인식 완료 상태를 보존해야 한다.
  - 보존은 승차 화면의 마지막 전환보다 먼저 완료되어야 한다.
  - 앱 재실행 후에도 동일한 준비값과 승차 인식 상태를 확인할 수 있어야 한다.
  - Phase 1의 기존 발급 상태에 카드 ID가 없으면 기존 최초·현재 정류장과 방면을 그대로 유지하며 ID만 한 번 보완해야 한다.
  - 기존 저장 데이터에 Phase 2 값이 없다는 이유만으로 최초 상태로 돌리거나 재발급·정류장 재설정을 요구하지 않아야 한다.
  - 손상·미지원·읽기 실패 데이터는 덮어쓰지 않아야 한다.
  - 저장 실패 시 이전 상태를 유지하고 승차 성공으로 안내하지 않아야 한다.
  - 인계에는 실제 타이머 진도, 이동 위치, 일시정지 상태, 도착 또는 완료 기록을 포함하지 않아야 한다.

#### 비즈니스 규칙

- [Must] **P2-BR-1:** 사용자에게 발급되는 집중동행카드는 한 장이며, 한 번 부여된 카드 ID는 재발급 없이 유지한다.
- [Must] **P2-BR-2:** 정류장 검색은 최초 설정에서만 허용한다. 최초 설정 직후에는 시간 선택으로 이동하고 이후 앱 실행은 현재 정류장 메인에서 시작한다.
- [Must] **P2-BR-3:** 선택 시간과 정확히 일치하는 버스·도착지 후보를 선택해야 여행 준비로 이동할 수 있다.
- [Must] **P2-BR-4:** 태그와 공백이 아닌 할 일은 필수다. 소리는 선택 사항이며 초기값은 `소리 없음`이다.
- [Must] **P2-BR-5:** 승차권의 정보는 버스 번호·출발·도착·시간·정류장 수·거리로 제한한다.
- [Must] **P2-BR-6:** Phase 3 인계는 승차 인식 성공 순간에 한 번만 생성하며, 마지막 화면 전환까지 미루지 않는다.
- [Must] **P2-BR-7:** 인식 성공 전 취소·이탈·숨김은 인계를 만들지 않는다. 인식 성공 후에는 인계를 취소하지 않고 늦은 화면 전환만 중단한다.
- [Must] **P2-BR-8:** 기존 값 보완·읽기·저장에 실패하면 최초·현재 정류장과 방면을 포함한 이전 값을 정확히 유지하고 성공으로 안내하지 않는다.
- [Must] **P2-BR-9:** Phase 2는 가상 정류장과 가상 노선을 사용하며 실제 GPS·교통카드 인증·실시간 운행·실제 여행 진행·완료 기록을 제공하지 않는다.

### 승차 단말기 상태·시간 명세

이 항목은 상태 전환과 사용자 안내를 판정하기 위한 명세이며 시각 스타일을 지정하지 않는다.

- 대기 상태에서는 `Focus Mate`, 기기의 실제 로컬 `HH:mm`, `작은 시작이 오늘을 바꿔요.`를 표시한다.
- 인식 성공 후에는 현재 카드 이름과 카드 ID를 표시한다.
- 일반 동작 순서는 접촉 이동 300ms → 인식 상태 유지 1400ms → 페이드 450ms → Phase 3 인계 대기 상태다.
- 승차 인계 저장 시점은 300ms 접촉 이동이 끝나고 인식 성공이 확정된 순간이다. 1400ms 유지나 450ms 페이드 완료까지 미루지 않는다.
- 동작 줄이기가 적용되면 접촉 이동·페이드·햅틱을 생략하되, 인식 성공 상태와 1400ms 안내는 유지한다.
- 실제 기기에서의 음질·음량·햅틱 감각과 화면의 시각적 완성도는 이 시간 명세의 수용 범위가 아니다.

### 사용자 시나리오

#### 정상 흐름: 신규 사용자

1. 카드가 없는 사용자가 앱을 연다.
2. 집중동행카드를 발급받고 카드 ID를 확인한다.
3. 최초 출발 정류장 이름과 방면을 선택한다.
4. 최초 설정 직후 첫 여행의 시간 선택으로 이동한다.
5. 시간을 선택하고 그 시간에 맞는 버스·도착지를 선택한다.
6. 기존 태그를 선택하거나 새 태그를 추가하고 할 일을 입력한다.
7. 소리를 선택하거나 초기값인 `소리 없음`을 유지한다.
8. 여섯 가지 운행 정보만 담긴 승차권을 확인한다.
9. 카드를 단말기에 접촉한다.
10. 승차 인식 성공 시 준비값이 한 번 보존되고 Phase 3 인계 대기 상태가 된다.

#### 정상 흐름: 재방문 사용자

1. 앱 실행 시 카드 발급과 최초 정류장 선택을 반복하지 않는다.
2. 저장된 현재 정류장과 방면이 메인에 읽기 전용으로 표시된다.
3. 여행 시작을 선택해 시간 선택으로 이동한다.
4. 앱 내부에서는 현재 정류장을 검색하거나 다른 정류장으로 이동할 수 없다.

#### 예외 흐름

- 선택 시간에 맞는 후보가 없으면 다음 단계로 이동하지 못한다.
- 시간을 변경하면 이전 버스·도착지 선택이 해제된다.
- 태그가 없거나 할 일이 공백 또는 80자를 넘으면 승차권 진입이 차단된다.
- 새 태그 이름이 공백·20자 초과·정규화 후 중복이면 저장하지 않고 이유를 안내한다.
- 소리 미리듣기에 실패해도 태그·할 일·여정 선택은 유지된다.
- 카드를 접촉 영역 밖에 놓으면 승차 성공으로 처리하지 않는다.
- 인식 성공 전에 앱이 숨겨지면 인계를 만들지 않는다.
- 인식 성공 후 화면 전환 전에 앱이 종료되어도 이미 성공한 인계는 남는다.
- 기존 저장 데이터가 손상되거나 지원하지 않는 버전이면 재발급 상태나 빈 상태로 덮어쓰지 않는다.
- 저장에 실패하면 성공 안내나 다음 단계 전환을 하지 않고 이전 값을 유지한다.

### 영향 범위

- 카드 진입은 실제 1회 카드 발급 경험으로 확장된다.
- 최초 정류장 진입은 실제 가상 정류장·방면 선택으로 확장된다.
- 현재 정류장 메인은 읽기 전용 정류장 정책을 유지하며 여행 준비 진입점을 제공한다.
- 기존 version 1 저장 사용자는 최초·현재 정류장 ID·이름·방면을 그대로 유지한다.
- 카드 발급 여부만 있고 ID가 없는 사용자는 재발급 없이 카드 ID를 한 번 보완한다.
- 카드 ID, 여행 준비값, 승차 인식 인계가 새로운 보존 대상이 된다.
- 기존 저장값에 새 항목이 없다는 사실은 손상으로 간주하지 않는다.
- 손상·미지원·읽기 실패 데이터 보호와 저장 성공 후에만 사용자 상태를 확정하는 기존 동작은 유지한다.
- 카드 도메인 FR-3은 부분 반영이다. 사진 입력과 꾸미기는 Phase 5까지 미완료로 남는다.
- 여정 도메인의 실제 분 타이머·지도·일시정지·재개·생명주기 진도는 Phase 3까지 미완료로 남는다.
