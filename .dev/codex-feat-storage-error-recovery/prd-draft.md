# PRD: W13 저장 오류 복구

상태: 초안 — 내보내기 포함 여부 사용자 확인 대기. 전체 과정 / 표준 프로파일.

## 배경
현재 iOS 앱은 손상·미지원 버전·내용 불일치·읽기 실패에서 시작을 막고 원본을 보존하지만 복구 동작은 없다. W00의 저장 v2 구조를 유지하며 preferences FR-4(미반영)를 구현한다. 손상에는 미래 형식일 수 있는 파일도 섞이므로 자동 정리는 금지한다.

## 목표
원본을 변경하지 않는 재시도와, 명시적 확인 후 동일 바이트 백업이 성공해야 진행되는 정리를 제공한다. 취소와 백업 실패 시 활성 원본을 보존한다.

## 요구사항
### 기능 요구사항
- [Must] FR-4a: 시작 오류 화면에 오류 원인, 다시 시도, 저장 데이터 정리를 제공한다.
- [Must] FR-4b: 같은 데이터를 다시 읽고 성공하면 저장된 상태의 시작 화면으로, 실패하면 최신 오류 화면으로 이동한다.
- [Must] FR-4c: 정리 전에 초기화 결과와 백업 선행 조건을 안내하고 확인·취소를 제공한다.
- [Must] FR-4d: 확인 후 원본과 동일한 바이트의 백업을 확인한 뒤에만 활성 데이터를 정리하고 첫 시작 화면으로 이동한다.
- [Must] FR-4e: 백업·정리 실패를 성공으로 안내하지 않고 오류 화면과 재시도 동작을 유지한다.
- [Could / 미확정] FR-4f: 보존 원본의 외부 내보내기. 사용자 결정 후 범위 확정.

### 비즈니스 규칙
- [Must] BR-1: 재시도·확인 화면 진입·취소는 원본을 변경하지 않는다.
- [Must] BR-2: 모든 오류에서 자동 정리를 금지하고 정리마다 명시적 확인을 받는다.
- [Must] BR-3: 버전 1·2 읽기, 버전 2 저장 계약을 유지한다. 0 이하·3 이상 정수는 미지원, 숫자가 아닌 버전은 손상이다.
- [Must] BR-4: 동일 바이트 백업 확인 실패 시 활성 원본 정리를 시작하지 않는다.
- [Must] BR-5: 정리 후 기존 저장 데이터 없음 경험을 사용하며 저장 스키마를 변경하지 않는다.

## 사용자 시나리오
- 정상 복구: 일시적 읽기 실패 → 다시 시도 → 저장 상태의 기존 시작 화면.
- 재시도 실패: 오류 화면 유지, 최신 오류 안내, 원본 보존.
- 정리 취소: 오류 화면 복귀, 원본·백업 상태 불변.
- 정리 성공: 명시적 확인 → 동일 원본 백업 확인 → 활성 데이터 정리 → 첫 시작 화면.
- 보존 실패: 정리 중단, 원본·오류 화면 유지.
- 미지원 버전: 자동 변환·정리 없이 재시도 또는 확인 후 정리만 제공.

## 영향 범위
iOS 시작 오류 화면, 복구 후 진입 흐름, 활성 app-state 원본 및 보존 백업. 정상 v1·v2 시작 흐름 유지. 웹 동작은 범위 밖이다.

## 수용 기준
### AC-1: 복구 선택지 [FR-4a / BR-2]
Given: 손상·미지원 정수 버전·내용 불일치·읽기 실패로 시작이 중단되어 있다.
When: 오류 화면이 표시된다.
Then: 오류 원인과 다시 시도·저장 데이터 정리가 제공되고 자동 실행은 없다.

### AC-2: 재시도 성공 [FR-4b / BR-1 / BR-5]
Given: 첫 읽기는 실패했지만 동일한 활성 데이터의 다음 읽기는 성공할 수 있다.
When: 다시 시도를 선택한다.
Then: 저장 상태에 맞는 기존 시작 화면으로 이동하고 재시도에 의한 활성 원본 쓰기는 0회다.

### AC-3: 재시도 실패 [FR-4b / FR-4e / BR-1]
Given: 재시도에서도 활성 데이터를 읽지 못한다.
When: 다시 시도를 선택한다.
Then: 최신 오류를 표시하고 오류 화면을 유지하며 원본 쓰기·삭제는 0회다.

### AC-4: 정리 취소 [FR-4c / BR-1 / BR-2]
Given: 정리 확인 화면에 초기화 결과와 백업 선행 조건이 표시된다.
When: 취소한다.
Then: 오류 화면으로 돌아오고 원본 바이트는 동일하며 백업 생성·첫 시작 전환은 없다.

### AC-5: 원본 보존 후 정리 [FR-4c / FR-4d / BR-2 / BR-4 / BR-5]
Given: 사용자가 확인했고 백업과 활성 데이터 정리를 완료할 수 있다.
When: 정리가 완료된다.
Then: 백업 바이트는 정리 전 원본과 정확히 같고 활성 오류 데이터가 시작을 막지 않으며 저장 데이터 없음의 첫 시작 화면을 표시한다.

### AC-6: 원본 보존 실패 [FR-4d / FR-4e / BR-1 / BR-4]
Given: 사용자가 확인했지만 백업 생성 또는 동일 바이트 확인이 실패한다.
When: 정리가 실패 결과를 반환한다.
Then: 원본은 동일하고 첫 시작으로 이동하지 않으며 원본 보존 실패로 정리 미완료 안내와 재시도 동작이 표시된다.

### AC-7: 백업 후 정리 실패 [FR-4e / BR-4]
Given: 동일 백업은 확인됐지만 활성 데이터 정리가 실패한다.
When: 정리 절차가 종료된다.
Then: 오류 화면을 유지하고 성공·첫 시작을 표시하지 않으며 백업 바이트는 정리 전 원본과 같다.

### AC-8: 버전 경계 [FR-4a / BR-2 / BR-3 / BR-5]
Given: 정상 v1·v2, 0 이하·3 이상 정수 버전, 숫자가 아닌 버전 파일이 각각 있다.
When: 각 파일을 읽는다.
Then: 정상 v1·v2만 기존 시작으로 진입하며 범위 밖 정수는 미지원, 숫자가 아닌 값은 손상 안내를 표시하고 오류 원본은 확인 전 변경되지 않는다.

## 제외 범위
웹 변경, 스키마 v3·v2 구조 변경, 미지원 버전 자동 변환, 클라우드·계정·기기간 복원, 일반 저장 실패 후 편집 재저장 흐름. 외부 내보내기는 사용자 결정 전 미확정이다.
