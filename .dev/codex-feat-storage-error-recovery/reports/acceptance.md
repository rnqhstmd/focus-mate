## 인수 검증 결과

### 수용 기준 충족 여부

| # | 수용 기준 | 충족 | 근거 |
|---|----------|------|------|
| 1 | 손상·미지원 버전·내용 불일치·읽기 실패에서 오류 원인과 다시 시도·저장 데이터 정리를 제공하며 자동 정리하지 않는다. | O | 네 오류 원인이 구분되고 두 복구 선택지가 표시되며 화면 진입만으로 원본이나 백업이 바뀌지 않는 경험을 확인했다 (저장 오류 화면, StorageRecoveryFlowTests에서 확인). |
| 2 | 다음 읽기가 성공하면 저장 상태에 맞는 기존 시작 화면으로 돌아가며 활성 원본을 쓰지 않는다. | O | 일시적 읽기 실패 뒤 다시 시도하면 저장된 현재 정류장과 방향이 복원되고 원본·백업이 그대로 유지된다 (재시도 흐름, AppRecoveryTests와 StorageRecoveryFlowTests에서 확인). |
| 3 | 재시도도 실패하면 최신 오류와 복구 선택지를 유지하며 원본을 쓰거나 삭제하지 않는다. | O | 재시도 결과가 이전 오류와 다를 때 최신 원인이 반영되고, 계속 읽을 수 없는 경우에도 오류 화면·다시 시도·원본·백업이 유지된다 (재시도 실패 흐름, AppRecoveryTests와 StorageRecoveryFlowTests에서 확인). |
| 4 | 정리 전에 초기화 결과와 내부 백업 선행 조건을 안내하고, 취소하면 원본·백업·시작 화면을 바꾸지 않는다. | O | 카드·여행·기록 초기화와 내부 원본 보존 안내, 확인·취소가 제공되며 취소 후 오류 화면과 기존 저장물이 유지된다 (정리 확인 화면, AppRecoveryTests와 StorageRecoveryFlowTests에서 확인). |
| 5 | 명시적 확인 뒤 원본과 같은 내부 백업을 확인한 경우에만 활성 오류 데이터를 정리하고 첫 시작 화면으로 이동한다. | O | 손상 및 미지원 데이터 모두 동일 바이트 백업이 남고 활성 오류 데이터가 사라진 뒤 첫 시작 화면으로 이동하며, 재실행 후에도 같은 결과가 유지된다 (저장 데이터 정리 흐름, StorageRecoveryTests·AppRecoveryTests·StorageRecoveryFlowTests에서 확인). |
| 6 | 백업 생성 또는 동일 바이트 확인이 실패하면 원본과 오류 화면을 유지하고 정리 미완료 및 재시도를 제공한다. | O | 백업 실패와 다른 바이트 백업 모두 첫 시작 전환을 막고 원본을 유지하며, 사용자에게 정리 미완료와 다시 시도·재정리 선택지를 제공한다 (원본 보존 실패 흐름, StorageRecoveryTests·AppRecoveryTests·StorageRecoveryFlowTests에서 확인). |
| 7 | 정확한 백업 뒤 활성 데이터 정리가 실패하면 성공으로 안내하지 않고 오류 화면과 정확한 백업을 유지한다. | O | 정리 실패 시 첫 시작으로 이동하지 않고 내부에 정확한 백업을 유지한다. 후속 요청·취소 뒤에도 원본이 그대로라는 일괄 보장을 다시 표시하지 않는다 (정리 실패 흐름, RecoveryHistoryTests와 RecoveryHistoryFlowTests에서 확인). |
| 8 | 정상 v1·v2만 기존 시작으로 진입하고, 0 이하·3 이상 정수는 미지원, 숫자가 아닌 버전은 손상으로 안내하며 확인 전 원본을 바꾸지 않는다. | O | v1·v2 읽기와 v2 저장 경험이 유지되고, 허용 범위 밖 정수와 숫자가 아닌 버전은 복구 대상 오류로 남아 자동 변환·정리되지 않는다 (저장 버전 규칙, StorageV2Tests와 StorageRecoveryTests에서 확인). |

### 우선순위별 구현 상태

- [Must] 전체 11건 중 11건 구현 완료
- [Should] 전체 0건 중 0건 구현 완료, 0건 미구현
- [Could] 전체 0건 중 0건 구현 완료, 0건 미구현

### 비즈니스 정합성

비즈니스 정합성 이슈 없음.

- 복구는 원본을 바꾸지 않는 재시도와 사용자의 명시적 확인을 받은 정리로 구분된다.
- 정리는 동일 원본의 내부 백업이 확인된 뒤에만 진행되며, 보존 또는 정리 실패를 성공으로 안내하지 않는다.
- 보존 원본은 앱 내부에만 남고 외부 내보내기·공유 경험은 추가되지 않았다.
- 정상 v1·v2 시작 경험과 v2 저장 계약이 유지되며, 미지원 파일의 자동 변환·자동 정리는 추가되지 않았다.
- 최신 전체 검증에서 웹 31건과 경계 검증, iOS 단위 141건·UI 21건, Debug·Release 빌드가 모두 통과했고 검증 상태와 지문이 확정됐다 (verify.md에서 확인).

### 검증 경계

실기기와 VoiceOver 실제 포커스 이동은 P6 미검증 항목으로 남아 있다. 이번 인수는 W13의 자동 검증 범위 완료를 의미하며, 해당 직접 사용성 검증까지 완료됐다는 판정으로 확장하지 않는다.

### 판정

- **ACCEPT**: 모든 [Must] 요구사항과 AC-1~8을 충족했다. 승인된 내부 원본 보존 전용 범위로 인수 완료.
