## PRD: W09a 하차 태그·요약·기록·메모 + 마이페이지 큰 글자 회귀 수정

### 배경
- 근거 FR: journey FR-12(AC-14), records FR-6(AC-7)의 하차·요약·기록·메모 부분, card FR-5(마이페이지) 회귀 수정. 새 FR ID는 만들지 않고 인용한다. 아래 FR-N은 이 PRD 안에서만 쓰는 번호다.
- 이번 범위는 W09a다. 분석(주/월·태그 분석과 인사이트)은 W09b로 분리했다(2026-10-15 사용자 결정).
- 현재 제품 상태
  - 타이머가 0이 되면 "도착했어요"만 보이는 임시 도착 화면(journey.arrived)이 뜬다. 나가는 길이 없어 앱을 다시 켜야 메인으로 간다. 도착 안내·하차 태그·완료 기록은 없다. 이 때문에 W09 전에는 TestFlight를 포함한 외부 배포가 금지돼 있다.
  - 메인의 "도착한 여정이 있어요" 카드는 "새 여정 시작"만 있다. 확정하면 도착지가 현재 정류장이 되고 여정이 지워지며, 완료 기록은 남지 않는다. 임시 동작이다.
  - 완료 기록 저장과 메모 저장 규칙은 이미 있다(W08). 하차 성공만 기록으로 인정하고, 같은 여정 번호는 1건만 남기며, 메모는 최대 200자다. 어떤 화면도 이를 호출하지 않는다.
  - 기록 화면은 "아직 여행 기록이 없어요."만 있는 빈 화면이다. 마이페이지는 완료 기록에서 완료 여정 수와 시간을 읽는다(W11).
  - 승차 태그(카드 끌어 30% 겹침 인식, 1400ms 유지, 450ms 전환)와 출발 안내(세 문장, "시작" 버튼)가 있다(W04). LCD에는 카드 이름과 체크만 표시하고 카드 번호는 표시하지 않는다.
  - 도착하면 잠금 화면·다이나믹 아일랜드 표시(Live Activity)는 종료 대상이다(W15).
  - 웹 프로토타입 기준선(designs/prototype/index.html): 잔디 5단계는 하루 합계 0 / 1~30 / 31~60 / 61~120 / 121분 이상. 날짜별 목록은 최신순 10개씩 더 보기, 연도 단위 이동.
  - 버그: 마이페이지 최대 글자 크기(접근성 XXXL)에서 ProfileUITests `testAC20_최대_글자_크기에서_주요_요소가_스크롤로_가시_영역에_들어온다`, `testAC20_최대_글자_크기에서_설정을_눌러_설정에_가고_뒤로_돌아온다`가 실패한다. W07 머지 전 main에서도 실패하던 기존 결함. 원인 분석은 설계 단계.
- 규모: 대형(신규 화면 3종, 여러 기능에 걸친 변경).

### 목표
- 여행을 끝낸 사용자가 도착 안내 → 확인 → 하차 태그 → 요약 → 메인으로 막힘없이 마무리하고, 그 여행이 기록에 정확히 1건 남는다.
- 사용자가 기록 화면에서 지난 여행을 날짜·연도별로 돌아보고 메모를 남기거나 고친다.
- 도착 후 앱을 다시 켜야만 메인으로 가던 문제가 사라져 외부 배포 차단이 풀린다.
- 큰 글자 사용자가 마이페이지 모든 항목에 도달하고 설정 왕복을 한다.

### 요구사항
#### 기능 요구사항
- [Must] FR-1 도착 안내: 타이머가 끝나면 도착 안내를 보여준다. 노선은 "버스 번호 · 도착 정류장 도착". "곧 ○○에 도착합니다", "버스가 멈추면 일어나주세요", "카드를 찍고 내려주세요" 세 문장이 약 1.7초씩 차례로 나타나고 마지막 문장은 남는다. 그 뒤 **확인** 버튼이 나타난다. 안내 중 일시정지·포기 없음, 완료 기록 없음. 동작 줄이기가 켜져 있으면 세 문장을 한꺼번에 보여준다. [journey FR-12]
- [Must] FR-2 도착 대기 복원: 도착 시점에 "하차 대기" 상태가 저장된다. 안내 중이나 하차 태그 중에 앱을 벗어나거나 종료해도, 다시 켜면 메인에 도착한 여정 카드가 있고 그 카드의 **하차하기**로 도착 안내부터 다시 시작한다. 도착 후 잠금 화면 표시는 종료된다. [journey FR-12]
- [Must] FR-3 하차 태그: **확인**을 누르면 하차 태그 화면으로 간다. 승차 태그와 같은 조작(끌어서 30% 이상 겹치면 놓기 전 인식, 터치만으로는 태그되지 않음, VoiceOver·키보드 활성화는 바로 인식). LCD에는 카드 이름과 체크만 표시하고 카드 번호와 "하차 완료"는 표시하지 않는다. 하차 태그 화면에는 뒤로가기가 없다. [journey FR-12]
- [Must] FR-4 하차 완료 저장: 하차 접촉이 성공한 1회에만, 한 번의 저장으로 (a) 완료 기록 1건 생성 (b) 도착 정류장을 현재 정류장으로 저장(방향 유지) (c) 진행 여정(재개 정보) 제거를 모두 수행한다. 중복 접촉에도 기록·저장은 1회. 저장 실패 시 화면을 넘기지 않고 같은 화면에서 다시 태그할 수 있으며, 세 결과가 하나도 일어나지 않는다. [journey FR-12, records FR-6]
- [Must] FR-5 완료 기록 내용: 여정 번호, 하차 접촉 성공 시각, 로컬 날짜, 버스, 태그와 태그 색, 할 일, 여행 시간(분), 소리, 출발·도착 정류장 이름, 빈 메모. 도착 정류장은 저장된 도착지. [records FR-6]
- [Must] FR-6 하차 후 요약: 하차 접촉 성공 후 전환을 마치면 요약 화면. 한 일, 여행 시간, 도착 정류장, 200자 선택 메모 입력, **메인으로** 버튼. 메모는 건너뛸 수 있다. 입력하면 해당 기록의 메모로 저장. 메모 저장 실패 시 입력 유지·재시도. [records FR-6]
- [Must] FR-7 메인 복귀: **메인으로** → 메인, 진행 여정 카드 없음, 현재 정류장은 도착지. 요약 도중 앱 종료 → 재실행 시 요약 없이 메인, 기록은 저장돼 있고 메모는 기록 화면에서 남긴다. [journey FR-12]
- [Must] FR-8 도착 여정 처리 확정: 도착한 여정이 있으면 메인 도착 여정 카드의 동작은 **하차하기** 하나뿐(누르면 도착 안내부터 다시 시작). 하차를 미루고 새 여정을 시작하거나 기록 없이 도착 여정을 정리하는 경로는 없다. 기존 임시 "새 여정 시작"과 `journey.arrived` 임시 화면은 이 흐름으로 대체한다. [journey FR-12]
- [Must] FR-9 기록 화면: 연 단위 일합계 잔디, 선택 날짜의 기록 목록, 연도 이동.
  - 잔디: 선택 연도의 모든 날짜 격자. 하루 합계 0분 = 0단계, 1~30 = 1, 31~60 = 2, 61~120 = 3, 121 이상 = 4.
  - 날짜 선택: 오늘 이후 선택 불가. 처음에는 오늘 선택.
  - 목록: 선택 날짜 기록을 최신 하차 시각 순 최대 10개, 11건 이상이면 **더 보기**로 10개씩 증가.
  - 연도 이동: 이전/다음 연도와 연도 선택. 올해 이후 불가. 연도를 바꾸면 선택 날짜는 올해면 오늘, 아니면 그 해의 가장 최근 기록일(없으면 1월 1일).
  - 요약 줄: "N회 여행 · N일 · 시간".
  - 기록 0건 안내: "첫 여행을 마치면 잔디에 색이 채워져요. 하루하루 나만의 시간을 모아보세요." 기록이 있고 선택 날짜만 비면 "이날은 완료한 여행이 없어요." [records FR-6]
- [Must] FR-10 메모 수정: 기록 목록에서 각 기록의 메모를 남기거나 고친다(최대 200자). 없으면 "메모 남기기", 있으면 "메모 수정". 저장 실패 시 입력 유지·안내. [records FR-6]
- [Must] FR-11 예시 기록 비노출: 예시 기록을 화면에 노출하지 않고 저장하지 않는다. 기록 화면과 마이페이지는 실제 완료 기록만 사용한다. [records FR-6]
- [Must] FR-12 마이페이지 큰 글자 회귀 수정(card FR-5): 최대 글자 크기에서 카드, 카드 꾸미기, 완료 여정 통계, 시간 통계, 설정 행이 모두 스크롤로 보이는 영역에 들어오고, 설정 왕복이 된다.

#### 비즈니스 규칙
- [Must] BR-1: 완료 기록은 하차 접촉 성공에서만 생긴다. 도착 안내 노출, 안내 확인, 앱 재실행은 기록을 만들지 않는다.
- [Must] BR-2: 한 여정은 최대 1건(같은 여정 번호 중복 불가). 이미 기록된 여정의 중복 하차 접촉은 무시한다.
- [Must] BR-3: 하차 성공의 세 결과(기록 생성·도착지 반영·재개 정보 제거)는 모두 일어나거나 모두 일어나지 않는다.
- [Must] BR-4: 메모 최대 200자. 초과 입력은 입력 단계에서 200자까지만, 저장 시 앞뒤 공백 제거, 공백만이면 메모 없음.
- [Must] BR-5: 날짜는 하차 시점의 기기 로컬 날짜.
- [Must] BR-6: 도착 안내·하차 태그 도중, 그리고 도착 여정이 남아 있는 동안 포기·일시정지·새 여정 시작 불가.
- [Should] BR-7: 저장 도착지가 계산 도착지와 다르면 도착 안내에서도 지도 생략(W06 규칙). 도착 상태에서 지도 도구 비활성, 정류장 목록 접힘.
- [Should] BR-8: 마이페이지 완료 여정 수·시간은 하차 기록 저장 후 별도 작업 없이 증가.

#### 품질 기대
- [Should] QE-1: 하차 후 앱 재실행 없이 메인 도달.
- [Should] QE-2: 기록 0건·저장 실패·선택 날짜 기록 없음에서 다음 행동을 알 수 있는 한 줄 안내.
- [Should] QE-3: 새 화면의 모든 조작 요소는 접근성 식별자·낭독 문구를 갖고 최대 글자 크기에서도 스크롤로 도달. 실기기 VoiceOver·햅틱은 W14.

### 사용자 시나리오
- 정상: 타이머 0초 → 도착 안내 세 문장 → 확인 → 하차 태그 → 1400ms·450ms 뒤 요약 → 메모 → 메인으로 → 새 여정 시작 가능, 기록 화면 오늘 칸 채워짐, 마이페이지 수치 증가.
- 메모 건너뛰기: 메모 없이 메인으로, 기록은 빈 메모, 기록 화면에서 나중에 메모.
- 예외: 하차 저장 실패 → 화면 유지·안내·재태그 재시도. 메모 저장 실패 → 입력 유지·안내·재시도.
- 중단/복원: 도착 직후/안내 중/하차 태그 중 종료 → 메인 도착 여정 카드(하차하기), 기록 없음. 하차 성공 직후/요약 중 종료 → 메인, 기록 1건, 여정 없음.
- 엣지: 연타 → 기록 1건. 기록 0건 기록 화면 → 빈 안내. 12월 31일 23:50 하차 → 12월 31일. 11건 이상 → 10개 + 더 보기. 메모 200/201자.

### 영향 범위
- 여정: 도착 상태 화면(journey.arrived), 메인 진행 여정 카드의 도착 종류, 승차 태그 재사용, 도달 정류장 저장.
- 기록: 빈 기록 화면 → 실제 기록 화면. W08 저장 규칙 재사용.
- 마이페이지: 통계 자동 증가(W11), 큰 글자 회귀 수정.
- 잠금 화면 표시(W15): 도착 시 종료, 하차 후 남지 않음.
- 저장 형식 변경 없음. 업데이트 전 도착 상태 여정은 새 하차 흐름으로 진입.
- 메인 "도착한 여정이 있어요 / 새 여정 시작" 임시 카드 → "하차하기" 카드.

### 수용 기준
AC-1: 도착 안내 노출 → [FR-1]
  Given: 진행 중 여정의 남은 시간이 1초이고 동작 줄이기가 꺼져 있다
  When: 타이머가 0초가 된다
  Then: 노선 문구 "버스번호 · 도착정류장 도착"과 "곧 ○○에 도착합니다"가 보인다. 이어서 1.7초 간격으로 "버스가 멈추면 일어나주세요", "카드를 찍고 내려주세요"가 순서대로 나타난 뒤 **확인**(`alighting.confirm`) 버튼이 보인다. 그동안 일시정지·포기 버튼은 없고 완료 기록은 0건이다.

AC-2: 동작 줄이기 도착 안내 → [FR-1]
  Given: 동작 줄이기가 켜져 있고 AC-1과 같은 상태다
  When: 타이머가 0초가 된다
  Then: 세 문장과 **확인** 버튼이 한꺼번에 보인다.

AC-3: 도착 상태 저장 → [FR-2]
  Given: 진행 여정이 있다
  When: 타이머가 0초가 된다
  Then: 저장된 여정이 도착 상태(진도 = 총 시간)이고 저장 횟수는 도착 1회다. 완료 기록은 0건이다.

AC-4: 도착 안내 중 종료 후 복원 → [FR-2, BR-1]
  Given: 도착 안내가 떠 있다
  When: 앱을 종료하고 다시 실행한다
  Then: 메인에 도착한 여정 카드가 보이고, 카드의 **하차하기**(`open.alighting`)를 누르면 도착 안내가 처음부터 다시 나타난다. 완료 기록은 0건이다.

AC-5: 도착 시 잠금 화면 표시 종료 → [FR-2]
  Given: 진행 중 잠금 화면 표시가 1개 있다
  When: 타이머가 0초가 되고, 또는 도착 상태로 앱을 재실행한다
  Then: 남아 있는 잠금 화면 표시가 0개다(종료 요청 기록 확인). 하차 완료 후에도 0개다.

AC-6: 확인 후 하차 태그 이동 → [FR-3]
  Given: 도착 안내의 **확인** 버튼이 보인다
  When: **확인**을 누른다
  Then: 하차 태그 화면(`alighting.tag`)으로 이동하고 포커스는 카드에 있다. 완료 기록은 0건이다.

AC-7: 하차 LCD 표기 → [FR-3]

### 제외 범위
- 분석 화면(주/월 합계, 태그 비중·필터, 이전 기간 비교, 마친 시간대, 노선 상위 3, 길이 분포, 최장 연속일, 메모 회고)은 W09b로 이관.
- 실기기 VoiceOver·햅틱·실제 iPhone 큰 글자는 W14.
- 기록 삭제·내보내기·검색·보관 기간 정책 제외.
- 하차 후 바로 새 여정 지름길, 요약 공유 제외.
- 카드 교체, 잠금 화면 표시 디자인 변경 제외.
