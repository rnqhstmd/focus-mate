## PRD: 승차권 · 승차 태그 · 출발 안내 (journey FR-11, status.md 미반영, 작업 W04) — 확정판

규모: 대형 (신규 화면 3개와 진행 여정 저장 신설, 메인·준비·카드·기록 기능과 연동)

### 배경
- 현재 제품 상태
  - 준비 화면(PreparationView)에서 여정·태그·할 일을 확정하면 '승차권 보기' 버튼이 켜진다. 소리는 기본값(버스)이 항상 있어 완성 여부에 영향을 주지 않는다. 버튼을 누르면 준비 확정만 되고 어느 화면으로도 이동하지 않는다.
  - 승차권, 승차 태그, 여행, 출발 안내 화면이 없다. 목적지 중 해당하는 것은 제목 자리표시뿐이다.
  - 진행 여정의 저장 형식이 정해져 있지 않다. 현재 저장소는 진행 여정이 들어 있으면 손상으로 취급한다(JourneySection).
  - 메인 화면의 여행 버튼(식별자 open.preparation, 현재 글자 '여행 준비')은 여행 준비 진입점이다. 진행 중인 여정 안내는 없다. W04에서 글자를 '여행 시작하기'로 바꾼다(설계 Q&A 사용자 결정).
  - '시작' 뒤에는 빈 '여행' 임시 화면을 두고 왼쪽 위 뒤로가기로 메인에 돌아간다(설계 Q&A 사용자 결정). W05가 이 자리에 실제 여행 화면을 넣는다.
  - 카드는 집중동행카드 이름과 꾸민 외형을 가진다. 카드 번호는 화면에 표시하지 않는다(PassIdentity).
- 사용자가 확정한 결정
  - 시안(Pen 렌더)과 docs/FLOWS.md를 기준으로 구현한다. '최신 승차 단말기' 브라우저 확인은 보류하며 미검증으로 기록한다.
  - 출발 안내는 FLOWS.md 2차 계약(세 문장이 차례로, 마지막에 '시작' 버튼)을 채택한다. 최신 렌더 DO8HO와 일치. ':62'의 '확인' 버튼 계약은 폐기하며 문서 정리는 별도 건이다.
  - Phase-1 시절 초안(P2-AC-10~14)은 참고만 한다.
  - 재실행·중복 여정: 앱을 열면 메인에서 "진행 중인 여정이 있다"고 알린다. 이어가기와 여행 화면 복귀는 하지 않는다(W07). 이 상태에서 메인의 '여행 시작하기'를 누르면 저장된 진행 여정을 완료 기록 없이 자동 폐기하고 새 여행 흐름(시간 선택)을 시작한다.
  - 진행 여정이 남은 상태에서 새 승차권 진입은 막지 않는다. 새 인식은 기존 진행 여정을 교체한다. 저장된 진행 여정은 항상 최대 1건이다.
  - 승차 태그 화면의 뒤로가기는 승차권 화면으로 돌아간다.
  - 접촉 성공 시 저장이 실패하면 멈추고 다시 태그할 수 있게 한다.
- 이번 작업은 "준비 확정 → 승차권 → 승차 태그 → 진행 여정 저장 → 여행 화면(자리표시) → 출발 안내 → 시작 확인" 흐름이다.

### 목표
- 준비를 마친 사용자가 승차권을 보고, 카드를 단말기에 대어 여정을 시작하는 경험을 완성한다.
- 접촉이 성공한 순간 진행 여정이 반드시 한 번 저장되어, 이후 어떤 이탈이 있어도 유실·중복되지 않는다.
- 성공 지표: 미완성 준비로 승차권 진입 경로 0건 / 접촉 성공당 저장 정확히 1건, 저장된 진행 여정 최대 1건 / VoiceOver·키보드 사용자도 끌기 없이 태그 완료 / 재실행 시 메인에서 진행 중인 여정을 알 수 있음.

### 요구사항

#### 기능 요구사항
- [Must] FR-1: 승차권 진입 차단과 진입 (journey FR-11, status.md 미반영)
  - 준비 완성(여정, 태그, 공백이 아닌 할 일이 모두 있음)에서 '승차권 보기'를 누르면 승차권 화면으로 이동한다. 소리는 기본값이 있어 완성 조건이 아니다.
  - 하나라도 없으면 '승차권 보기'가 잠기고 어떤 경로로도 승차권 화면에 들어갈 수 없다.
  - 진행 여정이 저장되어 있어도 승차권 진입은 막지 않는다.
- [Must] FR-2: 승차권 화면 구성
  - 지도 배경 위 티켓 카드: 출발 정류장, 도착 정류장, 정류장 수와 거리, 탑승 시점('지금'/날짜), 태그와 할 일. 하단 '버스에 탑승하기 →' 버튼.
  - 버스 번호와 여행 시간은 화면 비표시, 낭독기용으로만 제공.
  - 이 단계에서는 진행 여정·완료 여정을 만들지 않는다.
- [Must] FR-3: '버스에 탑승하기'를 누르면 승차 태그 화면으로 이동한다.
- [Must] FR-4: 승차 태그 화면 구성
  - 단말기(LCD 'Focus Mate', 현재 시각 HH:mm, '승차 준비'), 태그 영역, 위쪽 화살표, 아래쪽 점선 테두리 안의 사용자 카드(꾸민 외형)만 보인다.
  - 제목, 정류장, 단계, 하단 안내, '카드를 여기에', 상표, '눌러서 태그하기'는 화면 비표시, 낭독기용으로 유지.
  - 왼쪽 위 뒤로가기 유지, 인식 전에는 승차권 화면으로 돌아간다.
- [Must] FR-5: 끌어서 태그 인식
  - 카드는 위아래로만 끈다. 좌우 최대 26, 위로 태그 영역 위쪽까지, 아래로 20까지.
  - 카드가 태그 영역과 30% 이상 겹치는 순간 손을 떼기 전에 인식하고 진동. 카드는 그 자리에 남는다.
  - 인식되면 LCD에 카드 이름('집중동행카드')과 체크. 카드 번호 비표시.
  - 30% 미만에서 손을 떼면 인식 없이 원위치.
- [Must] FR-6: 끌지 않고 터치만 하면 카드가 살짝 튀고 '카드를 위로 밀어 단말기에 대주세요' 안내. 인식 없음.
- [Must] FR-7: VoiceOver 활성화나 키보드(Enter/Space 상당)로 카드를 활성화하면 태그. 카드는 태그 영역 아래쪽 가장자리에 걸치도록 올라가고 이후 FR-8~9와 동일. 인식 낭독 문구는 '집중동행카드 인식됨, 승차했습니다'.
- [Must] FR-8: 인식 시 진행 여정 1회 저장·교체
  - 인식 접촉 성공 시 접촉 이동 300ms 뒤 진행 여정을 1회 저장. 1400ms 유지·450ms 전환 완료를 기다리지 않는다.
  - 저장 내용: 여정의 위치·방향·시간, 진도(0, 출발 확인 전), 할 일, 태그, 소리 스냅샷.
  - 기존 진행 여정이 있으면 교체. 저장된 진행 여정은 최대 1건.
  - 인식 뒤 추가 접촉·끌기는 무시하며 저장이 늘지 않는다.
- [Must] FR-9: 인식 상태 1400ms 유지, 450ms 전환 뒤 여행 화면(자리표시: 출발 안내 + 빈 화면)으로 이동. 인식 후 승차 태그 화면으로 되돌아오는 뒤로가기 없음.
- [Must] FR-10: 인식 후 이탈(뒤로가기 등)·앱 숨김은 대기 중인 여행 화면 전환만 취소, 저장 유지. 잘못 놓음·중복 접촉·인식 전 이탈·숨김은 예약 전환을 남기지 않는다.
- [Must] FR-11: 출발 안내
  - 여행 화면 진입 직후 같은 자리에서 '문을 닫습니다' → '자리에 앉아주세요' → '버스 출발합니다'가 약 1.7초씩 차례로.
  - 마지막 문장이 남고 '시작' 버튼. 노선·버스·정류장 정보 비표시.
  - 안내 중 일시정지 불가. 포커스는 '시작'.
  - 동작 줄이기면 세 문장을 한꺼번에.
- [Must] FR-12: '시작' 전 진행·남은 시간 정지. '시작'을 누르면 진행 여정에 '출발 확인됨' 기록 후 여행 자리표시 화면. 실제 분 진행은 W05.
- [Must] FR-13: 인식 시점 저장 실패면 여행 화면 전환 없음, 기존 저장(기존 진행 여정 포함) 불변, 실패 안내 후 같은 화면에서 다시 태그 가능.
- [Must] FR-14: 메인의 진행 중인 여정 안내와 자동 폐기
  - 진행 여정이 저장되어 있으면 메인에 "진행 중인 여정이 있다" 안내(재실행 직후, 같은 세션 이탈 후 복귀 모두).
  - 이 상태에서 '여행 시작하기'를 누르면 진행 여정을 완료 기록 없이 자동 폐기하고 시간 선택으로 시작. 별도 확인 없음.
  - 재실행 시 여행 화면 자동 복귀·이어가기 없음(W07).
- [Should] FR-15: FR-14 및 FR-1·FR-8의 교체 동작은 W07 이어가기·포기 도입 전 임시 동작이다.
- [Should] FR-16: 동작 줄이기·접근성
  - 동작 줄이기면 접촉 이동·페이드·진동 생략. 인식 유지(1400ms)와 상태 안내는 유지. 진입 연출(단말기, 카드, 두 번 올림 안내)과 점선 테두리 깜빡임 생략.
  - 모든 신규 화면과 메인 안내는 VoiceOver, 가장 큰 글자 크기에서 버튼 도달성 보장(preferences FR-3).

#### 비즈니스 규칙
- [Must] BR-1: 준비 미완성(여정, 태그, 공백 아닌 할 일 중 하나라도 없음)이면 승차권 진입 불가. 승차권 단계에서는 진행·완료 여정을 만들지 않는다.
- [Must] BR-2: 진행 여정은 접촉 성공 시 정확히 1회 저장. 중복 접촉·재진입·전환 취소로 저장이 늘지 않는다.
- [Must] BR-3: 저장된 진행 여정은 이탈·숨김으로 지워지지 않는다. 완료 기록은 하차 성공(W09)에서만.
- [Must] BR-4: 카드 번호는 어떤 신규 화면에도 표시하지 않는다.
- [Must] BR-5: 출발 확인 전에는 진행·남은 시간이 시작되지 않는다.
- [Must] BR-6: 인식은 끌어서 겹치거나 낭독기·키보드 활성화로만. 단순 터치로는 일어나지 않는다.
- [Should] BR-7: 겹침 비율 = 겹친 면적 ÷ 태그 영역 면적(238×160). 가정이며 시안 카드 크기와 대조해 확인.
- [Must] BR-8: 저장된 진행 여정은 최대 1건. 새 인식은 기존 진행 여정을 교체.
- [Must] BR-9: 자동 폐기된 진행 여정은 완료 기록으로 남기지 않는다.

#### 품질 기대
- [Should] QE-1: 설명 없이 "카드를 위로 밀어 대는" 행동을 이해한다(위쪽 화살표·올림 안내).
- [Should] QE-2: 오조작(실수 터치, 짧은 끌기)이 여정 시작으로 이어지지 않는다.
- [Should] QE-3: 재실행 사용자가 진행 중인 여정이 있었음을 알아챈다.

### 사용자 시나리오
- 정상: 준비 완성 → '승차권 보기' → 승차권 → '버스에 탑승하기' → 카드를 위로 끌어 30% 이상 겹침 → 진동·LCD 체크 → 1400ms·450ms → 출발 안내 세 문장 → '시작' → 출발 확인됨.
- 예외: 짧게 끌고 놓음 → 원위치 / 터치만 → 튐+안내 / 인식 직후 뒤로가기·숨김 → 전환 취소, 저장 유지 / 인식 후 재접촉 → 무시.
- 엣지: 저장 실패 → 전환 없음·불변·재시도 / 재실행 시 진행 여정 → 메인 안내, '여행 시작하기'로 폐기 후 시간 선택 / 세션 내 이탈 후 메인 → 같은 안내 / 진행 여정 남은 채 새 인식 → 교체 1건 / 동작 줄이기 / 출발 안내 중 숨김 후 복귀 → 안내 처음부터(가정), 진행 여정 유지 / 가장 큰 글자 → '버스에 탑승하기', '시작', '여행 시작하기' 도달.

### 영향 범위
- 메인: 진행 여정 안내 추가, '여행 시작하기'가 진행 여정 폐기 동작을 가짐.
- 준비: '승차권 보기'가 이동하도록 바뀜.
- 저장소: 진행 여정이 처음 실제 값을 가짐. 기존 active null 데이터는 영향 없음. 버전 처리 필요 여부 설계에서 확인.
- 카드: 승차 태그 화면에서 꾸민 외형 사용. 기록: 완료 기록을 만들지 않으며 폐기도 기록 없음.
- 테스트 시드·런치 인자에 승차권, 태그, 출발 안내, 진행 여정 보유 상태 진입 추가.

### 수용 기준

AC-1: 준비 완성 시 승차권으로 이동 → [FR-1]
  Given: 여정, 태그, 공백이 아닌 할 일이 모두 있는 준비 화면
  When: '승차권 보기'를 누른다
  Then: 승차권 화면이 보이고, 진행 여정과 완료 기록은 모두 0건이다

AC-2: 준비 미완성 시 승차권 진입 차단 → [FR-1, BR-1]
  Given: 여정, 태그, 공백이 아닌 할 일 중 하나라도 없는 준비 화면(소리는 기본값 버스로 항상 있음)
  When: '승차권 보기'를 누른다
  Then: '승차권 보기'는 비활성이고 이동은 일어나지 않으며, 승차권 화면은 어떤 경로로도 열리지 않는다

AC-3: 승차권 표시 항목 → [FR-2]
  Given: 승차권 화면
  When: 화면이 열린다
  Then: 출발 정류장, 도착 정류장, 정류장 수와 거리, 탑승 '지금'(또는 날짜), 태그와 할 일, '버스에 탑승하기' 버튼이 보이고, 버스 번호와 여행 시간은 화면에 보이지 않으나 접근성 라벨에는 존재한다

AC-4: 탑승 버튼으로 승차 태그 화면 이동 → [FR-3]
  Given: 승차권 화면
  When: '버스에 탑승하기'를 누른다
