## Background

**W01 [P2] 카드 발급·접촉 카드 (card FR-3)** — iOS 앱이 "카드 발급 여부(Bool)"만 저장하고 발급 화면이 문구뿐이라, 처음 쓰는 사용자가 카드를 받을 방법이 없었습니다. 이 PR은 집중동행카드를 실제로 1회 발급하고, 이후 승차(W04)·꾸미기(W10)·마이페이지(W11)가 함께 쓰는 공통 카드 뷰와 이름·번호 단일 출처를 만듭니다.

### 사용자에게 달라지는 점
- 첫 실행: "집중동행카드 발급받기" → 카드가 슬롯에서 나오는 연출 + 그라데이션 진동(약→강, 끝에 뚝) → "출발지 선택하기"로 진행. 완료 화면은 버튼을 누를 때까지 유지됩니다.
- 저장 실패 시 진행을 막고 "다시 발급받기"로 재시도합니다(저장 없이 계속 쓰지 않음 — 카드 번호 불일치 방지).
- 기존 사용자(버전 1·W00 파일)는 발급 화면 없이 앱 시작 때 카드 정보만 조용히 보충됩니다. 보충 실패는 화면에 알리지 않고 다음 실행에서 재시도합니다.
- 카드 번호는 어떤 화면에도 표시하지 않습니다(승차 LCD도 이름과 체크만 — W04에서 확정 사항으로 이관).
- 시스템 동작 줄이기는 연출에만 적용합니다(진동은 그대로). 앱 안 동작 줄이기·진동 설정은 만들지 않습니다.

### 요구사항
- FR-3-1~9 (발급 화면·1회 발급·저장 실패·기존 사용자 보충·공통 카드 뷰·이름/번호 출처·발급 햅틱·접근성·연출 시간), BR-1~8, QE-1~3 — 수용 기준 AC-1~21 전부 자동 검증, AC-19M(VoiceOver 장식 비노출·완료 후 포커스)은 수동 확인 항목.

### 설계 요점
- 저장: `app-state.json` v2 `cards.items[]`에 `CardSnapshot{id: "FM-" + 8자리, issuedAt}`. 정합성(BR-5)은 `AppSnapshot.validate` 한 곳에서 판정 — 잘못된 데이터는 원본 보존 + 저장 상태 오류 화면.
- 화면 분기는 `AppModel.presentedRoute`만 사용(발급 완료 화면 유지는 메모리 플래그 — 재실행 시 출발지 선택으로).
- 보충은 읽기(`loadIfNeeded`)와 분리된 `start()` 단계 — "읽기는 쓰지 않는다" 보장 유지.
- 발급 상태 머신은 첫 suspension 전 MainActor 가드로 연타를 직렬화. 진동은 CoreHaptics 패턴(순수 값 + 변환)으로 테스트 가능.
