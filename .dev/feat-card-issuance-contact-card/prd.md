# PRD: 카드 발급과 공통 카드 뷰 (FR-3 (status.md 미반영), 작업 W01)

규모: 대형. 신규 화면·저장 데이터 추가, W04·W10·W11이 결과물을 가져다 쓴다.

## 사용자 확정 결정 (Q&A)

- Q: 승차 LCD에 카드 번호? → A: 카드 이름과 체크만, 번호 비표시 (FLOWS 2026-10-13 2차)
- Q: 발급 저장 실패 시? → A: 진행 차단, 안내 후 재시도
- Q: 동작 줄이기에서 진동? → A: 앱 안 동작 줄이기·진동 설정은 만들지 않음. 발급 연출만 시스템 `\.accessibilityReduceMotion`을 따름
- Q: 진동 시점·모양? (설계 단계) → A: 카드가 슬롯에서 나오는 연출 동안 "점점 세게 → 끝에 뚝" 그라데이션 진동 패턴 1회. 동작 줄이기로 카드가 바로 나타나도 같은 패턴 재생
- Q: 기존 사용자 보충 저장 실패를 화면에 알릴까? (설계 단계) → A: 알리지 않음
- Q: 카드 위 글자에 Dynamic Type? (설계 단계) → A: 카드 크기에 비례(화면 문구·버튼만 Dynamic Type)

- Q: 발급 중 파일 외부 손상으로 재시도가 계속 실패하는 경우? (리뷰 단계) → A: W13으로 이관
- Q: 후속 작업이 저장 파일에 항목을 추가할 때? (리뷰 단계) → A: 항목 추가 시 버전을 올리고 변환 코드를 둔다
- Q: AC-19 자동 검증 불가 2항목? (구현 단계) → A: 수동 확인 항목(AC-19M)으로 분리

## 배경

- 웹 프로토타입은 카드 1회 발급을 구현했다. 카드 ID는 `FM-` 뒤에 숫자 8자리를 붙인다. 카드 ID와 발급 시각을 저장하고, 지원 기기에서만 진동하며, 기존 사용자에게 카드를 자동으로 발급한다 (animation-preview.html:1009-1016).
- 현재 iOS는 발급 여부(Bool)만 저장한다. 카드 이름·ID·발급 시각은 저장하지 않는다.
- `screen.cardEntry` 화면에는 문구만 있다. `cards.items`는 W00이 비워 두었고, 항목이 하나라도 있으면 파일을 읽지 않는다.
- 여정(`journey.active`)과 기록(`records.items`)의 항목 계약도 비어 있다. 그래서 여정·기록 보존은 "빈 값 유지"와 "항목이 든 파일은 읽기 거부 후 보존"으로만 검증한다.
- 승하차 화면은 W04 담당이다. W01은 공유 카드 뷰와 카드 이름·번호를 읽는 단일 출처를 제공한다.

## 목표

- 처음 쓰는 사용자는 버튼 한 번으로 카드를 받고, 바로 출발지 선택으로 넘어간다.
- 사용자당 카드는 1장이다. 재실행해도 같은 ID가 유지된다.
- Phase 1·W00 사용자는 데이터 손실 없이 카드 정보만 보충받고, 발급 화면을 거치지 않는다.
- W04·W10·W11은 같은 카드 뷰와 같은 출처를 쓴다.

성공 지표: 카드 ID 불일치 0건, 저장 실패를 성공으로 안내 0건, 기존 사용자에게 발급 화면 재노출 0건.

## 범위 / 비범위

- 범위: 발급 화면(발급 전·발급 중·완료·저장 실패), 카드 저장(ID·발급 시각), 기존 사용자 보충, 기본 외형 공통 카드 뷰, 이름·번호 단일 출처, 발급 햅틱, VoiceOver·Dynamic Type·시스템 동작 줄이기
- 비범위: 승하차 화면·LCD·접촉, 꾸미기, 마이페이지, 저장 오류 복구 화면, 출발지 선택 화면 내용, 앱 안 동작 줄이기·진동 설정

## 요구사항 (모두 FR-3 (status.md 미반영)의 세부)

### 기능
- [Must] FR-3-1 발급 화면: 발급 전 → 발급 중 → 완료. 완료 화면에 카드와 "출발지 선택하기" 버튼을 둔다.
- [Must] FR-3-2 1회 발급·저장: ID와 발급 시각을 저장한다. 사용자당 1장이다. 완료 화면은 버튼을 누르기 전에는 다음 화면으로 자동 이동하지 않는다.
- [Must] FR-3-3 저장 실패: 미발급 상태로 남고, 실패를 안내하고, 다시 시도할 수 있다. 실패 상태에서는 다음 화면으로 진행할 수 없다.
- [Must] FR-3-4 기존 사용자 보존·보충: 버전 1 파일과, 버전 2이면서 `cards.items`가 빈 파일이 대상이다. 앱 시작 때 카드 정보를 1회 만들어 저장한다. 다른 값은 바꾸지 않는다.
- [Must] FR-3-5 공통 카드 뷰: 기본 외형이다. 카드 번호는 표시하지 않는다.
- [Must] FR-3-6 이름·번호 단일 출처: 이름은 "집중동행카드"(고정, 저장 안 함), 번호 표기는 `FM · 1234 5678`이다. 카드가 없으면 "없음"을 돌려준다. 현재 어떤 화면도 번호를 노출하지 않는다.
- [Must] FR-3-7 발급 햅틱: 지원 기기에서 저장 성공 후 연출 시작과 함께 "발급 진동 패턴"을 정확히 1회 재생한다. 패턴은 연출 상한(0.9초) 길이 동안 세기가 약→강으로 커지는 연속 진동과 끝의 짧은 탭 1개다. 동작 줄이기와 무관하게 같은 패턴을 재생한다. 미지원 기기에서는 조용히 생략한다. 앱 안에 진동 설정은 없다.
- [Must] FR-3-8 접근성: VoiceOver 라벨과 Dynamic Type을 적용한다. 발급 연출은 시스템 동작 줄이기를 따른다.
- [Should] FR-3-9 발급 연출 시간: 발급 중 상태는 일반 설정에서 0초 초과 0.9초 이하, 동작 줄이기에서 0초다.
- [Could] FR-3-10 재실행 시 완료 화면 복원: 채택하지 않는다 (A3).

### 비즈니스 규칙
- [Must] BR-1 ID 형식: `FM-` + 숫자 8자리, 앞자리 0 허용.
- [Must] BR-2 ID 불변: 재실행·보충 재호출·연타로 ID가 바뀌지 않는다.
- [Must] BR-3 1회 발급: 발급 후에는 버튼이 없다. 발급 중에는 버튼이 잠긴다.
- [Must] BR-4 번호 비노출: 카드 위·승하차 LCD·마이페이지·VoiceOver 라벨 어디에도 번호를 노출하지 않는다.
- [Must] BR-5 정합성: 다음은 잘못된 데이터다. 카드가 있는데 미발급, 카드가 2장 이상, ID 형식 오류. 잘못된 데이터는 원본을 보존하고 저장 상태 오류 화면을 보여준다.
- [Must] BR-6 실패 시 무변경: 파일이 바이트 단위로 이전과 같고, 화면은 발급 전 상태다. 저장 없이 계속 쓰는 것은 허용하지 않는다.
- [Must] BR-7 보충은 조용히: 발급 화면·연출·햅틱이 없고, 이동하는 화면도 바뀌지 않는다.
- [Should] BR-8 보충 저장 실패: 앱은 계속 쓸 수 있고(이동 불변), 다음 실행에서 다시 시도한다.

### 품질 기대
- [Should] QE-1 기존 사용자에게 추가 화면이 없다.
- [Should] QE-2 XXXL 글자 크기에서도 버튼을 누를 수 있다.
- [Should] QE-3 W04·W10·W11이 카드 뷰와 출처를 수정 없이 재사용한다.

### 테스트 지원 요구
테스트에서 다음을 주입할 수 있어야 한다: 저장 성공/실패, 발급 중 대기 시간, 시스템 동작 줄이기, 햅틱 지원 여부와 호출 횟수. 기존 시드(`none`, `cardOnly`, `ready`, `corrupt`, `unsupported`)에 "발급됨·카드 없음" 시드(`cardIssued` true, `cards.items` 빈 값, 정류장 있음)를 추가한다.

## 사용자 시나리오

- 정상: 첫 실행 → "집중동행카드 발급받기" → 발급 중(버튼 잠김) → 카드 표시·햅틱 1회 → "카드가 발급됐어요" + "출발지 선택하기" → 첫 출발지 화면
- 저장 실패: 카드·햅틱 없음. 실패 안내와 "다시 발급받기"를 보여주고 진행을 막는다.
- 연타: 버튼이 잠겨 카드는 1장만 생긴다.
- 발급 중 종료: 저장은 이미 끝났으므로, 재실행하면 발급된 사용자다.
- 기존 사용자: 앱 시작 때 보충하고 평소 화면으로 간다.
- 햅틱 미지원: 진동만 없고 흐름은 같다.
- 손상 데이터: 오류 화면을 보여주고 파일을 보존한다.
- 다운그레이드: 지원하지 않는다 (A2).

## 영향 범위

- 첫 실행 화면이 실제 발급 화면으로 바뀐다.
- 저장 파일은 버전 2를 유지한다. 카드 항목을 처음 채우고, 읽기 검증(BR-5)을 추가한다.
- 앱 시작 때 보충 저장 단계가 생긴다. 읽기와는 분리되어 있어 "읽기는 쓰지 않는다"는 원칙이 유지된다.
- 발급 상태가 되면 자동으로 다음 화면으로 가던 구조를 바꿔 완료 화면을 유지한다 (FR-3-2).
- 하위 호환: 버전 1 파일과 버전 2(카드 없음) 파일은 그대로 열린다.

## 수용 기준 (Given-When-Then)

UI = XCUITest, 단위 = XCTest. 식별자와 문구는 테스트가 그대로 확인한다.

AC-1: 발급 전 화면 구성 → [FR-3-1] (UI)
  Given: 저장 파일이 없는 첫 실행이다 (시드 `none`).
  When: 앱을 연다.
  Then: `screen.cardEntry`가 존재한다. `card.title` 값은 "집중동행카드를 발급받아볼까요?"다. `card.issueButton` 라벨은 "집중동행카드 발급받기"이고 활성 상태다. `card.face`, `card.continueButton`, `card.issueError`는 존재하지 않는다. `test.persistedBytes`는 "absent"다.

AC-2: 발급 성공 시 저장값 → [FR-3-2, BR-1] (UI)
  Given: AC-1 상태다.
  When: `card.issueButton`을 한 번 누르고 `card.continueButton`이 나타날 때까지 기다린다.
  Then: `test.snapshot`의 `cardIssued`는 true다. `cards.items`는 정확히 1개이고 `id`는 `^FM-[0-9]{8}$`와 일치하며 `issuedAt`은 ISO 8601이다. `journey.active`는 null, `records.items`는 0개다. `test.persistedBytes`는 "absent"가 아니다.

AC-3: 발급 완료 화면 유지 → [FR-3-1, FR-3-2] (UI)
  Given: AC-2 직후이고 아무것도 누르지 않았다.
  When: 5초간 대기한다.
  Then: `screen.cardEntry`가 존재한다. `card.title`은 "카드가 발급됐어요. 이제, 어디에서 출발할까요?"다. `card.face`가 존재한다. `card.continueButton` 라벨은 "출발지 선택하기"다. `card.issueButton`과 `screen.initialStationEntry`는 존재하지 않는다.

AC-4: 계속 버튼 이동 → [FR-3-1] (UI)
  Given: AC-3 상태이고 `id`를 X로 기억했다.
  When: `card.continueButton`을 누른다.
  Then: `screen.initialStationEntry`가 존재하고 `screen.cardEntry`는 존재하지 않는다. `cards.items`는 1개이고 `id`는 X다.

AC-5: 발급 중 연타·잠금 → [FR-3-1, BR-3] (UI)
  Given: AC-1 상태다. 발급 중 상태가 테스트가 해제할 때까지 유지되도록 테스트 전용 해제 장치를 켰고(0.9초 상한은 AC-18이 검증) 시스템 동작 줄이기는 꺼져 있다.
  When: `card.issueButton`을 연달아 3번 누른 뒤 발급 중 상태를 해제한다.
  Then: 발급 중 `card.issueButton` 라벨은 "카드를 발급하고 있어요"이고 비활성이다. 완료 후 `cards.items`는 정확히 1개이고 `card.issueButton`은 존재하지 않는다.

AC-6: 재실행 후 같은 ID → [FR-3-2, BR-2] (UI)
  Given: 출발지 선택 전에 발급을 마쳤고 `id`를 X로 기억했다.
  When: 앱을 종료하고 같은 저장소로 다시 실행한다.
  Then: `screen.initialStationEntry`가 존재한다. `screen.cardEntry`와 `card.issueButton`은 존재하지 않는다. `cards.items`는 1개이고 `id`는 X다.

AC-7: 발급 저장 실패 → [FR-3-3, BR-6] (UI)
  Given: 저장 파일이 없고 모든 저장이 실패하도록 설정했다.
  When: `card.issueButton`을 누른다.
  Then: `card.issueError` 값은 "카드를 발급하지 못했어요. 다시 시도해 주세요."다. `card.face`, `card.continueButton`, `screen.initialStationEntry`는 존재하지 않는다. `card.issueButton` 라벨은 "다시 발급받기"이고 활성 상태다. `test.persistedBytes`는 "absent"다. `cardIssued`는 false이고 `cards.items`는 0개다. `storage.saveFailure`는 존재하지 않는다. 햅틱 호출은 0회다.

AC-8: 실패 후 재시도 성공 → [FR-3-3] (단위)
  Given: 첫 저장은 실패하고 두 번째 저장은 성공하는 저장소다.
  When: 발급을 두 번 요청한다.
  Then: 첫 요청은 false를 돌려주고 `cards.items`는 0개다. 두 번째 요청은 true를 돌려주고 1개다. 파일에는 두 번째 요청의 ID 하나만 있다.

AC-9: 기존 사용자 보충(버전 1) → [FR-3-4, BR-7, BR-2] (단위)
  Given: 버전 1 파일 `{"version":1,"state":{"cardIssued":true,"initialStation":{성수},"currentStation":{성수}}}`가 있다.
  When: 앱 시작 단계(불러오기 후 보충)를 같은 파일로 연달아 두 번 호출한다.
  Then: 첫 호출 후 `version`은 2다. `cards.items`는 1개이고 `id`는 `^FM-[0-9]{8}$`다. 정류장은 보충 전과 같다. `journey.active`는 null, `records.items`는 0개다. 이동 경로는 `.main`이다. 햅틱 호출은 0회다. 두 번째 호출 후 `id`와 파일 바이트는 첫 호출 후와 같다.

AC-10: 기존 사용자 보충(버전 2, 카드 없음) → [FR-3-4, QE-1] (UI)
  Given: `cardIssued` true, `cards.items` 빈 값, `journey.active` null, `records.items` 빈 값, 정류장 서울숲인 시드다.
  When: 앱을 연다. 종료한 뒤 같은 저장소로 다시 연다.
  Then: 두 실행 모두 `screen.main`이 존재하고 `screen.cardEntry`는 한 번도 존재하지 않는다. `cards.items`는 1개이고 `id`는 두 실행에서 같다. `main.currentStation`은 "서울숲"이다. 햅틱 호출은 0회다.

## 디자인 스펙 (AC 아님)

- 기본 카드: 서울 점묘 배경, IC 칩, 비접촉 표시, "Focus Mate", "집중동행카드". 카드 번호는 없다. 꾸미기는 W10에서 한다.
- 비율과 크기는 W01 설계에서 확정한다. 웹 기준은 태그 영역 238×160, 단말기 폭 274다. 카드는 놓이는 영역에 맞춰 같은 비율로 크기가 바뀐다.
- 문구:
  - 발급 전: 제목 "집중동행카드를 발급받아볼까요?", 설명 "독서도, 작업도, 잠깐의 쉼도. 한 장의 카드로 나만의 여정을 시작해요.", 힌트 "한 번 발급받아, 모든 몰입 여정에 사용해요."
  - 완료: 제목 "카드가 발급됐어요. 이제, 어디에서 출발할까요?", 설명 "오늘부터, 나만의 시간으로. 이 카드가 매 여정에 함께해요.", 힌트 "발급받은 카드는 승차할 때와 하차할 때 사용해요."
- 발급 연출은 슬롯 모션이다. 시스템 동작 줄이기에서는 모션 없이 카드가 즉시 나타난다.
- 어두운 화면이 기준이다. 글자 크기는 시스템 설정을 따른다.

## 이관 항목

- W04: 승차 화면에 W01 카드 뷰를 배치한다. **승차 LCD는 카드 이름과 체크만 표시하고 번호는 표시하지 않는다(확정).** 하차 LCD도 카드 이름과 체크다. 접촉 인식·접촉 진동·접촉 저장도 W04가 맡는다. 접촉 진동도 앱 안 설정 없이 동작하는지 W04에서 다시 확인한다. 카드가 없을 때 승차를 막는 규칙도 W04가 정한다.
- W10: 색·사진 꾸미기(최대 6장)를 맡는다. 꾸미면 브랜드·이름·문구가 사라지고 IC 칩과 비접촉 표시만 남는다. 카드 뷰가 외형 정보를 받는 방식도 W10이 정한다.
- W11: 같은 카드 뷰를 읽기 전용으로 쓴다. 번호는 표시하지 않는다.
- W04·W11 공통: `PassIdentity.numberText`는 공개 값이지만 어떤 화면에도 쓰지 않는다(BR-4). 새 화면 AC에 AC-16과 같은 "test.* 제외 전체 요소 순회 — 번호 미포함" 검사를 넣는다(리뷰 단계 보안 감사 이관).
- W13: 손상 데이터의 재시도·정리 화면을 맡는다. 발급 화면에 있는 동안 파일이 외부에서 손상되어(writeBlocked) "다시 발급받기"가 계속 실패하는 경우도 W13에서 다룬다(원본은 W01에서 보존됨).
- W04·W08: 여정·기록 항목이 실제로 보존되는지 검증한다.

## 가정

- A1: 카드 이름은 고정값이며 저장하지 않는다.
- A2: 파일 버전은 2를 유지한다. 다운그레이드는 지원하지 않는다.
- A3: 완료 화면에서 앱을 종료했다가 다시 열면 출발지 선택 화면으로 간다. 웹과 다르다.
- A4: 보충 저장이 실패하면 다음 실행에서 다시 시도한다. 저장된 적 없는 ID는 바뀔 수 있다.
- A5: 웹의 `NS-` ID는 지원하지 않는다.
- A6: 웹은 저장 실패 후에도 계속 쓸 수 있지만, iOS는 진행을 막는다 (결정 2).
- A7: 웹은 동작 줄이기에서 햅틱을 생략하고 발급 시 2회 진동한다. iOS는 동작 줄이기와 무관하게 그라데이션 패턴(약→강 + 끝 탭)을 1회 재생하고, 동작 줄이기는 연출에만 적용한다 (결정 3·설계 단계 결정).
- A9: 저장 파일에 새 항목을 추가하는 후속 작업(W10 등)은 버전을 3으로 올리고 변환 코드를 둔다. 버전 2 디코더는 모르는 키를 버리므로 같은 버전에 키를 추가하지 않는다.
- A10: 카드 ID는 기기 로컬에서만 의미가 있으며 기기 간 유일성을 보장하지 않는다(10^8 공간, CSPRNG).
- A11: `issuedAt`은 앱이 직접 쓴 `yyyy-MM-ddTHH:mm:ssZ` 형식만 가정한다. 소수초·`+09:00` 오프셋 입력의 처리(허용·정규화·거부)와 미래·극단 시각 검증은 W13에서 정한다.
- A8: 여정·기록 항목 보존은 W00이 계약을 비워 두어 이번에 검증하지 않는다 (AC-14 f로 대체).
