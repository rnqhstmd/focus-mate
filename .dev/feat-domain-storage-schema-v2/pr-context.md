## Background

W00(작업 계획 묶음 1): 앱 상태 저장 파일 `app-state.json`을 버전 1 → 2로 확장한다.

- 현재 v1은 카드 발급 여부·최초/현재 정류장만 담는다. 카드(W01·W02)·진행 여정(W04·W05·W07)·완료 기록(W08)이 같은 파일 구조를 동시에 바꾸면 충돌하므로, 구조 변경을 W00에서 한 번만 하고 후속 작업은 자기 영역 내용만 채운다.
- 기존 v1 데이터는 100% 보존하고 화면 변화는 없다. 미래 버전·손상 파일은 어떤 경로로도 덮어쓰지 않는다(복구 UI는 W13).

### 요구사항 (모두 Must)
- FR-1 v2 형식: 기존 3키 유지 + `cards`·`journey`·`records` 영역
- FR-2 초기 내용: 카드 빈 목록, 진행 여정 없음, 기록 빈 목록
- FR-3 v1 파일은 읽을 때 메모리에서만 v2로 변환(읽기만으로 파일 불변)
- FR-4 모든 저장은 v2, 세 영역·기존 항목 함께 유지 — 전체 생성자 private + `updating…` 갱신 함수로 다른 영역을 실수로 비우는 경로를 컴파일 단계에서 차단
- FR-5 정수 버전 0 이하·3 이상은 미지원, 비정수 버전은 손상(둘 다 원본 보존·쓰기 차단)
- FR-6 변환·검증 실패 시 원본 보존·저장 차단(기존 오류 분류 유지)
- FR-7 시작 화면 분기 불변
- BR-1~5: 영역 안 항목 추가는 버전 변경 사유 아님 / 원본 덮어쓰기 금지 / atomic write / v1 백업 없음 / 영역 통째 누락은 손상

### 설계 요지
- 신규 `SnapshotCodec`(헤더 → 버전 → 구조 → 내용 순 판정, `migrateV1`, sortedKeys 인코딩), `LocalSnapshotStore`는 코덱에 위임(공개 API 불변)
- 영역별 파일 분리(`CardSection`·`JourneySection`·`RecordSection`) — 원소 타입은 값 없는 enum이라 W00 빌드는 원소가 든 파일을 손상으로 보존
- 출력 바이트를 golden 테스트(G1 빈 상태, G2 v1 변환)로 고정

### 검증
- verify 게이트: iOS Unit 63 + UI 11, 0 failures / 웹 test·build exit 0 / 경고 0(기준선 3)
- 리뷰 2회: SPEC PASS 5/5, 최종 Critical 0·Important 0 / 인수 검증 ACCEPT
