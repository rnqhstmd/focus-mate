## PRD: 도메인 저장 구조 확장 (버전 1 → 2) [W00]

규모: 중형. 기존 저장 정책을 바꾸고 이후 여러 작업이 이 구조에 기대기 때문이다.

### 배경
- 현재 `app-state.json`은 버전 1이다. 담는 것은 카드 발급 여부, 최초 정류장, 현재 정류장뿐이다. 정류장은 ID, 이름, 방향을 저장한다. (LocalSnapshotStore, AppSnapshot에서 확인)
- 손상, 미지원 버전, 읽기 실패 시에는 초기 상태로 덮어쓰지 않고 원본을 보존한다. 이때 새 저장도 막는다. 저장에 실패하면 이전 상태를 유지한다.
- 후속 작업이 각자 다른 정보를 저장해야 한다. 카드는 W01·W02, 진행 여정은 W04·W05·W07, 완료·메모 기록은 W08이다. 이들이 같은 저장 파일 구조를 동시에 바꾸면 충돌한다. 그래서 파일 구조 변경은 W00에서 한 번만 한다. (.dev/plan.md 근거)
- 저장 오류 복구(재시도, 원본 정리)는 Phase 5의 W13 범위다. 그 전까지 손상이나 미지원 파일은 원본을 보존하고 진행을 막는 현재 동작을 유지한다. (preferences FR-4)
- 현재 제품 상태: 이미 앱을 쓰는 사용자의 파일은 버전 1이다. 이 사용자는 업그레이드 후에도 발급 여부와 정류장 정보를 잃지 않아야 한다.

### 목표
- 카드, 여정, 기록 세 영역이 저장 파일 안에 각자 자리를 갖는다. 후속 작업은 자기 영역의 내용만 채우고 파일 버전을 다시 올리지 않는다.
- 기존 버전 1 사용자의 데이터가 100% 보존되고, 사용자가 업그레이드 때문에 겪는 화면 변화가 없다.
- 알 수 없는 파일(미래 버전, 손상)을 어떤 경우에도 덮어쓰지 않는다.

### 요구사항
#### 기능 요구사항
- [Must] FR-1: 저장 파일은 버전 2 형식을 갖는다. 기존 항목(발급 여부, 최초 정류장, 현재 정류장) 위치와 의미는 그대로 두고, 카드·여정·기록 영역 세 개를 추가한다.
- [Must] FR-2: 새 영역의 초기 내용은 다음과 같다.
  - 카드 영역: 카드 없음(빈 목록).
  - 여정 영역: 진행 중 여정 없음.
  - 기록 영역: 완료 기록 없음(빈 목록).
  - 상세 항목은 후속 작업이 정한다.
- [Must] FR-3: 버전 1 파일을 읽으면 버전 2 상태로 변환해 사용한다. 기존 항목은 그대로 유지하고 새 영역은 초기 내용으로 채운다. 읽기만 한 경우에는 파일을 바꾸지 않는다.
- [Must] FR-4: 이후 모든 저장은 버전 2로 기록한다. 저장 시 세 영역의 내용과 기존 항목이 함께 유지된다.
- [Must] FR-5: 지원하지 않는 버전은 읽지 않는다. 대상은 3 이상, 0 이하의 정수 버전이다(미지원 버전 오류). 숫자가 아닌 값(문자열·null·실수 등)도 읽지 않되, 미지원 버전 오류에 정수 값을 담을 수 없으므로 손상으로 분류한다(원본 보존·쓰기 차단은 동일). 파일이 없는 경우는 지원 대상이 아니라 첫 실행으로 보고, 초기 상태로 시작한다.
- [Must] FR-6: 변환이나 검증에 실패하면 원본을 보존하고, 그 상태에서 새 저장을 막는다. 대상은 손상, 읽기 실패, 버전 1의 내용 불일치, 버전 2의 영역 누락 또는 형식 오류다. 오류 종류는 현재 구분(손상, 미지원 버전, 내용 불일치, 읽기 실패)을 그대로 쓴다.
- [Must] FR-7: 시작 화면 분기(카드 발급 → 최초 정류장 → 메인)는 기존과 동일하다. 새 영역의 내용은 분기에 영향을 주지 않는다.

#### 비즈니스 규칙
- [Must] BR-1: 영역 안에 항목을 추가하는 것은 버전 변경 사유가 아니다. 버전 2 구조는 후속 작업(W01~W13)이 파일 버전을 올리지 않고 확장할 수 있어야 한다.
- [Must] BR-2: 알 수 없거나 손상된 원본은 어떤 경로로도 초기 상태로 덮어쓰지 않는다. 앱 시작이나 변환 과정도 마찬가지다.
- [Must] BR-3: 저장 실패 시 직전 메모리 상태와 기존 파일을 유지한다. 파일 쓰기는 중간 상태가 남지 않는 방식(atomic write)을 유지한다.
- [Must] BR-4: 이번 작업에서는 버전 1 백업 파일을 만들지 않는다. 버전 2는 버전 1 내용을 모두 포함하므로 변환 후 손실이 없다. 전제: 버전 1 파일은 `cardIssued`·`initialStation`·`currentStation` 세 키만 가진다 — 네이티브 앱은 출시된 적이 없고 Phase 1 운영 코드에는 저장 호출부가 없다(유일한 호출부는 DEBUG 시험 경로).
- [Must] BR-5: 버전 2 파일에서 영역 하나가 통째로 없으면 손상으로 본다. 영역 안의 항목 누락 처리는 해당 후속 작업이 정한다.

### 사용자 시나리오
- 정상 흐름 A: 버전 1 사용자가 업그레이드 후 실행한다. 이전과 같은 화면으로 들어가고, 정류장 변경 같은 첫 저장 때 파일이 버전 2로 바뀐다.
- 정상 흐름 B: 신규 사용자는 파일이 없는 상태로 시작한다. 카드 발급 후 첫 저장부터 버전 2로 기록된다.
- 예외 흐름: 파일이 손상됐거나 미지원 버전이면 현재처럼 진행을 막고 원본을 보존한다. 복구 UI는 W13이 맡는다.
- 엣지 케이스:
  - 빈 파일: 손상으로 처리한다.
  - 버전 값 없음: 손상으로 처리한다.
  - 버전 2인데 영역 누락: 손상으로 처리한다.
  - 버전 3(미래 버전): 미지원으로 처리하고 원본을 보존한다.
  - 버전 1인데 카드 미발급 상태에 정류장이 있음: 내용 불일치로 처리한다.
  - 변환 도중 저장 쓰기 실패: 이전 파일과 메모리를 유지한다.
  - 앱을 이전 버전으로 되돌린 경우: 버전 2 파일은 버전 1 앱에서 미지원으로 보존된다. 이번 범위에서 별도 대응은 없다.

### 영향 범위
- 영향받는 기존 기능: 저장 및 복원, 시작 화면 분기, 저장 오류 보호. 화면 변화는 없다.
- 기존 사용자: 버전 1 사용자의 데이터가 보존된다.
- 후속 작업(W01~W05, W07, W08, W13)이 이 영역 위에서 동작한다. W08·W13은 영역 내용만 고치고 파일 구조는 바꾸지 않는다.
- 기존 시험 데이터(버전 1 샘플, 버전 999 미지원 시험 데이터)는 유효해야 한다. 버전 999는 계속 미지원이어야 한다.

### 수용 기준
- AC-1: 버전 1 파일이 데이터 손실 없이 버전 2 상태로 읽힌다. → [FR-3, FR-2, FR-7]
  - Given: `{"version":1,"state":{"cardIssued":true,"initialStation":{"id":"seongsu","name":"성수","direction":1},"currentStation":{"id":"seongsu","name":"성수","direction":1}}}` 파일이 있다.
  - When: 저장소를 읽고 시작 화면 분기를 판단한다.
  - Then: 발급 여부 true, 최초·현재 정류장은 입력값과 동일하다. 카드 목록 개수는 0, 진행 중 여정은 없음, 완료 기록 개수는 0이다. 시작 화면 분기 결과는 메인이고, 읽기 후 파일 바이트는 읽기 전과 동일하다.
- AC-2: 저장하면 항상 버전 2 형식으로 기록되고, 기존 데이터와 새 영역이 모두 유지된다. → [FR-1, FR-2, FR-4, BR-1]
  - Given: (a) 파일이 없는 상태, (b) AC-1의 버전 1 파일 상태 두 경우가 있다.
  - When: 상태를 저장하고 파일을 다시 읽는다.
  - Then: 파일의 `version`은 2이고 `state`에 `cardIssued`, `initialStation`, `currentStation`, 카드·여정·기록 영역 키가 모두 있다. (b)는 정류장 값이 AC-1과 동일하다. 다시 읽은 상태는 저장한 상태와 같고, 같은 상태를 다시 저장하면 바이트가 동일하다.
- AC-3: 지원하지 않거나 손상된 파일은 읽기와 저장 모두에서 원본이 보존된다. → [FR-5, FR-6, BR-2]
  - Given: 각각 별도 파일이다. 버전 3 파일, 버전 999 파일, 버전 0 파일, 빈 파일, 버전 값이 없는 파일, 버전 2에서 기록 영역이 없는 파일.
  - When: 읽기를 시도하고, 이어서 정상 상태 저장을 시도한다.
  - Then: 읽기는 미지원 버전(해당 버전 값) 또는 손상 오류를 던진다. 저장은 쓰기 차단 오류를 던진다. 어느 경우도 파일 바이트가 시도 전과 동일하다.
- AC-4: 내용이 맞지 않는 버전 1 파일과 쓰기 실패에서도 기존 상태가 유지된다. → [FR-6, BR-3]
  - Given: (a) `cardIssued:false`에 정류장이 있는 버전 1 파일, (b) 정상 버전 2 파일이 있고 파일 쓰기가 실패하도록 설정한 저장소가 있다.
  - When: (a)는 읽기와 저장을 시도하고, (b)는 변경된 상태를 저장한다.
  - Then: (a)는 읽기가 내용 불일치 오류를 던지고 저장이 차단되며 파일 바이트가 동일하다. (b)는 저장 실패 오류를 던지고 파일 바이트가 저장 전과 동일하다.
- AC-5: 시작 화면 분기와 기존 시험 데이터 동작이 이전과 같다. → [FR-7]
  - Given: 파일 없음, 카드 발급 true에 정류장 없음, 카드 발급 true에 정류장 둘 다 있음의 세 가지 상태가 있다. 시험용 `corrupt` 데이터와 버전 999 데이터도 있다.
  - When: 각 상태에서 시작 화면 분기를 판단한다.
  - Then: 분기 결과는 순서대로 카드 입구, 최초 정류장 입구, 메인이다. `corrupt`와 버전 999 데이터는 각각 손상·미지원 오류를 계속 일으키고, 기존 저장 관련 자동 테스트가 모두 통과한다.

### 제외 범위
- 카드 ID와 외형, 사진, 여정의 시간·버스·태그·소리·진행도, 완료 기록과 메모의 상세 항목. 후속 작업이 정한다.
- 손상이나 미지원 파일을 위한 복구 UI(재시도, 정리, 내보내기). W13 범위다.
- 이전 버전 앱으로의 하위 호환, 버전 1 백업 파일 생성, 웹 프로토타입 저장 연동.
- 영역별 별도 파일 분리.
