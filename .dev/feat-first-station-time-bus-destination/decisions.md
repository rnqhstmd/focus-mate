AskUserQuestion으로 오간 질문과 선택을 자동 기록한다. 고른 것뿐 아니라 버린 선택지도 남으므로 왜 그렇게 정했는지가 추적된다.

## 2026-10-13 20:35 · Ruling: T1 컴파일 RED → 인터페이스 뼈대 후 단언 RED

**판정.** red-writer 테스트는 대상 타입 부재로 컴파일 실패(첫 RED). 설계서 인터페이스 시그니처만 담은 뼈대(빈 값 반환)를 RouteData.swift·JourneyPlanner.swift에 넣어 단언 실패를 확인했다: 27건 중 24건 실패. 통과 3건(17분 후보 없음, 14/361분 후보 없음, 미지 id → nil)은 "없음"이 기대값인 경계 케이스라 빈 뼈대와 우연히 일치한 것이며, 어떤 형태로 다시 써도 빈 뼈대에서는 통과한다. 재작성하지 않고 회귀 가드로 유지한다.
**근거.** Swift는 누락 심볼이 테스트 타깃 전체 컴파일을 막으므로 단언 RED를 보려면 시그니처 뼈대가 필요하다(설계 "구현 순서" T1에 명시). 뼈대는 동작이 없다.
**틀리면.** 세 케이스를 다른 기대값의 케이스로 교체하도록 red-writer 재호출.

## 2026-10-13 22:24 · Ruling: T6 리뷰 Important("min" 표기) 분류와 처리

**판정.** 리뷰가 [동작결함]으로 표기한 후보 버튼의 화면 문구 "N min"을 [동작불변] 문구 정리로 재분류하고 "N분"으로 고쳤다(재현 RED 없이 정리 경로, fix-round 1/5). AC-11의 "2.75km" 화면 단언 공백은 단위 테스트(JourneyPlannerTests 25분 → "2.75km")와 렌더링이 distanceText를 그대로 쓰는 구조로 충족된 것으로 본다.
**근거.** 상태·분기·이동·저장 어느 것도 바뀌지 않는 보이는 문구 변경이고, 접근성 레이블(VoiceOver)은 이미 "N분"이다. 후보 버튼은 children: .ignore라 XCUITest로 내부 문구를 관찰할 수 없어 재현 RED를 세우려면 테스트 전용 노출이 필요하다(안티패턴).
**틀리면.** 화면 문구를 접근성 value로 노출하는 설계를 추가하고 재현 RED → 수정 경로로 다시 처리.
