## PRD: 다이나믹 아일랜드·잠금 화면 진행 표시 (Live Activity) — 확정본

규모: 대형. 앱에 없던 표시 영역을 새로 추가하고, 신규 타깃과 설정 변경이 따르며, W07과 경계가 맞닿아 있다.

### 배경
- 현재 제품 상태
  - 여행(타이머)의 남은 시간과 진행은 앱 안에서만 보인다. 잠금 화면이나 다른 앱을 쓰는 중에 확인하려면 앱을 다시 열어야 한다.
  - 타이머는 앱이 백그라운드에 있어도 계속 흐른다 (여정 요구사항 FR-5).
  - 타이머 상태는 진행 중 / 일시정지 / 도착 세 가지다.
  - 앱 안 남은 시간은 분 올림 "N min" 표기다 (JourneyTimerDisplay에서 확인).
  - 한 번 출발한 여행 화면에서 메인으로 돌아가는 길은 없다. 나가기·포기·이어가기는 W07에서 만든다.
  - 여행 정보는 버스(번호·종류), 도착지 이름, 총 시간, 경과 시간으로 구성된다 (JourneySnapshot, RouteData에서 확인). 예: 버스 "343" 간선.
- 변경 이유
  - 집중하는 동안 휴대폰을 잠그거나 다른 앱을 쓰는 것이 이 제품의 일반적인 사용 방식이다.
  - 앱 밖에서 "어느 버스로 어디까지 가는 중이고 얼마나 남았는지"가 보이면 몰입감과 확인 편의가 높아진다.
- 확정된 전제
  - 시스템이 종료 시각만 받아 직접 카운트다운한다. 앱이 1초마다 갱신하지 않는다.
  - 진도 계산은 바꾸지 않는다. 타이머의 상태와 남은 시간을 읽기만 한다 (W05 인계 노트).
  - 위젯 확장 타깃을 새로 추가하고, 앱에 Live Activity 지원 설정을 추가한다.
  - 자동 테스트는 "언제 어떤 내용으로 시작·갱신·종료를 요청하는가"와 문구 값까지만 검증한다. 실제 렌더는 W14 수동 점검이 맡는다.
- 사용자 결정 반영 요약

| 항목 | 결정 |
|---|---|
| 화면 이탈 | 일시정지 상태로 갱신해 남긴다. |
| 백그라운드 만료 | 만료 시점을 종료 시각으로 두고, 만료되면 "도착" 성격 문구를 보여준다. |
| 일시정지로 진입 | 진입하자마자 "일시정지" 카드로 시작한다. |
| 남은 시간 표기 | 시스템 카운트다운(분:초)을 쓴다. |
| 백그라운드 재동기화 | 하지 않는다. |
| 도착지 이름 | 저장된 이름을 그대로 쓴다. |

### 목표
- 여행 중 앱 밖(잠금 화면, 다이나믹 아일랜드)에서 버스·도착지·남은 시간·진행 정도를 확인할 수 있다.
- 일시정지, 재개, 도착, 화면 이탈이 앱 밖 표시에 빠짐없이 반영된다.
- 이 기능이 꺼져 있거나 실패해도 여행 진행·저장·화면에는 영향이 없다.
- 성공 지표
  - 남은 시간을 확인하려고 앱을 다시 열지 않아도 된다.
  - 도착했거나 끝난 여행의 카드가 잠금 화면에 남아 혼동시키는 사례가 없다.
  - 이 기능이 원인인 오류 안내가 사용자에게 노출되지 않는다.

### 비목표
- 진도 계산 방식의 변경.
- 여행 화면 구조 개편, 도착 안내(W09), 포기·이어가기(W07).
- 푸시 원격 갱신, 실제 GPS·버스 API.
- 카드 사진·카드 이름 등 개인 식별 요소의 표시.
- 사용자용 "앱 밖 표시 켜기/끄기" 설정 화면 (시스템 설정에 맡김).
- 앱 안 "N min" 표기를 앱 밖과 통일하는 것. 앱 밖은 분:초 카운트다운이고, 단위가 다른 것은 의도다.
- 실제 기기의 잠금 화면·아일랜드 렌더 확인 (W14 수동 점검).


### 개정 1 (설계 단계 사용자 결정, 2026-10-15) — 아래가 본문보다 우선한다

- **진행 막대 제거**: 앱 밖 표시에 진행 막대·진행 비율을 두지 않는다.
  - FR-1·FR-9·BR-2에서 "진행 정도"를 뺀다. 표시 데이터 필드는 **7개**(여행 구분자, 버스 번호, 버스 종류, 도착지 이름, 종료 시각(없을 수 있음), 멈춘 남은 초(없을 수 있음), 상태)다.
  - AC-1·2·4·8·9·20의 "진행 비율" 판정은 삭제한다. **AC-27은 삭제**한다. AC-30은 "정확히 7가지"로 바꾼다.
- **앱 시작 정리 확대 (FR-6 앱 시작 절 대체)**: 앱 시작 시 저장 상태를 기준으로 남은 표시를 맞춘다.
  - 저장된 여행이 없거나 도착 상태 → 남은 표시 전부 종료 (AC-10·11 유지).
  - 저장된 여행이 출발했고 미도착(재실행 시 일시정지로 읽힘) →
    - 다른 여행 id의 표시는 종료한다.
    - 같은 여행 id의 표시는 1개만 남기고(여분 종료) "일시정지" 상태로 갱신한다(멈춘 남은 초 = 총 초 − 저장 경과 초, 종료 시각·만료 시점 없음).
    - 같은 여행 표시가 없으면 아무것도 시작하지 않는다.
  - 신규 **AC-32**: Given 같은 여행 id 표시 1개 + 다른 여행 id 표시 1개가 남아 있고 저장된 여행이 출발·미도착(총 3600초, 경과 600초)이다 / When 앱 시작 정리 / Then 다른 id에 end 1회, 같은 id에 update 1회(상태 "일시정지", 멈춘 남은 초 3000, endDate·staleDate nil), start 0회.
  - 신규 **AC-33**: Given 같은 여행 id 표시 2개, 저장된 여행 출발·미도착 / When 앱 시작 정리 / Then end 1회(여분), update 1회(일시정지), 최종 활성 표시 1개.
  - 신규 **AC-34**: Given 남은 표시 없음, 저장된 여행 출발·미도착 / When 앱 시작 정리 / Then start·update·end 모두 0회.
- **상태 전달 방식**: 타이머 컨트롤러가 상태 변화 지점에서 알림만 보낸다(진도 계산 불변, AC-28 유지).
- **가정(보안 감사 반영)**: 도착지 이름은 앱 카탈로그의 가상 노선 정류장 이름이라 개인 식별·실제 위치 정보로 보지 않는다. 잠금 화면에 잠금 해제 없이 보이는 것은 버스 번호·종류·도착지·시간뿐이다.
- **알려진 한계(감수, M 항목 추가)**:
  - M-13: 사용자가 잠금 화면에서 카드를 직접 닫으면, 같은 화면 세션에서는 다시 띄우지 않는다.
  - M-14: 앱이 백그라운드일 때 첫 시작 요청이 나가면 시스템이 거부할 수 있고, 그 화면 세션에는 카드가 없다.
  - M-15: 일시정지·재개를 빠르게 연타하면 갱신 요청 반영 순서가 뒤바뀌어 다음 상태 변화 전까지 카드 상태가 앱과 다를 수 있다(요청 순서 비보장).
  - M-16: 저장 읽기 실패로 시작한 실행에서는 앱 시작 정리를 하지 않으므로, 복구 후에도 같은 실행 동안 이전 카드가 남을 수 있다(다음 실행 때 정리).

### 요구사항

#### 기능 요구사항
- [Must] FR-1: 여행이 진행 중 상태로 화면에 나타나면 앱 밖 표시를 1회 시작한다. 내용은 버스 번호·종류, 도착지 이름, 종료 시각(카운트다운 기준), 진행 정도, 상태 "운행 중"이다.
- [Must] FR-2: 진행 중 여행을 일시정지하면 표시를 "일시정지" 상태로 갱신하고, 카운트다운 대신 멈춘 남은 시간을 보여준다.
- [Must] FR-3: 일시정지 상태의 여행을 재개하면 표시를 갱신해 "운행 중"으로 되돌린다. 새 종료 시각은 시계 현재 시각 + 남은 초다.
- [Must] FR-4: 도착하면 표시를 종료한다.
- [Must] FR-5: 여행 화면이 사라지는 경로(leave)에서 진행 중이던 여행이 일시정지로 바뀌면, 표시를 종료하지 않고 "일시정지" 상태로 갱신해 남긴다. 이미 일시정지이거나 도착한 상태에서의 leave는 요청을 보내지 않는다.
- [Must] FR-6: 이전 실행이 남긴 표시를 현재 여행 상태에 맞춰 정리한다. 정리 시점은 두 곳이다.
  - 앱 시작 시: 저장된 여행이 없거나 이미 도착한 경우, 남은 표시를 모두 종료한다.
  - 여행 화면이 나타날 때:
    - 다른 여행의 표시는 종료한다.
    - 같은 여행의 표시가 2개 이상이면 1개만 남기고 종료한다.
    - 같은 여행의 표시가 남아 있으면 새로 시작하지 않고 현재 상태로 갱신해 재사용한다.
- [Must] FR-7: 표시를 시작·갱신·종료하지 못해도 (사용자가 설정에서 끔, 시스템 허용 안 함, 요청 실패) 여행 진행, 저장, 화면 동작은 달라지지 않는다. 사용자에게 오류도 표시하지 않는다.
  - 시작이 실패했거나 허용되지 않은 경우: 그 화면 세션에서는 재시도하지 않는다. 존재하지 않는 표시에 갱신·종료도 보내지 않는다.
  - 갱신·종료 요청이 실패한 경우: 재시도하지 않는다. 다음 상태 변화 때 정상 요청한다.
- [Must] FR-8: 상태와 표시 내용이 바뀌지 않으면 같은 요청을 반복하지 않는다. 다음 상황에서는 요청이 나가지 않는다.
  - 화면 다시 그리기
  - 포그라운드 복귀 반복
  - 틱
  - 10초 체크포인트 저장
  - 백그라운드 전환
- [Must] FR-9: 표시에 들어가는 정보는 다음으로 한정한다.
  - 여행 구분자
  - 버스 번호·종류
  - 도착지 이름 (저장된 이름 그대로)
  - 종료 시각 또는 멈춘 남은 초
  - 진행 정도
  - 상태

  카드 이름·사진·할 일·태그·소리·출발지는 넣지 않는다.
- [Must] FR-10: 표시의 모든 문구(상태 이름, 일시정지 시간 표기, 도착 안내, 접근성 설명)는 한국어다. 버스 번호·종류·도착지는 입력값 그대로 쓴다. 확정 문구는 아래 "확정 문구"에 둔다.
- [Must] FR-11: 위젯 확장 타깃을 추가하고, 앱에 Live Activity 지원 설정을 넣는다. 기존 앱 빌드와 기존 자동 테스트는 그대로 통과해야 한다.
- [Must] FR-12: 진행 중 표시에는 만료 시점을 종료 시각으로 지정한다. 앱이 깨어 있지 않아도 종료 시각이 지나면 시스템이 만료 처리하고, 카드는 "도착했어요"를 보여준다.
- [Should] FR-13: 저장 실패로 타이머가 자동 일시정지된 경우에도 표시를 "일시정지"로 갱신해 앱 안과 앱 밖이 어긋나지 않게 한다.
- [Must] FR-14: 일시정지 상태로 화면에 나타난 여행(autoStart 없이 생성, 저장된 일시정지)은 진입하자마자 "일시정지" 표시를 시작한다. 이후 재개는 새 시작이 아니라 갱신이다.

#### 비즈니스 규칙
- [Must] BR-1: 종료 시각은 "요청 시점의 시계 현재 시각 + 타이머의 남은 초"다.
- [Must] BR-2: 진행 정도는 "경과 초 ÷ 총 초"이며 0 이상 1 이하다.
- [Must] BR-3: 동시에 존재하는 표시는 최대 1개다. 같은 여행의 표시가 이미 있으면 시작하지 않고 갱신한다.
- [Must] BR-4: 이미 도착한 여행으로 진입하면 표시를 시작하지 않는다.
- [Must] BR-5: 만료 시점(staleDate) 정책
  - "운행 중" 요청에는 항상 staleDate = 종료 시각으로 지정한다.
  - "일시정지" 요청에는 staleDate와 종료 시각을 지정하지 않는다. 일시정지는 시간이 흐르지 않으므로 만료되지 않는다.
- [Must] BR-6: 표시의 존재 여부는 여행 진도, 저장, 체크포인트, 화면 전환 결과를 바꾸지 않는다.
- [Must] BR-7: 앱 밖은 시스템 카운트다운(분:초)이고 앱 안은 "N min"이다. 이 표기 차이는 의도다. 일시정지 중 멈춘 시간은 "M:SS" 형식으로 보여준다.

#### 품질 기대
- [Should] QE-1: 잠금 화면의 남은 시간이 앱 안 남은 시간과 1분 이상 어긋나지 않는다.
- [Should] QE-2: 설정에서 이 기능을 꺼둔 경우에도 앱 사용 경험에 안내나 지연이 생기지 않는다.

#### 확정 문구 (FR-10)
- 상태 이름
  - 진행 중: "운행 중"
  - 일시정지: "일시정지"
  - 도착: "도착"
- 만료 안내 문구: "도착했어요"
- 일시정지 멈춘 시간 표기: "M:SS"
  - 분은 자릿수 제한이 없고, 초는 항상 2자리다.
  - 예: 3000초 → "50:00", 65초 → "1:05", 0초 → "0:00", 3600초 → "60:00"
- 접근성 설명 템플릿 (`{번호}`, `{종류}`, `{도착지}`는 입력값 그대로)
  - 운행 중: "{번호}번 {종류} 버스, 도착지 {도착지}, 운행 중"
    - 남은 시간은 시스템 카운트다운이 읽어 주므로 이 문구에는 넣지 않는다.
  - 일시정지: "{번호}번 {종류} 버스, 도착지 {도착지}, 일시정지, 남은 시간 {M}분 {S}초"
    - 예: 3000초 → "남은 시간 50분 0초", 65초 → "남은 시간 1분 5초"
  - 도착: "{번호}번 {종류} 버스, 도착지 {도착지}, 도착"

### 사용자 시나리오
- 정상 흐름
  1. 출발 안내에서 "시작"을 누르면 잠금 화면 카드와 다이나믹 아일랜드가 뜬다.
  2. 잠그면 카드에 "343 간선 / 도착지 / 분:초 카운트다운 / 진행 정도"가 보인다.
  3. 일시정지하면 카드가 "일시정지"로 바뀌고 멈춘 시간("50:00" 등)이 보인다. 재개하면 카운트다운이 이어진다.
  4. 도착하면 카드가 사라진다.
- 예외 흐름
  - 설정에서 Live Activity를 꺼둔 사용자는 표시가 없고 앱 동작은 그대로다.
  - 시스템이 시작을 거부해도 앱 안에는 오류 표시가 없다.
- 엣지 케이스
  - 앱 강제 종료 후 재실행
    - 같은 여행의 카드는 현재 상태로 갱신해 재사용한다.
    - 다른 여행이나 도착한 여행의 카드는 종료한다.
  - 일시정지로 진입하면 즉시 "일시정지" 카드가 뜨고, 재개하면 같은 카드가 운행 중으로 바뀐다.
  - 이미 도착한 여행으로 진입하면 카드를 시작하지 않는다.
  - 저장 실패로 자동 정지하면 카드도 "일시정지"로 갱신된다.
  - 백그라운드에서 종료 시각이 지나면 시스템이 카드를 만료 처리하고 "도착했어요"가 보인다.
  - 화면 이탈 후 일시정지 카드가 남는다. 앱을 다시 실행하면 정리 또는 재사용된다.

### 영향 범위
- 영향받는 기존 기능
  - 타이머 컨트롤러: 상태 변화 시점에 표시 요청을 연결한다. 진도 계산은 변경하지 않는다.
  - 여행 화면: 컨트롤러 생성부와 이탈 처리.
  - 서비스 묶음: 표시 요청 창구를 주입한다.
  - 앱 시작 지점: 정리 호출.
  - 프로젝트 구성: 위젯 확장 타깃, Live Activity 지원 설정.
- 기존 사용자 영향: 저장 형식 변경이 없고, 진행 중 여행은 그대로 이어진다. 기능이 꺼져 있으면 변화가 없다.
- W07과의 경계
  - 이번 범위: 타이머 화면 이탈 처리, 앱 시작 정리, 상태 변화 시 시작·갱신·종료.
  - W07 후속: "나가기"·"포기" 확인 시점의 표시 종료, 이어가기 진입점 통합 확인.
  - 여행 화면과 앱 모델의 대규모 변경은 하지 않는다.

### 수용 기준

용어
- "게이트웨이"는 표시 요청 창구다. 테스트에서는 요청 기록기를 쓴다.
- "시계"는 주입된 테스트 시계다.
- 요청 내용은 상태, 종료 시각(endDate), 만료 시점(staleDate), 멈춘 남은 초, 진행 비율을 말한다.
- 별도 언급이 없으면 총 3600초 여행, 시계 현재 T, 버스 "343" 간선, 저장 성공 조건이다.

AC-1: 진행 중 진입 시 시작 [FR-1, BR-1, BR-2, FR-9]
- Given: 출발한 여행이 autoStart=true로 진행 중이고, 게이트웨이에 남은 표시가 없다.
- When: 컨트롤러가 화면에 나타난다.
- Then: start가 정확히 1회 요청된다.
  - 상태는 "운행 중"이고, endDate는 T + 3600초이며, 진행 비율은 0.0이다.
  - 버스 번호 "343", 종류 "간선", 저장된 도착지 이름이 포함된다.
  - 카드 이름·할 일·태그·소리·출발지 값은 요청에 없다.

AC-2: 일시정지 시 갱신 [FR-2, BR-2, BR-5]
- Given: AC-1 상태에서 시계가 600초 흐른 진행 중 여행이다.
- When: 사용자가 일시정지를 누르고 저장이 성공한다.
- Then: update가 정확히 1회 요청된다.
  - 상태는 "일시정지"이고, 멈춘 남은 초는 3000이다.
  - 진행 비율은 600÷3600(허용 오차 0.0001)이다.
  - endDate와 staleDate는 없음(nil)이다.

AC-3: 일시정지 중 반복 요청 없음 [FR-2, FR-8]
- Given: AC-2 직후이고 시계가 300초 더 흐른다.
- When: 포그라운드 복귀와 화면 다시 그리기가 각각 3회 일어난다.
- Then: 추가 요청이 0회다. 컨트롤러 remainingSeconds는 3000으로 유지된다.

AC-4: 재개 시 종료 시각 재계산 [FR-3, BR-1, BR-5]
- Given: AC-3 상태에서 시계 현재가 T2이다.
- When: 사용자가 재개를 누르고 저장이 성공한다.
- Then: update가 1회 요청된다.
  - 상태는 "운행 중"이다.
  - endDate는 T2 + 3000초이고, staleDate는 endDate와 같다.
  - 진행 비율은 600÷3600이다.
  - start는 추가되지 않는다.

AC-5: 전이 실패 시 요청 없음 [FR-3, BR-6]
- Given: 일시정지 상태이고 다음 저장이 실패하도록 설정되어 있다.
- When: 사용자가 재개를 누른다.
- Then: 게이트웨이 요청이 추가되지 않고, 타이머 상태는 일시정지로 유지된다.

AC-6: 도착 시 종료 [FR-4]
- Given: 표시가 시작된 진행 중 여행이고, 시계가 3600초 흐른다.
- When: 틱 또는 포그라운드 복귀로 도착이 처리된다.
- Then: end가 정확히 1회 요청된다. 이후 start/update 요청은 0회다.

AC-7: 도착 상태 진입 시 시작 안 함 [BR-4]
- Given: 저장된 경과 초가 총 초와 같은 도착 상태이고, 남은 표시가 없다.
- When: 컨트롤러가 생성되어 화면에 나타난다.
- Then: start, update, end 요청이 모두 0회다.

AC-8: 일시정지 진입 시 일시정지 카드 시작 [FR-14, BR-2, BR-5]
- Given: 저장된 경과 600초의 일시정지 여행이거나 autoStart=false로 생성되어 일시정지이고, 남은 표시가 없다.
- When: 컨트롤러가 화면에 나타난다.
- Then: start가 1회 요청된다.
  - 상태는 "일시정지"이고, 멈춘 남은 초는 3000이며, 진행 비율은 600÷3600이다.
  - endDate와 staleDate는 없음(nil)이다.

AC-9: 일시정지 진입 후 재개는 갱신 [FR-14, FR-3, BR-3]
- Given: AC-8 상태이고 시계 현재가 T3이다.
- When: 사용자가 재개를 누르고 저장이 성공한다.
- Then: update가 1회 요청된다.
  - 상태는 "운행 중"이고, endDate는 T3 + 3000초이며, staleDate는 endDate와 같다.
  - 해당 여행의 start 누적은 1회 그대로다.

AC-10: 앱 시작 시 고아 표시 종료 [FR-6]
- Given: 게이트웨이에 이전 실행이 남긴 표시가 1개 있고, 저장된 여행이 없다.
- When: 앱 시작 정리가 실행된다.
- Then: end가 1회 요청되고, start/update는 0회다.

AC-11: 도착한 여행의 남은 표시 종료 [FR-6, FR-4]
- Given: 게이트웨이에 같은 여행 id의 표시가 1개 남아 있고, 저장된 여행은 도착 상태다.
- When: 앱 시작 정리가 실행되거나 해당 여행 화면이 나타난다.
- Then: end가 정확히 1회 요청되고, start/update는 0회다.

AC-12: 같은 여행의 진행 중 표시 재사용 [FR-6, BR-3]
- Given: 같은 여행 id의 남은 표시가 1개 있고, 컨트롤러는 진행 중이며 시계 현재가 T4이다.
- When: 컨트롤러가 화면에 나타난다.
- Then: start 0회, update 1회다.
  - 상태는 "운행 중"이고, endDate는 T4 + remainingSeconds이며, staleDate는 endDate와 같다.

AC-13: 같은 여행의 일시정지 표시 재사용 [FR-6, FR-14, BR-3]
- Given: 같은 여행 id의 남은 표시가 1개 있고, 컨트롤러는 일시정지이며 경과 600초이다.
- When: 컨트롤러가 화면에 나타난다.
- Then: start 0회, update 1회다. 내용은 AC-8의 일시정지 내용(멈춘 남은 초 3000, endDate·staleDate 없음)과 같다.

AC-14: 같은 여행의 중복 표시 정리 [FR-6, BR-3]
- Given: 같은 여행 id의 남은 표시가 2개 있고, 컨트롤러는 진행 중이다.
- When: 컨트롤러가 화면에 나타난다.
- Then: end 1회(여분 1개), update 1회, start 0회다. 최종 활성 표시는 1개다.

AC-15: 다른 여행의 표시 교체 [FR-6, BR-3]
- Given: 다른 여행 id의 남은 표시가 1개 있고, 현재 컨트롤러는 진행 중이다.
- When: 컨트롤러가 화면에 나타난다.
- Then: 남은 표시에 대해 end 1회, 현재 여행에 대해 start 1회가 요청된다. 최종 활성 표시는 1개이고 현재 여행의 것이다.

AC-16: 요청 실패 시 앱 동작 불변 [FR-7, BR-6]
- Given: 게이트웨이의 모든 요청이 실패하도록 설정되어 있다.
- When: 진행 중 시작 후 일시정지, 재개, 도착을 거친다.
- Then: 컨트롤러 status 전이는 running → paused → running → arrived이다.
  - 저장 요청 횟수와 내용이 게이트웨이 성공 시와 같다.
  - showsTransitionFailure와 showsSaveWarning은 계속 false이다.

AC-17: 표시 사용 불가 시 추가 요청 없음 [FR-7]
- Given: 게이트웨이의 start가 "사용 불가"(사용자가 Live Activity를 끈 상태)로 실패한다.
- When: 진행 중 시작에 이어 일시정지, 재개, 도착이 일어난다.
- Then: start 시도는 1회이고, 이후 update와 end 요청은 0회다. 사용자용 오류 문구 노출은 0건이다.

AC-18: 같은 상태 중복 요청 억제 [FR-8]
- Given: 진행 중으로 start가 이미 요청되었다.
- When: 틱 10회, returnToForeground 3회, appear 3회가 호출되고 상태 변화가 없다.
- Then: start/update 추가 요청이 0회다.

AC-19: 체크포인트 저장은 요청을 유발하지 않음 [FR-8]
- Given: 진행 중이고 10초 체크포인트 간격으로 저장이 반복된다.
- When: 체크포인트 저장이 3회 성공한다.
- Then: 게이트웨이 추가 요청이 0회다.

AC-20: 저장 실패 자동 정지 시 갱신 [FR-13, BR-2]
- Given: 진행 중이고 경과 120초이며 다음 체크포인트 저장이 실패하도록 설정되어 있다.
- When: 저장이 실패해 컨트롤러가 정지(showsSaveWarning == true)한다.
- Then: update가 1회 요청된다.
  - 상태는 "일시정지"이고, 멈춘 남은 초는 정지 시점의 remainingSeconds이다.
  - 진행 비율은 정지 시점 경과 ÷ 3600이다.
  - endDate와 staleDate는 없음(nil)이다.

AC-21: 백그라운드 전환 시 요청 없음 [FR-8]
- Given: 진행 중이고 표시가 이미 시작되었다.
- When: enterBackground가 호출되고 저장이 성공한다.
- Then: 게이트웨이 추가 요청이 0회다.

AC-22: 만료 시점 정책 [FR-12, BR-5]
- Given: 진행 중 start, 재개 update, 재사용 update(AC-1, AC-4, AC-12), 일시정지 start/update(AC-2, AC-8, AC-13, AC-20)를 각각 기록한다.
- When: 각 요청의 staleDate를 검사한다.
- Then: 상태 "운행 중" 요청은 모두 staleDate == endDate이다. 상태 "일시정지" 요청은 모두 staleDate가 없음(nil)이다.

AC-23: 도착 후 복귀 시 중복 종료 없음 [FR-4, FR-8]
- Given: 백그라운드 중 시간이 총 시간을 넘겼다.
- When: returnToForeground가 호출되고, 이어서 appear가 2회 호출된다.
- Then: end 요청은 총 1회다.

AC-24: 진행 중 화면 이탈 시 일시정지로 갱신 [FR-5]
- Given: 경과 900초의 진행 중이고 표시가 시작된 여행이다.
- When: leave가 호출되고 저장이 성공해 일시정지로 전환된다.
- Then: update가 1회 요청된다.
  - 상태는 "일시정지"이고, 멈춘 남은 초는 이탈 시점 remainingSeconds(2700)이다.
  - endDate와 staleDate는 없음(nil)이다.
  - 이후 start 요청은 0회이고, end 요청도 0회다.

AC-25: 일시정지·도착 상태의 leave 시 요청 없음 [FR-5, FR-8]
- Given: 일시정지 상태(표시 유지)인 경우와 도착해 표시가 종료된 경우를 각각 준비한다.
- When: 각각 leave가 호출된다.
- Then: 두 경우 모두 게이트웨이 추가 요청이 0회다.

AC-26: 한국어 문구 [FR-10, BR-7]
- Given: 문구 정의에 버스 번호 "343", 종류 "간선", 도착지 "서울역"을 넣는다.
- When: 세 상태의 상태 이름, 만료 안내 문구, 일시정지 시간 표기, 접근성 설명을 요청한다.
- Then: 반환 문자열이 아래 값과 정확히 같다.
  - 상태 이름: "운행 중", "일시정지", "도착"
  - 만료 안내 문구: "도착했어요"
  - 일시정지 시간 표기: 3000초 → "50:00", 65초 → "1:05", 0초 → "0:00", 3600초 → "60:00"
  - 접근성 설명, 운행 중: "343번 간선 버스, 도착지 서울역, 운행 중"
  - 접근성 설명, 일시정지(3000초): "343번 간선 버스, 도착지 서울역, 일시정지, 남은 시간 50분 0초"
  - 접근성 설명, 일시정지(65초): "343번 간선 버스, 도착지 서울역, 일시정지, 남은 시간 1분 5초"
  - 접근성 설명, 도착: "343번 간선 버스, 도착지 서울역, 도착"

AC-27: 진행 비율 범위 [BR-2]
- Given: 경과 초가 0, 1800, 3600(총 3600초)인 세 경우다.
- When: 진행 비율을 계산한다.
- Then: 값은 각각 0.0, 0.5, 1.0이다. 경과가 총 시간을 초과하는 입력(예: 4000)은 1.0으로 제한되고, 음수 입력은 0.0으로 제한된다.

AC-28: 진도 계산 불변 [BR-6]
- Given: 게이트웨이를 연결한 컨트롤러와 연결하지 않은 컨트롤러가 같은 시계 진행과 같은 조작 순서를 받는다.
- When: 시작, 일시정지, 재개, 도착까지 진행한다.
- Then: 두 컨트롤러의 status, elapsedSeconds, remainingSeconds, 저장 요청 목록이 매 단계 같다. 기존 JourneyTimerController 단위 테스트가 변경 없이 전부 통과한다.

AC-29: 프로젝트 구성 [FR-11]
- Given: 위젯 확장 타깃과 Live Activity 지원 설정이 추가된 프로젝트다.
- When: `python3 scripts/check-ios.py build`와 `test`를 실행한다.
- Then: 빌드가 성공하고, 앱 Info의 Live Activity 지원 값이 true이다. 기존 FocusMate 단위·UI 테스트 중 이번 변경으로 새로 실패하는 건수가 0건이다.

AC-30: 데이터 최소화 [FR-9]
- Given: 표시 데이터 모델의 필드 목록이다.
- When: 필드 목록을 검사한다.
- Then: 필드는 정확히 다음 여덟 가지다: 여행 구분자, 버스 번호, 버스 종류, 도착지 이름, 종료 시각(없을 수 있음), 멈춘 남은 초(없을 수 있음), 진행 비율, 상태. 카드 id·카드 이름·할 일·태그·소리·출발지 필드는 없다.

AC-31: 도착지 이름 그대로 사용 [FR-9]
- Given: 저장된 도착지 이름이 "서울역"이고, 지도 일관성 규칙으로 지도가 생략되는 여행이다.
- When: 시작 요청이 만들어진다.
- Then: 요청의 도착지 이름은 "서울역"과 정확히 같다.

### 수동 점검 항목 (W14로 이관, 자동 테스트 제외)
- M-1: 잠금 화면 카드에 버스·도착지·분:초 카운트다운·진행 정도가 읽기 쉽게 보인다.
- M-2: 다이나믹 아일랜드 컴팩트·최소·확장 형태가 각각 표시되고 내용이 잘리지 않는다.
- M-3: 진행 중 시스템이 앱 호출 없이 카운트다운을 이어간다 (앱이 백그라운드·정지여도).
- M-4: 일시정지 시 카운트다운이 멈추고 "M:SS" 정적 시간이 보인다. 재개하면 같은 카드에서 카운트다운이 이어진다.
- M-5: 일시정지 카드가 오래 방치돼도 "도착했어요"로 바뀌지 않고 일시정지로 남는다 (Q2·Q3 반영).
- M-6: 백그라운드에서 종료 시각이 지나면 카드가 0에서 멈춘 채 남지 않고 "도착했어요"로 바뀐다 (Q2 반영).
- M-7: 일시정지 상태로 화면에 진입(재실행 후 등)하면 즉시 "일시정지" 카드가 보이고, 재개하면 같은 카드가 운행 중으로 바뀐다 (Q3 반영).
- M-8: 설정에서 Live Activity를 끈 상태로 여행을 진행해도 앱에 오류 표시가 없다.
- M-9: VoiceOver로 카드를 읽을 때 한국어로 버스·도착지·상태·(일시정지 시) 남은 시간이 들린다.
- M-10: 큰 글자·다크/라이트에서 카드 가독성이 유지된다.
- M-11: 앱 강제 종료 후 재실행하면 남은 카드가 현재 상태와 맞게 정리 또는 재사용된다 (같은 여행은 유지, 도착·없음은 사라짐).
- M-12: 화면 이탈 후 일시정지 카드가 남고, 앱을 다시 열면 같은 카드가 재사용된다 (Q1 반영).

### 제외 범위 / 후속
- W07: "나가기"·"포기" 확인 시점의 표시 종료 연결. 이어가기 진입점 통합 확인 (FR-14, AC-13이 대응 규칙).
- W09: 도착 안내 화면과 연동한 문구·마무리 조정.
- W14: M-1 ~ M-12 실기기 점검.
- 후속 검토
  - 앱 강제 종료 중 일시정지 카드는 앱을 다시 실행하기 전까지 정리되지 않는다 (일시정지 카드는 만료 지정이 없기 때문). 원격 갱신은 도입하지 않으며, 이 한계는 감수한다.
  - 백그라운드 재동기화는 하지 않는다.
  - 사용자용 켜기/끄기 설정은 후속으로 둔다.
  - 시작 실패 후 같은 세션 내 재시도는 하지 않는다.

### 자가 검증
- 유저 경험 관점
  - 가장 큰 위험은 일시정지 중 카운트다운이 계속 흐르는 오표시다. AC-2, AC-3, AC-22가 막는다.
  - 도착한 여행의 카드가 남는 위험은 FR-4, FR-6, FR-12가 막는다.
  - 일시정지 카드는 만료되지 않는다 (BR-5). 앱 강제 종료 후 방치되면 남는 한계는 위 후속에 명시했다.
- 해석 여지 관점
  - 상태 이름, 만료 문구, 시간 표기, 접근성 문구는 모두 확정 문자열이다 (AC-26).
  - 모든 Then은 요청 횟수와 값(상태, 종료 시각, 만료 시점, 멈춘 남은 초, 진행 비율), 또는 문구 문자열로 한정했다. 시각 표현은 M 항목으로 분리했다.
  - 운행 중 접근성 문구에 남은 시간이 없는 것은 시스템 카운트다운이 읽기 때문이다 (BR-7).
- 모순 점검
  - 일시정지 진입 시 start (AC-8)와 재개 시 update (AC-9)는 일관된다.
  - 같은 여행의 남은 카드는 start가 아니라 update로 재사용한다 (AC-12, AC-13). 그래서 AC-8의 "남은 표시가 없다" 조건과 충돌하지 않는다.
  - 정리 후 최종 활성 표시는 항상 1개다 (AC-14, AC-15). AC-10과 AC-11의 end는 앱 시작 정리 기준이다.
  - 시작 실패 후 요청이 없는 규칙 (AC-17)은 재사용·정리 경로와 충돌하지 않는다. 정리의 end는 실제 남은 표시가 있을 때만 나간다.
- 엣지 커버리지: 설정 꺼짐, 요청 실패, 고아 표시, 중복 표시, 다른 여행 표시, 도착 진입, 일시정지 진입, 자동 정지, 이탈, 백그라운드 만료, 반복 갱신, 전이 실패를 모두 다룬다.
- 요구사항 매핑: 모든 FR/BR은 최소 1개 AC에 연결된다. FR-11은 AC-29, FR-12는 AC-1·AC-22·M-6, BR-7은 AC-26이다. QE-1·QE-2는 M-3, M-8로 확인한다.
