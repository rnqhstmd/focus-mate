# PRD: W06 MapKit 가상 코스 (여행 화면 지도)

규모: 대형. 신규 화면 요소가 생기고, 여행 화면 배치가 바뀌며, 접근성과 동작 줄이기에도 영향이 있다.

### 배경
- 현재 제품 상태: 출발 안내의 '시작' 뒤 여행 화면은 검은 배경에 남은 시간("N min")과 일시정지/재개 버튼 하나뿐이다. 지도, 버스 움직임, 정류장 표시가 없다(JourneyTimerView에서 확인). 이 화면은 W05(실제 분 타이머)가 만들었고, 인계 메모(`.dev/plan.md`)는 "W06: 타이머 화면 위에 지도를 올린다(남은 시간 하단 좌측)"로 정해 두었다.
- 정류장은 성수 일대 실존 지명 9개가 순환하는 앱 내 가상 코스다. 지금은 이름만 있고 위치 좌표는 없다(RouteData에서 확인).
- 웹 프로토타입은 이미 폐곡선 코스, 진도에 따른 버스 이동, 따라가기/자유 탐색, 지도 테마 시트(어두운 지도/위성, 정류장 표시)를 갖고 있다. 위성은 색 필터를 씌운 시연이다(`animation-preview.html`, FLOWS 68-74행에서 확인).
- `context/journey/status.md`의 FR-6 [iOS·P3] MapKit 가상 코스(AC-7: "기본 지도와 승인된 앱 내 가상 코스를 표시한다. 실제 GPS·버스 API는 범위 밖")는 아직 ⬜이다. 이 PRD가 그 요구사항을 구체화한다.
- 기대 효과: 사용자는 줄어드는 숫자만 보는 대신 "버스를 타고 가는 중"이라는 여행 경험을 화면에서 느낀다.

### 목표
- 여행 화면 배경이 Apple 지도로 바뀌고, 가상 코스 위에서 버스가 타이머 진도에 맞춰 움직인다.
- 사용자가 지도를 마음대로 둘러보다가 한 번 눌러 버스로 돌아올 수 있다.
- 지도를 보는 동안에도 남은 시간, 일시정지, 안전한 저장은 지금처럼 동작한다.
- 하단에서 남은 시간·남은 정류장·남은 거리를 한눈에 본다.
- 비즈니스 관점의 성공 기준:
  - 사용자가 별도 안내 없이 "버스가 지금 어디쯤인지"를 알아본다.
  - 지도 조작이 타이머 진도나 저장 내용을 바꾸지 않는다.
  - 위치 권한 요청이 한 번도 뜨지 않는다.

### 요구사항

#### 기능 요구사항
- [Must] FR-1: (journey FR-6, status.md 미반영) 여행 화면의 검은 배경을 기본 Apple 지도로 대체한다. 남은 시간과 버튼은 지도 위에 얹힌다.
- [Must] FR-2: 지도에 앱 내 가상 코스를 그린다. 코스는 9개 순환 정류장을 `성수역 → 성수동 → 뚝섬역 → 성동구민체육센터 → 서울숲역 → 서울숲 입구 → 성수대교 북단 → 뚝섬한강공원 → 성수사거리 → (성수역)` 순서로 정류장 사이를 직선으로 잇는 닫힌 선이다. 이번 여행의 도착 정류장은 구분되는 표시로 보여 준다.
- [Must] FR-3: 버스 표시가 타이머 진도에 맞춰 코스 위를 움직인다. 출발 정류장과 진행 방향(정/역)을 따르며, 진행 방향은 버스 표시의 방향으로 드러난다. 위치 계산은 BR-2를 따른다.
- [Must] FR-4: 카메라는 '따라가기'와 '자유 탐색' 두 상태를 가진다. 여행 화면에 들어오면 따라가기로 시작한다. 사용자가 지도를 끌거나 확대·회전하면 자유 탐색이 된다. '버스 따라가기'를 누르면 따라가기로 돌아온다(BR-3).
- [Must] FR-5: 오른쪽 위에 동그란 버튼 두 개를 세로로 둔다. 위는 '버스 따라가기', 아래는 '지도 테마'다. 2D/3D 전환, 나침반, 전체 노선 버튼은 두지 않는다.
- [Must] FR-6: '지도 테마'를 누르면 시트가 열린다. 시트에서 '어두운 지도'(기본)와 '위성' 중 하나를 고르고, '정류장 표시'를 켜고 끌 수 있다. 정류장 표시를 끄면 9개 정류장 표시가 사라진다. 코스 선, 버스, 도착 표시는 계속 보인다.
- [Must] FR-7: 일시정지 중이거나 여행 화면을 떠나면 열린 지도 테마 시트를 닫는다. 일시정지 중에는 지도 도구 두 버튼을 비활성화하고, 재개하면 다시 활성화한다.
- [Must] FR-8: 지도는 기울인 3D 시점을 기본으로 한다. 사용자가 2D로 바꾸는 수단은 제공하지 않는다.
- [Must] FR-9: 지도 모드(어두운 지도/위성), 정류장 표시 여부, 카메라 상태, 2D/3D는 저장하지 않는다. 여행 화면에 들어올 때마다 기본값(따라가기, 어두운 지도, 정류장 표시 켜짐, 기울인 시점)으로 시작한다.
- [Must] FR-10: 화면 배치는 다음과 같다.
  - 하단 정보: 남은 시간은 왼쪽, 남은 정류장은 가운데, 남은 거리는 오른쪽이다.
  - 일시정지/재개 버튼은 왼쪽 위에 둔다.
  - Apple 지도 표기(법적 표기)는 남은 시간 위 왼쪽에 두고, 어떤 요소도 가리지 않는다.
- [Must] FR-11: 시스템의 '동작 줄이기'가 켜져 있으면 카메라 이동·회전·시점 전환 애니메이션을 줄인다. 따라가기 상태에서도 지도를 회전시키지 않는다. 상태 변화(따라가기/탐색 전환, 시트 열림/닫힘)는 동작 줄이기와 무관하게 동일하다.
- [Must] FR-12: 접근성을 지킨다.
  - VoiceOver는 지도를 하나의 요소로 읽는다. 값에 다음 정류장과 도착 정류장이 들어간다.
  - 두 도구 버튼과 시트의 모든 선택지는 이름과 현재 상태를 읽어 준다.
  - 큰 글자(Dynamic Type) 최대 크기에서도 모든 버튼이 눌리고 시트 내용이 잘리지 않는다.
- [Must] FR-13: 도착(arrived) 상태에서 버스 표시는 도착 정류장 위치에 멈춘다.
- [Must] FR-14: 위치 권한을 요청하지 않고 사용자 현재 위치를 표시하지 않는다. 실제 GPS, 버스 API, 실시간 위치는 쓰지 않는다.
- [Must] FR-15: 하단 정보에 '남은 정류장'(가운데)과 '남은 거리'(오른쪽)를 남은 시간과 함께 보여 준다. 라벨은 위, 숫자는 아래다(FLOWS 계약).
- [Should] FR-16: 지도 타일을 불러오지 못해도(오프라인 등) 타이머, 일시정지/재개, 저장, 도구 버튼은 그대로 동작한다. 지도가 복구되면 별도 조작 없이 다시 보인다.
- [Could] FR-17: 따라가기 중 지도는 버스가 향하는 방향이 위쪽이 되도록 회전한다. 동작 줄이기에서는 북쪽을 위로 고정한다(웹 프로토타입 동작).

#### 비즈니스 규칙
- [Must] BR-1: 가상 코스는 "앱 내 가상 코스"이며 실제 버스 노선이 아니다. 정류장 좌표는 각 정류장의 실제 위치(근사)다. 앱의 대상 지역은 서울 전체이므로 좌표 허용 범위는 서울시 경계 상자(위도 37.41~37.72, 경도 126.76~127.19)다. 좌표는 정류장 id에 묶인 데이터로 두어, 이후 정류장 카탈로그가 서울 전역으로 늘어도 코드 변경 없이 좌표만 추가한다(2026-10-15 사용자 결정). 정류장 사이는 도로를 따르지 않고 직선으로 잇는다. 실제 노선번호 안내나 도착 예측처럼 실제 운행으로 오해될 표기를 새로 만들지 않는다.
- [Must] BR-2: 진도→버스 위치 규칙.
  - 한 정류장 구간의 소요 시간은 선택한 버스의 정류장당 시간(2014번 5분, 강남02 6분, 343 8분)이다.
  - 이동한 정류장 수는 `경과 초 ÷ (정류장당 분 × 60)`이다. 소수 부분은 구간 안의 위치다.
  - 출발 정류장에서 시작해 정방향이면 +1, 역방향이면 -1 순서로 진행한다. 9번째 다음은 첫 정류장이다.
  - 구간 안의 위치는 두 정류장 사이 직선을 일정한 비율로 보간한다.
  - 이동 정류장 수가 총 정류장 수(`총 분 ÷ 정류장당 분`)에 닿으면 도착 정류장에 멈춘다.
  - 360분처럼 한 바퀴를 넘는 여정은 코스를 여러 바퀴 돈다.
  - 일시정지 중에는 위치가 변하지 않는다. 앱이 백그라운드에서 돌아오면 흐른 시간만큼 한 번에 이동한 위치를 보여 준다. 진도 계산은 W05를 그대로 따르며 지도가 바꾸지 않는다.
- [Must] BR-3: 카메라 상태 전환.
  - 따라가기에서 사용자가 직접 지도를 끌거나 확대·회전하면 자유 탐색이 된다.
  - 앱이 버스를 따라 카메라를 옮기는 동작은 자유 탐색으로 바꾸지 않는다.
  - 자유 탐색에서 '버스 따라가기'를 누르면 따라가기가 된다.
  - 따라가기 중 '버스 따라가기'를 눌러도 상태는 그대로 따라가기다(웹 프로토타입의 토글과 다름).
  - 일시정지/재개는 카메라 상태를 바꾸지 않는다.
  - 자유 탐색 중에도 버스 표시는 계속 코스를 따라 움직인다.
  - 일시정지 중에도 지도 직접 조작(끌기·확대)은 허용한다. 비활성인 것은 두 도구 버튼뿐이다.
- [Must] BR-4: 도구 버튼은 진행 중(running)과 도착(arrived) 상태에서 활성이고, 일시정지(paused) 상태에서 비활성이다. 도착 상태의 활성 여부는 W09가 도착 안내를 만들 때 다시 정한다.
- [Must] BR-5: 지도 테마 시트가 닫히는 때는 일시정지될 때, 여행 화면을 떠날 때, 도착 상태가 될 때, 사용자가 직접 닫을 때다.
- [Must] BR-6: 지도 조작과 테마 변경은 타이머 진도, 일시정지 상태, 저장 파일 내용(`app-state.json` 버전 4)을 바꾸지 않는다. 지도 때문에 저장이 새로 일어나지 않는다.
- [Must] BR-7: 남은 정류장 = `총 정류장 수 − floor(이동 정류장 수)`. 남은 거리 = `총 정류장 수 × 0.55km × (1 − 진도 비율)`을 소수 첫째 자리까지 표시한다. 도착 시 둘 다 0이다.
- [Must] BR-8: 지도 도구의 두 버튼과 시트가 쓰는 문구는 한국어이고, 지도 모드 이름은 '어두운 지도', '위성'이다.

#### 품질 기대
- [Should] QE-1: 사용자는 지도를 조작해도 남은 시간이 느려지거나 멈췄다고 느끼지 않는다.
- [Should] QE-2: 일시정지 후 재개했을 때 버스가 튀지 않고 멈췄던 자리에서 이어서 움직인다.
- [Should] QE-3: 사용자가 별도 설명 없이 두 버튼의 용도를 구분한다. 이는 W14 실기기 확인에서 본다.

### 사용자 시나리오

정상 흐름
1. 출발 안내에서 '시작'을 누르면 같은 화면이 지도로 바뀐다. 남은 시간·남은 정류장·남은 거리가 하단에, 일시정지가 왼쪽 위에 보이고, 오른쪽 위에 두 도구 버튼이 있다. 지도는 버스를 따라간다.
2. 사용자가 지도를 끌어 주변을 둘러본다. 버스는 계속 움직이지만 카메라는 따라가지 않는다. '버스 따라가기'를 누르면 버스로 돌아온다.
3. '지도 테마'로 위성을 고르고 정류장 표시를 끈다. 코스 선과 버스는 그대로다.
4. 일시정지하면 열린 시트가 닫히고 두 도구 버튼이 비활성이 된다. 재개하면 다시 활성이 되고 카메라 상태는 일시정지 전과 같다.
5. 0초가 되면 버스는 도착 정류장에 멈추고 "도착했어요"가 보인다.

예외·엣지 흐름
- 앱 종료 후 재실행: 메인으로 간다. 이어가기는 W07이다. W07이 여행 화면을 다시 열면 일시정지 상태이고 지도 설정은 기본값이다.
- 360분 여정: 코스를 여러 바퀴 돈다. 출발 정류장과 도착 정류장이 같을 수 있다(정류장 수가 9의 배수).
- 역방향 출발: 버스가 코스를 반대로 돈다.
- 도착 직전(남은 1분 이내): 버스가 도착 정류장에 거의 닿아 있고 남은 정류장은 1 또는 0이다.
- 지도 테마 시트가 열린 채 시간이 0이 되면 시트가 닫히고 도착 상태가 된다.
- 지도를 못 불러오는 환경: 선과 버스는 그려지고 타이머는 정상이다.
- 큰 글자 설정: 하단 정보 세 개와 시트가 줄바꿈 또는 세로 쌓임으로 읽히고, 법적 표기를 가리지 않는다.

### 영향 범위
- 영향받는 기존 기능: W05 타이머 화면의 배경과 배치가 바뀐다(남은 시간이 중앙에서 하단 왼쪽, 일시정지가 왼쪽 위로). 접근성 식별자 `journey.timer.remaining`, `journey.timer.pause`, `journey.timer.resume`, `journey.arrived`, `journey.timer.saveFailure`, `journey.timer.saveWarning`는 유지한다. 중앙 배치를 전제로 한 기존 UI 테스트는 재검증 대상이다.
- 저장 형식: 변경 없음(버전 4 유지, 지도 관련 키 추가 없음).
- 기존 사용자 영향: 진행 중 여정은 그대로 이어지고, 달라지는 것은 화면 모습뿐이다.
- 연계 작업:
  - W07: 이어가기와 포기는 여행 화면의 나가기 수단을 만들 때 이 PRD의 '장면 이탈' 규칙(시트 닫힘)을 따른다.
  - W09: 도착 안내와 정류장 목록을 함께 설계하고, 도착 상태의 도구 활성 여부를 다시 정한다.
  - W15: 다이나믹 아일랜드는 진도 값을 쓰며 이 지도와 독립이다.
  - W14: 실기기 확인이다.

### 수용 기준

AC의 "코스 좌표"는 승인된 코스 데이터를 가리킨다. 위치 계산 단위 테스트는 특정 위도·경도 값이 아니라 정류장 좌표와의 일치로 판정한다. 화면 AC에서 W는 화면 너비, H는 화면 높이다.

화면 구성
- AC-1: Given 출발 후 타이머가 진행 중이다. When 여행 화면이 표시된다. Then 지도 요소(`journey.map`), 남은 시간(`journey.timer.remaining`), 남은 정류장(`journey.timer.stops`), 남은 거리(`journey.timer.distance`), 일시정지 버튼(`journey.timer.pause`), 두 도구 버튼(`journey.map.follow`, `journey.map.theme`)이 모두 존재한다. → [FR-1, FR-5, FR-10, FR-15]
- AC-2: Given 여행 화면이다. When 각 요소의 frame을 비교한다. Then 다음이 모두 참이다. → [FR-5, FR-10, FR-15]
  - `remaining.midY > H/2`이고 `remaining.midX < W/2`
  - `stops.midY > H/2`이고 `W/3 < stops.midX < 2W/3`
  - `distance.midY > H/2`이고 `distance.midX > W/2`
  - `remaining.midX < stops.midX < distance.midX`
  - `pause.midY < H×0.2`이고 `pause.midX < W/2`
  - `follow.midY < H×0.2`, `theme.midY < H×0.2`, 두 버튼 모두 `midX > W/2`
  - `follow.midY < theme.midY`
- AC-3: Given 여행 화면이다. When frame을 비교한다. Then Apple 지도 표기 요소가 접근성 트리에서 확인되면 그 frame의 `maxY ≤ remaining.minY`이고 `midX < W/2`이며, 표기 frame이 남은 시간·남은 정류장·남은 거리·두 도구 버튼·일시정지 frame과 교차하지 않는다. 표기 요소를 찾지 못하면 수동 확인 M-1로 대체한다. → [FR-10]
- AC-4: Given 여행 화면이다. When 화면 요소를 전수 조회한다. Then 2D/3D 전환, 나침반, 전체 노선 버튼에 해당하는 식별자가 존재하지 않는다. → [FR-5, FR-8]

가상 코스·버스 위치(단위 테스트)
- AC-5: Given 승인된 코스 데이터. When 정류장 목록을 읽는다. Then 정확히 9개이고, 순서와 id가 `RouteStops`와 같으며, 좌표가 서로 모두 다르다. 모든 좌표가 서울 경계 상자(위도 37.41~37.72, 경도 126.76~127.19) 안이다. 코스 선은 정류장 사이 직선이며 마지막 정류장에서 첫 정류장으로 이어지는 선분을 포함해 닫혀 있다. → [FR-2, BR-1]
- AC-6: Given 출발 정류장 인덱스 i, 정방향, 버스 2014(5분), 총 25분. When 경과가 0초, 5분, 12분 30초, 25분이다. Then 위치가 순서대로 각각 정류장 i, 정류장 i+1, 정류장 i+2와 i+3의 정확히 중간, 도착 정류장(i+5)이다. 중간 위치는 두 정류장 사이 직선 위에 있다. → [FR-3, BR-2]
- AC-7: Given 같은 조건에서 역방향이다. When 경과가 5분, 25분이다. Then 위치가 각각 정류장 i-1, 정류장 i-5(9로 순환)이다. 같은 두 정류장 사이 구간을 반대로 지날 때(출발 i 정방향의 i→i+1 구간과 출발 i+1 역방향의 i+1→i 구간) 이동 방향(heading) 차이가 180°다. → [FR-3, BR-2]
- AC-8: Given 360분, 버스 2014(72정류장), 출발 정류장 i. When 경과가 45분, 360분이다. Then 위치는 각각 정류장 i(정류장 9개, 한 바퀴)와 도착 정류장이다. 경과가 360분을 넘는 값은 도착 정류장에서 고정된다. → [BR-2]
- AC-9: Given 어떤 버스 조건이든. When 경과를 0초부터 총 시간까지 올리며 위치를 연속으로 본다. Then 위치가 한 번의 계산 간격에서 한 정류장 구간 길이를 넘어 점프하지 않고, 정류장 통과 시점이 `정류장당 분 × 60초`의 배수다(강남02 6분, 343 8분 포함). → [BR-2]
- AC-10: Given 진행 중에 경과 초가 갱신된다. When 일시정지한 뒤 경과가 변하지 않는다. Then 위치가 변하지 않고 재개 후 정지 지점부터 이어진다. → [BR-2, QE-2]
- AC-11: Given 도착(arrived) 상태. When 지도 상태를 읽는다. Then 버스 위치가 도착 정류장 좌표와 일치한다. → [FR-13]

- AC-21: Given 시트가 열려 있다. When '정류장 표시'를 끈다. Then 정류장 표시 상태가 `off`이고, 코스 선·버스·도착 표시는 존재한다. 다시 켜면 `on`이다. → [FR-6]

- AC-23: Given 시트가 열려 있다. When 여행 화면을 떠나는 이벤트가 발생한다. Then 시트가 닫혀 있다. → [FR-7, BR-5]

접근성·큰 글자

- AC-34: Given 여행 화면이다. When 두 버튼의 접근성 정보를 읽는다. Then 따라가기 버튼은 라벨 "버스 따라가기"와 값("따라가는 중"/"자유 탐색 중")을 갖고, 지도 테마 버튼은 라벨 "지도 테마"를 갖는다. 비활성 상태가 접근성에 노출된다. → [FR-12, FR-5]
- AC-35: Given 시트가 열려 있다. When 접근성 값을 읽는다. Then '어두운 지도'·'위성'은 선택됨 여부를, '정류장 표시'는 켜짐/꺼짐을 값으로 갖는다. → [FR-12, FR-6]
- AC-36: Given 가장 큰 접근성 글자 크기로 실행한다. When 여행 화면과 열린 시트를 본다. Then 두 도구 버튼, 일시정지 버튼, 시트의 세 컨트롤이 모두 존재하고 hittable이며 최소 44×44pt이다. 시트 내용이 화면 밖으로 잘리지 않는다. 남은 시간·남은 정류장·남은 거리 요소가 존재하고 서로, 그리고 일시정지 버튼과 겹치지 않는다. → [FR-12, FR-15]

기존 동작 유지
- AC-38: Given W05의 타이머 시나리오(시작, 일시정지, 재개, 도착, 저장 실패 안내)를 실행한다. When 지도가 붙은 화면에서 반복한다. Then W05의 결과(남은 시간 표기 "N min", 일시정지/재개 전환, 도착 상태 문구, 저장 실패 안내 식별자)는 같다. → [FR-1, BR-6]

하단 정보
- AC-39: Given 진행 중 어떤 경과 값. When 남은 정류장·남은 거리를 계산한다. Then 남은 정류장 = 총 정류장 − floor(이동 정류장 수), 남은 거리 = 총 정류장 × 0.55 × (1 − 진도 비율)(소수 1자리)이다. 경과 0에서 총 정류장 수와 총 거리이고 도착 시 둘 다 0이다. 화면에서는 `journey.timer.stops`, `journey.timer.distance`가 같은 값을 노출한다. → [FR-15, BR-7]

복구
- AC-40: (수동 M-6으로 대체 — 설계 단계 결정) 지도 타일 로드 실패는 시뮬레이터에서 재현할 수단이 없고, 지도를 빼는 DEBUG 대체 렌더는 실제 위험을 재현하지 못한다. 타이머·도구가 지도와 독립이라는 점은 구조(지도 컨트롤러에 저장·타이머 의존 없음)와 AC-38로 보장하고, 실제 오프라인 동작은 M-6에서 확인한다. → [FR-16]

### 수동 확인 항목 (실기기·실제 낭독, W14 연계)
- M-1: Apple 지도 표기가 남은 시간 위 왼쪽에서 가려지지 않는지 눈으로 확인(AC-3이 자동 확인 불가인 경우의 대체).

- M-6: 오프라인에서 지도가 비어 있어도 사용 흐름이 자연스러운지 확인.
- M-7: 지도 렌더 픽셀 자체(코스 선과 버스가 실제로 그려지는지)는 XCUITest로 검증할 수 없어 사람이 눈으로 확인.

### PRD 자가 검증 3관점

1. 유저 경험
   - 따라가기 버튼의 의미가 웹에서는 토글이라 "눌렀더니 따라가기가 꺼졌다"가 생긴다. 그래서 항상 "버스로 복귀"로 정의했다(BR-3, AC-16).
   - 일시정지 중 지도 직접 조작을 막을지 모호했다. 막지 않고 버튼만 비활성으로 정의했다.
   - 시트가 열린 채 도착이 되는 경우가 비어 있었다(BR-5, AC-24).
   - 오프라인 지도 실패 경험이 비어 있었다(FR-16, AC-40).
   - 하단 정보가 3개가 되어 큰 글자에서 겹칠 위험이 있다. AC-36과 M-4로 확인한다.
2. 해석 여지 제거
   - "진도에 맞춰 움직인다"는 BR-2의 정류장 단위 직선 보간 규칙과 AC-6~AC-11로 구체화했다.
   - "화면 위치"는 AC-2에서 frame 비교식(midX/midY 대비 W/H)으로 못박았다.
   - 좌표 범위는 AC-5에서 위도 37.53~37.55, 경도 127.03~127.06으로 확정했다. 그 안의 구체 값은 코스 데이터 확정 때 정한다.
   - 위치 계산 AC는 정류장 좌표와의 일치로만 판정해 특정 좌표값에 묶이지 않는다.
   - "동작 줄이기"의 대상은 카메라 이동·회전·시점 전환뿐이고 버스 위치는 진도 그대로 연속이다(웹은 정류장 단위 점프이므로 차이가 있다).
3. 엣지케이스
   - 360분 다중 바퀴, 역방향, 출발=도착, 도착 후 고정, 백그라운드 복귀 후 큰 점프, 일시정지 중 조작, 시트 열린 채 이탈·도착, 앱 재실행 후 기본값, 큰 글자, 지도 로딩 실패를 다뤘다.
   - 자동 검증이 불가한 지도 렌더 픽셀(M-7)과 법적 표기 겹침(M-1)은 수동 항목으로 분리했다.

### 확정된 가정
1. 도착(arrived) 상태에서도 지도 도구는 활성이다(W09가 재정의).
2. 따라가기 중 지도 회전은 Could(FR-17)다.
3. 동작 줄이기에서 버스 위치는 정류장 단위 점프 없이 연속 이동한다.
4. 위성은 실제 위성 영상이며 도로·지명 라벨을 함께 표시한다(MapKit hybrid, 2026-10-15 사용자 결정).
5. 도착 정류장에는 별도 표시를 둔다.
