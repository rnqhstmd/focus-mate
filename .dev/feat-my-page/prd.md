## PRD: 마이페이지 (card FR-5, status.md 미반영) — 확정판

규모: 중형. 최신 시안(Pen 노드 EPnQQ, R38 마이페이지)과 사용자 최종 결정을 모두 반영했다.

### 배경
- 메인 메뉴의 "마이페이지" 버튼(open.profile)은 제목만 있는 빈 화면(screen.profile)으로 이동한다. (DestinationScreen에서 확인)
- 앱의 목적지는 준비, 기록, 설정, 마이페이지, 시간 선택이다. "카드 꾸미기" 목적지는 아직 없다. 설정은 자리표시 화면(screen.settings)만 있다. (AppModel에서 확인)
- 카드는 발급·승하차 화면에서 같은 공통 카드 외형(PassFace)과 이름 "집중동행카드"(PassIdentity)로 보인다. 카드 번호는 어떤 화면에도 표기하지 않는다. 시안 카드도 번호가 없다.
- 완료 기록(RecordSection)에는 하루 단위 요약만 있고 전체 누적 집계는 없다. 기록 한 건의 시간은 1~360분이다. 예시 기록은 저장하지 않는다. 기록 하나라도 유효하지 않으면 기존 하루 요약은 집계를 거부한다. 하차 완료 연동(W09 후속) 전이라 실사용 기록은 현재 0건이다.
- 시간 표기 결정: 시안은 영어 "0 min"이고, W02 리뷰 결정은 앱 문구에서 "분"을 쓰는 것이다. 이 마이페이지 화면에 한해 시안의 영어 "min"/"h"를 쓰기로 결정했다. W02 관례를 앱 전체에서 바꾸는 것이 아니다. 접근성 읽기 값은 한국어를 쓴다.
- 카드 꾸미기(W10)는 다른 세션이 진행 중이다. 이번에는 새 목적지 이름 cardStudio를 경계로 자리표시를 만든다.

### 목표
- 사용자가 메인에서 한 번에 마이페이지로 가서 내 카드와 누적 성과(완료한 여정 수, 함께한 시간)를 확인한다.
- 화면은 시안의 요소, 순서, 문구와 1:1로 일치한다.
- 카드는 발급·승하차 화면과 같은 카드로 보이고, 통계는 records가 집계한 값과 항상 일치한다.
- 마이페이지를 열고 닫아도 저장된 데이터는 바뀌지 않는다.
- W10과 합칠 때의 절차를 정해 둔다(두 번째로 머지하는 브랜치가 design.md "W10 합류 절차"를 수행한다). (개정 2026-10-14: W10 실측 결과 "cardStudio만 바꾸면 수정 없이 합류"는 성립하지 않음)

- 통계 값은 시안대로 큰 숫자 "0"과 "0 min"이다. 여정 수는 단위 없이 숫자만 쓴다.

#### 디자인 스펙 (AC가 아닌 시각 기준)
아래 항목은 자동 테스트 대상이 아니며 시안 대조 리뷰로 확인한다.
- 다크 배경, 밝은 글자. 제목과 큰 제목은 굵은 글꼴이고 보조 문구와 라벨 부제는 흐린 회색이다.
- 카드는 어두운 면에 얇은 테두리가 있고, 오른쪽에 서울 점묘 배경이 깔린다. 카드는 좌우 여백을 두고 화면 폭에 맞춘다.
- 통계의 큰 숫자는 설명 글자보다 훨씬 크다. 통계는 좌우 2열로 나뉜다.
- 구분선은 가는 선이고, 행 오른쪽 chevron은 회색이다.
- 화면 좌우 여백은 같고, 하단은 홈 인디케이터 영역을 비워 둔다.
- 화면 진입 시 별도 애니메이션은 없다.
- 집계 실패 안내의 색과 위치는 시안에 없으므로 통계 영역 바로 아래에 보조 문구 스타일로 둔다.

### 요구사항

#### 기능 요구사항
- [Must] FR-5 (status.md 미반영) 마이페이지 화면: 메인 메뉴의 "마이페이지"를 누르면 "화면 구성" 요소 2~6, 8~10, 12가 정해진 순서로 표시된다.
- [Must] FR-5.1 (records 쪽 하위 요구) 누적 집계: records가 저장된 전체 완료 기록에서 완료 여정 수와 누적 시간(분 합계)을 계산해 제공한다. 마이페이지와 카드는 집계를 계산하지 않고 읽기만 한다.
- [Must] FR-5.2 카드 일관성: 마이페이지 카드는 발급·승하차와 같은 공통 카드 외형과 이름 출처를 쓴다. 카드 번호는 표시하지 않는다.
- [Must] FR-5.3 빈 상태: 기록이 0건이면 여정 수 "0", 시간 "0 min"을 표시한다. 오류나 빈 화면으로 처리하지 않는다.
- [Must] FR-5.4 읽기 전용: 마이페이지를 열고 머물고 닫는 동안 저장된 어떤 데이터도 바뀌지 않는다.
- [Must] FR-5.5 뒤로: 시스템 내비게이션 뒤로 동작으로 메인으로 돌아온다.
- [Must] FR-5.6 접근성: VoiceOver로 모든 요소가 읽히고, 가장 큰 접근성 글자 크기에서도 모든 요소에 스크롤로 닿을 수 있다. 동작 줄이기가 켜져 있어도 같은 내용이 보인다.
- [Must] FR-5.7 시안 문구: 큰 제목, 보조 문구, 카드 라벨, 통계 라벨, 행 이름이 시안 문구와 글자 단위로 같다.
- [Must] FR-5.8 카드 꾸미기 행: 탭하면 새 목적지 cardStudio로 이동한다. 목적지 화면은 제목 "카드 꾸미기"(식별자 screen.cardStudio)만 있는 자리표시이다. 뒤로 가면 마이페이지로 돌아온다. 메인 메뉴에는 cardStudio를 추가하지 않는다.
- [Must] FR-5.9 설정 행: 탭하면 기존 설정 자리표시(식별자 screen.settings)로 이동한다. 뒤로 가면 마이페이지로 돌아온다.
- [Must] FR-5.10 집계 실패: 저장된 기록 중 유효하지 않은 것이 있어 집계할 수 없으면 카드는 그대로 표시하고, 통계 두 칸 값은 "-"로, 안내 "기록을 불러오지 못했어요"(profile.statsError)를 표시한다. 일부 기록만 골라 합산하지 않는다.
- [Should] FR-5.11 경계 명시: 목적지 이름 cardStudio는 W10이 같은 목적지를 실제 카드 꾸미기 화면으로 대체하는 경계이다. 마이페이지의 "카드 꾸미기" 행과 이동 경로는 W10 합류 후에도 바뀌지 않는다.

#### 비즈니스 규칙
- [Must] BR-1 화면 시간 표기: 누적 분 M을 다음과 같이 표기한다. 이 규칙은 마이페이지 화면에만 적용한다.
  - M < 60이면 "M min"이다. 예: "0 min", "59 min".
  - M ≥ 60이고 60의 배수이면 "H h"이다. 예: "1 h", "2 h", "100 h".
  - 그 외에는 "H h R min"이다. 예: "1 h 1 min", "100 h 5 min".
  - 시간에는 상한이 없고 천 단위 구분 기호를 쓰지 않는다.
- [Must] BR-2 접근성 시간 표기: 같은 구조에 한국어 단위를 쓴다. "0분", "59분", "1시간", "1시간 1분", "2시간", "100시간", "100시간 5분"이다. 화면 텍스트(min/h)와 접근성 값(분/시간)은 분리한다.
- [Must] BR-3 집계 대상: 저장된 모든 완료(하차 완료) 기록이다. 예시 기록, 진행 중, 포기한 여정은 기록에 없으므로 포함되지 않는다.
- [Must] BR-4 완료 여정 수는 기록 건수이고, 함께한 시간은 각 기록 시간(분)의 합이다. 둘은 같은 기록 묶음에서 나온다.
- [Must] BR-5 카드 번호 비표시: 마이페이지의 어떤 텍스트와 접근성 라벨에도 `FM-`으로 시작하는 카드 번호가 없다.
- [Must] BR-6 여정 수 표기: 화면에는 숫자만 쓴다. 접근성 라벨은 "완료한 여정, N회"이다.
- [Must] BR-7 W02의 "분" 관례와의 관계: 마이페이지 화면 텍스트의 "min"/"h"는 시안을 따른 화면 한정 결정이다. 다른 화면의 "분" 표기는 바꾸지 않는다.

#### 품질 기대
- [Should] QE-1 시각장애 사용자도 VoiceOver 한 번 훑기로 카드 이름, 두 통계, 두 메뉴 행을 모두 알 수 있다.
- [Should] QE-2 큰 글자 설정 사용자도 도움 없이 두 통계, 두 행, 뒤로 이동에 모두 도달한다.

### 사용자 시나리오
- 정상: 완료 기록이 25분, 25분, 15분 3건이면 여정 수 "3", 시간 "1 h 5 min"이 표시된다. VoiceOver는 "완료한 여정, 3회", "함께한 시간, 1시간 5분"으로 읽는다.
- 빈 상태: 새로 발급받은 사용자는 "0"과 "0 min"을 본다.
- 경계: 합계 59분은 "59 min", 60분은 "1 h", 61분은 "1 h 1 min"이다.
- 큰 누적: 합계 6005분은 "100 h 5 min"이다.
- 반복 진입: 열고 닫기를 반복해도 숫자와 저장은 같고, 기록이 추가된 뒤에는 늘어난 값이 보인다.
- 카드 꾸미기 이동: 마이페이지에서 "카드 꾸미기"를 누르면 자리표시 화면이 열리고, 뒤로 가면 마이페이지로 돌아온다.
- 설정 이동: "설정"을 누르면 설정 자리표시가 열리고, 뒤로 가면 마이페이지로 돌아온다.
- 예외: 유효하지 않은 기록이 있으면 카드는 그대로, 통계 값은 "-", 안내 "기록을 불러오지 못했어요"가 보인다.

### 영향 범위
- 마이페이지 자리표시 화면이 시안 구성의 실제 화면으로 바뀐다. open.profile과 screen.profile은 유지한다.
- records에 누적 집계가 추가된다. 기존 하루 요약, 기록 저장, 메모 저장은 바뀌지 않는다.
- 새 목적지 cardStudio(자리표시)가 추가된다. 메인 메뉴 구성은 그대로다. W10(다른 세션)이 같은 목적지를 실제 화면으로 바꿀 때의 경계는 FR-5.11에 명시했다.
- 기존 사용자의 저장 데이터는 변경되지 않는다. 기록 0건도 정상이다.

### 수용 기준
- AC-1: Given 메인 화면일 때 / When open.profile을 탭하면 / Then screen.profile이 존재하고 제목 텍스트가 "마이페이지"이다. → [FR-5]
- AC-2: Given 마이페이지가 열려 있을 때 / When 요소의 화면 위치를 위에서 아래로 정렬하면 / Then 순서는 screen.profile, profile.headline, profile.subhead, profile.card, profile.cardName, profile.cardTagline, profile.customize, profile.stat.journeys, profile.stat.time, profile.settings이다. → [FR-5]
- AC-3: Given 마이페이지가 열려 있을 때 / When 문구를 읽으면 / Then profile.headline은 "내 시간에, 내 취향을."이고 profile.subhead는 "한 장으로 함께하는 나만의 여정"이다. → [FR-5.7]
- AC-4: Given 마이페이지가 열려 있을 때 / When 카드 라벨과 통계 라벨을 읽으면 / Then profile.cardName은 "집중동행카드", profile.cardTagline은 "모든 몰입 여정에 함께"이고, 통계 라벨은 "완료한 여정", "함께한 시간"이다. → [FR-5.7, FR-5.2]
- AC-5: Given 마이페이지가 열려 있을 때 / When profile.card의 하위 텍스트를 수집하면 / Then "Focus Mate", "집중동행카드", "나를 위한 시간, 한 장으로."가 모두 존재하고, 비접촉 표시 요소(profile.card.contactless)와 IC 칩 요소(profile.card.chip)가 존재한다. → [FR-5.2]
- AC-6: Given 발급된 카드의 번호가 `FM-12345678`일 때 / When 마이페이지의 모든 텍스트와 접근성 라벨을 수집하면 / Then `FM-`으로 시작하는 문자열이 없다. → [BR-5]
- AC-7: Given 같은 발급 카드일 때 / When 발급 완료 화면과 마이페이지에서 카드 이름 출처(PassIdentity)를 읽으면 (승하차는 W04에서 같은 출처를 쓴다) / Then 모두 "집중동행카드"로 같다. → [FR-5.2]
- AC-8: Given 완료 기록 0건일 때 / When 마이페이지를 열면 / Then profile.stat.journeys의 값 텍스트는 "0"이고 profile.stat.time의 값 텍스트는 "0 min"이며 profile.statsError는 없다. → [FR-5.3, BR-1]
- AC-9: Given 기록 시간이 각각 25, 25, 15분인 3건일 때 / When 마이페이지를 열면 / Then profile.stat.journeys의 값 텍스트는 "3"이고 profile.stat.time의 값 텍스트는 "1 h 5 min"이다. → [FR-5.1, BR-4, BR-6]
- AC-10: Given 누적 분이 0, 59, 60, 61, 120, 6000, 6005일 때 / When 화면 시간 표기를 만들면 / Then 순서대로 "0 min", "59 min", "1 h", "1 h 1 min", "2 h", "100 h", "100 h 5 min"이다. → [BR-1]

### 제외 범위
- 카드 꾸미기의 실제 화면과 꾸미기 저장 손상 안내(W10). 이번에는 자리표시만 만든다.
- 설정 화면의 내용. W12 폐기로 자리표시만 있다.
- 통계 확장(평균, 태그별, 기간별): 기록 화면 분석의 범위이다.
- 하차 완료가 기록으로 저장되는 연동: W09 후속 범위이다.
- 카드 번호 표기, 카드 재발급과 교체.
- 다른 화면의 시간 단위 "분" 표기 변경.
- 카드 미발급 상태 처리: 메인은 카드 발급 완료가 전제다.

### PRD 품질 자가 검증
- 유저 경험: 진입, 확인, 하위 화면 이동, 복귀가 시안 순서대로 이어진다. 빈 상태와 집계 실패도 카드가 보이는 정상 화면이다. 메뉴 두 행은 빈 화면이 아니라 제목이 있는 자리표시로 이동한다.
- 해석 여지 제거: 요소 순서, 문구, 식별자, 이동 경로를 표와 FR로 고정했다. 시간 표기는 화면(min/h)과 접근성(분/시간)을 분리해 구체 값으로 나열했다. 색·크기·여백은 디자인 스펙 절로 분리했다. 미확정 질문은 없다.
- 엣지케이스: 0건, 59/60/61분, 큰 누적, 예시 기록 제외, 유효하지 않은 기록, 중복 호출, 추가 후 재진입, 저장 불변, 큰 글자, 동작 줄이기, 하위 화면 복귀를 다뤘다.

### AC 자가 검증
- 모든 FR/BR이 AC에 매핑되었다. FR-5→AC-1·2, FR-5.1→AC-9·12·14·17, FR-5.2→AC-4·5·7, FR-5.3→AC-8, FR-5.4→AC-15·31, FR-5.5→AC-16, FR-5.6→AC-18~21, FR-5.7→AC-3·4, FR-5.8→AC-23~25·28·33, FR-5.9→AC-23·26·27, FR-5.10→AC-29~32, FR-5.11→AC-33, BR-1→AC-8·10·22, BR-2→AC-11·18, BR-3→AC-13, BR-4→AC-9·12·17, BR-5→AC-6·19, BR-6→AC-9·18, BR-7→AC-22.
- 모든 AC는 Given-When-Then이다. Then은 텍스트, 위치 순서, 식별자, 접근성 라벨, 저장 바이트 비교, 이동 결과로 판정 가능하다. 색·크기·여백·애니메이션은 AC에 없다.
- 뒤로 이동은 시스템 내비게이션 뒤로 동작 후 화면 식별자의 존재 여부로 검증한다. profile.back 식별자는 쓰지 않는다.
- 식별자 profile.*는 이 PRD가 확정하는 계약이다. 카드 내부 요소 profile.card.contactless, profile.card.chip은 공통 카드 뷰에 대응하는 식별자로 구현 시 맞춘다.
- AC-14는 값 출처를 확인하는 검사이며 구현 방식을 지정하지 않는다.


### 개정 기록 (2026-10-14, 설계·리뷰 반영 — 사용자 결정)
- AC-5: 카드 내부 문구 "나를 위한 시간, 한 장으로."와 profile.card.contactless/profile.card.chip 식별자 검증은 W10(카드 꾸미기) 합류 후로 이연한다. 이번 범위는 profile.card 존재, 라벨 "집중동행카드", FM- 미포함이다. 근거: W10이 공통 카드(PassFace)를 시안 배치로 이미 재작성 중이며, 사용자 결정으로 W11은 PassFace를 수정하지 않는다.
- FR-5.11: "W10 합류 후 마이페이지 수정 불필요"를 철회한다. W10은 카드 꾸미기를 목적지 push가 아니라 전체 화면 세션으로 연다. 두 번째로 머지하는 브랜치가 꾸미기 행을 W10 진입으로 연결하고, cardStudio 자리표시를 제거하며, 마이페이지 카드를 PassFace(style:)로 바꾸고, AC-5를 검증한다.
- AC-14: "CardSnapshot에 집계 관련 필드가 없다"로 재정의한다(W10이 style 필드를 추가하므로 필드 개수는 단언하지 않는다).
- AC-29~31: 유효하지 않은 기록은 저장 파일을 읽고 쓰는 단계에서 이미 차단되어 실제 앱에서 도달할 수 없다. 단위 연쇄(records 실패 → ProfileStats.unavailable → "-" 표시)로만 검증한다.
- AC-21: 시뮬레이터에서 동작 줄이기를 자동으로 켤 수 없어, ProfileView에 애니메이션 API가 0건임을 정적으로 확인하고 실기기 확인은 W14에서 한다.
