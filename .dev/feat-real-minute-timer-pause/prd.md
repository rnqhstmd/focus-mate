## PRD: W05 실제 분 타이머·일시정지 (journey FR-5 / AC-6)

규모: 대형. 진행 여정 저장 형식이 버전 4로 바뀌고, 여러 화면 상태와 저장 규칙에 걸친다.

### 배경
- 현재 상태:
  - 승차 태그에 성공하면 진행 여정 1건을 저장한다. 필드는 분·버스·출발/도착 정류장·태그·할 일·소리·승차 시각·단계·진도(경과 초)다.
  - 여행 화면은 출발 안내('시작')까지만 구현되어 있다. 그 뒤에는 제목만 있는 임시 화면이 있다.
  - 일시정지 여부는 저장하지 않는다.
  - 선택 가능한 시간은 15~360분이다. 저장 검증은 "분 > 0"뿐이다. 정류장·버스 id는 카탈로그와 대조하지 않는다.
  - 승차가 성공한 뒤에도 준비 확정값이 남는다. 그래서 다시 승차하면 진행 여정을 덮어쓸 수 있다.
- 문제: 승차를 마쳐도 실제 집중 시간을 재는 기능이 없다. 제품의 핵심 가치가 아직 없다.
- 웹 프로토타입은 30초 압축 시연으로 "앱 밖 시간 미가산"을 계약으로 두었지만, iOS는 사용자 결정(2026-10-15 설계 단계)으로 이를 **뒤집는다**: 이 앱은 보조 도구라 다른 앱 사용·제어 센터·백그라운드 중에도 타이머가 흐른다. 앱 종료(프로세스 종료)만 여정을 끊은 것으로 본다.

### 목표
- '시작' 후 선택한 분만큼 남은 시간이 실제로 줄어든다. 일시정지·재개로 멈췄다가 이어갈 수 있다.
- 앱이 살아 있는 동안(포그라운드·비활성·백그라운드)은 시간이 계속 흐른다. 앱이 종료되면 여정은 끊긴 것으로 보고 마지막 저장 진도에서 일시정지로 복원한다(종료 중 시간 미가산). 손실은 BR-5 한도 안이다.
- 저장 실패를 사용자가 모르는 채로 진도를 잃지 않는다.

### 기능 요구사항
- [Must] FR-1: '시작'을 누르면 같은 화면이 타이머 화면으로 바뀐다. 이 화면이 `journey.placeholder`를 대체한다.
- [Must] FR-2: 타이머 화면은 남은 시간과 일시정지/재개로 구성한다. **뒤로가기는 없다**(타이머 화면에서 메인으로 갈 수 없음, 사용자 결정. 포기·나가기는 W07). 스와이프 뒤로가기도 막는다.
  - 남은 시간은 "N min"으로만 표시하고 초·h 표기는 쓰지 않는다.
  - 분은 올림으로 계산한다. "0 min"은 정확히 0초일 때만 나온다.
- [Must] FR-3: 선택한 분 전체를 1초 단위로 진행한다. 진도는 BR-1(앱 프로세스가 살아 있는 동안의 단조 시간)을 따른다.
- [Must] FR-4: 일시정지하면 즉시 저장한다. 재개해도 저장한다. 일시정지 여부도 저장되는 상태다.
- [Must] FR-5: 비활성(제어 센터·알림 센터·앱 전환기)과 백그라운드에서도 일시정지하지 않고 시간이 계속 흐른다. 백그라운드 진입 시 그 시점 진도를 진행 상태로 즉시 저장한다(체크포인트). 복귀하면 그 사이 흐른 시간이 반영된 남은 시간을 보여주고, 그 사이 0초에 도달했으면 바로 도착 상태다.
- [Must] FR-6: 타이머 화면(출발 완료 단계)에서는 메인으로 이동할 수 없다. 시스템 뒤로가기 버튼과 스와이프 제스처 모두 비활성이다.
- [Must] FR-7: 진행 중에는 체크포인트 주기마다 저장한다. 앱이 종료된 뒤 다시 실행하면 메인으로 가고(진행 여정 안내), 진행 여정은 마지막 저장 진도의 일시정지 상태로 복원된다. 종료돼 있던 시간은 더하지 않는다. 메인에서 이어갈지·새 여정을 갈지 사용자가 고르는 화면은 W07이다.
- [Must] FR-8: 0초에 도달하면 진도를 총 시간으로 저장하고 멈춘 뒤 임시 도착 상태를 보여준다. 도착 안내·하차·완료 기록은 W09다.
- [Must] FR-9: '시작' 뒤에는 승차권·승차 태그로 다시 갈 수 없다.
- [Must] FR-10: 저장에 실패하면 BR-7을 따른다.
- [Must] FR-11: 저장 형식을 버전 4로 올리고, 버전 3을 읽을 수 있게 한다.
- [Should] FR-12: 접근성(낭독·큰 글씨·동작 줄이기)을 지원한다.

### 비즈니스 규칙
- BR-1: 진도는 앱 프로세스가 살아 있고 일시정지가 아닌 동안 흐른 초다(포그라운드·비활성·백그라운드 포함, 시스템 잠자기 포함). 단조 시계(ContinuousClock 계열)로 재므로 기기 벽시계를 바꿔도 영향받지 않는다. 프로세스가 종료된 동안의 시간은 포함하지 않는다.
- BR-2: 분은 1~360, 경과는 0 ≤ elapsed ≤ 분×60이다.
- BR-3: 카탈로그에 없는 정류장·버스 id는 손상으로 본다. 읽을 때는 그 여정만 버리고, 쓸 때는 거부한다.
- BR-4: 손상 여정은 지금처럼 버린다. 백업·안내는 없다(사용자 결정).
- BR-5: 체크포인트 주기는 진행 중 약 10초다. 일시정지·재개·백그라운드 진입·도착 때는 주기와 상관없이 즉시 저장한다. 앱이 포그라운드에서 강제 종료되면 손실은 최대 약 10초다(틱 지연 포함 ≤ 11초 허용).
- BR-6: 출발 완료 단계에서는 승차권 열기·승차 태그 열기·승차 저장을 모두 거부한다. 출발 대기 단계에서는 덮어쓰기를 유지한다(사용자 결정).
- BR-7: 사용자 전환(일시정지·재개·시작)의 저장이 실패하면 전환하지 않고 "저장하지 못했어요. 다시 눌러주세요."를 보여준다. 주기 체크포인트 저장이 실패하면 **타이머를 일시정지**(메모리 진도 유지)하고 `journey.timer.saveWarning`("진도를 저장하지 못해 멈췄어요. 재개를 눌러주세요.")을 보여준다. 재개를 누르면 그 시점 진도로 저장을 재시도해 성공 시 경고를 지우고 진행, 실패 시 일시정지를 유지한다(사용자 결정). 백그라운드·이탈 저장 실패는 이미 일시정지이므로 경고만 남기고 재개 시 재시도한다.
- BR-8: 0초 도달 임시 상태는 다음과 같다.
  - "0 min"과 `journey.arrived`를 보여주고 일시정지/재개를 숨긴다. 진도는 분×60이다.
  - 별도 단계 값은 두지 않고 "진도 = 총 시간"을 도착으로 본다.
  - 재실행해도 이 상태가 유지되고 시간은 더 흐르지 않는다.
- BR-9: currentVersion은 4이고 새 필수 항목은 `paused`다.
  - v3 출발 대기는 출발 대기로 읽는다.
  - v3 출발 완료는 일시정지 + 저장된 진도로 읽는다.
  - 다시 저장하면 v4로 기록한다.
- BR-10: 어떤 경로도 완료 기록을 만들지 않는다.
- BR-11: 일시정지·재개를 연타해도 전환은 한 번만 반영한다.

### 품질 기대
- QE-1: VoiceOver에서는 화면에 들어올 때 "남은 시간 N분"을 읽는다. 시간이 바뀔 때마다 자동으로 낭독하지는 않는다.
- QE-2: 버튼이 현재 상태를 낭독한다. 큰 글씨에서도 잘리지 않고 누를 수 있다.
- QE-3: 동작 줄이기에서도 기능·시간이 같다.

### 수용 기준
(시간 경과는 모두 주입 시계로 검증한다.)
- AC-1: '시작'이 타이머를 시작한다 — Given 25분 여정, 출발 대기 / When '시작' / Then `journey.placeholder`는 없고 `journey.timer.remaining`이 "25 min"이다. 저장값은 출발 완료·paused=false·경과 0이다.
- AC-2: 분 표기와 올림 — Given 1500초 진행 중 / When 0·1·60·61·1499·1500초 경과 / Then 25·25·24·24·1·0 "min"이고 시·초 표기는 없다.
- AC-3: 전체 진행 — Given 360분 / When 21600초 경과 / Then 경과 21600이 저장되고 이후에도 넘지 않는다.
- AC-4: 일시정지 — Given 경과 90 / When 일시정지 후 300초 / Then 저장값은 90·paused이고 "24 min"이다. `journey.timer.resume`만 노출된다.
- AC-5: 재개 — Given AC-4 / When 재개 후 60초 / Then 저장값은 150·paused=false이고 "23 min"이다.
- AC-6: 연타 방어 — Given 진행 중 / When 일시정지 2연타, 재개 2연타 / Then 저장 쓰기는 2회다. 경과는 전환 사이에 흐른 시간만큼만 는다.
- AC-7: 백그라운드에서도 진행 — Given 25분 경과 100 진행 중 / When 백그라운드 진입 후 시계 600초 진행 뒤 복귀 / Then 진입 시 (100, paused=false)가 저장되고, 복귀 후 상태는 진행 중·경과 700·"14 min"이며 일시정지 버튼(`journey.timer.pause`)이 노출된다. 비활성(inactive) 전이만으로는 상태·저장이 바뀌지 않는다.
- AC-8: 백그라운드 중 도착 — Given 25분 경과 1400 진행 중 / When 백그라운드 진입 후 시계 600초 진행 뒤 복귀 / Then `journey.arrived`가 노출되고 저장 경과는 1500(1회), 일시정지/재개 버튼은 없다. 일시정지 중이었다면 백그라운드 왕복 후에도 저장값·상태가 그대로다.
- AC-9: 메인 이동 불가 — Given 타이머 화면(진행 중 또는 일시정지 또는 도착) / When 화면을 확인하고 스와이프 뒤로가기를 시도한다 / Then 내비게이션 뒤로가기 버튼이 노출되지 않고, 스와이프 뒤에도 `screen.journey`가 그대로이며 path가 바뀌지 않는다.
- AC-10: 주기 체크포인트 — Given 경과 0 / When 9초, 그다음 1초 / Then 저장된 경과는 0, 그다음 10이다.
- AC-11: 종료 후 재실행 — Given 진행 중 마지막 체크포인트 120 이후 5초 더 진행(미저장) / When 앱을 종료하고 시계 3600초 뒤 재실행 / Then 메인(`main.activeJourney`)으로 시작하고, 진행 여정은 경과 120·paused로 복원된다(종료 중 시간 미가산).
- AC-12: 0초 도달 — Given 남은 60초 / When 60초 / Then "0 min"과 `journey.arrived`가 노출되고 pause·resume은 없다. 경과는 분×60이고 기록은 늘지 않는다. 이후 시간이 흘러도 변하지 않는다.
- AC-13: 도착 상태 복원 — When 재실행 / Then 경과는 분×60이고 기록은 0건이다. 타이머 화면은 `journey.arrived`를 보여준다.
- AC-14: 도착 중복 없음 — When 1초 미만 남았을 때 시계 진행·백그라운드 진입·틱이 겹친다 / Then 도착 저장은 1회이고 경과는 분×60을 넘지 않는다. 도착 상태에서는 재개·재시작 수단이 없다.
- AC-15: 전환 저장 실패 — Given 다음 저장 실패 / When 일시정지 / Then pause가 계속 노출되고 실패 안내가 나온다. 저장값은 이전과 같다. 저장이 성공하게 바꾼 뒤 다시 누르면 일시정지된다.
- AC-16: 체크포인트 저장 실패 — Given 경과 0 진행 중·다음 저장 실패 / When 10초 / Then 일시정지로 바뀌고(`journey.timer.resume` 노출) `journey.timer.saveWarning`이 노출되며, 시계를 더 흘려도 남은 시간이 그대로다. 저장을 성공으로 바꾸고 재개하면 경과 10·paused=false가 저장되고 경고가 사라진다. 재개 저장도 실패하면 일시정지·경고가 유지된다.
- AC-17: '시작' 저장 실패 — Then 타이머 화면으로 넘어가지 않고 `journey.saveFailure`가 노출된다. 저장값은 출발 대기·0이다.
- AC-18: 재승차 차단 — Given 출발 완료 여정과 남은 확정값 / When 승차권 열기·승차 태그 열기·승차 저장 / Then 셋 다 거부되고 여정의 id·경과·paused가 그대로다.
- AC-19: '시작' 전 재승차 — Given 출발 대기 / When 새 승차 저장 / Then 새 id 1건으로 교체된다.
- AC-20: 분 상한 — 0·1·360·361 / Then 0·361은 쓰기 거부, 읽기에서 여정만 버림이다. 1·360은 허용한다.
- AC-21: 경과 상한(25분) — -1·0·1500·1501 / Then -1·1501은 거부·버림이고 0·1500은 허용한다.
- AC-22: 카탈로그 대조 — 출발·도착·버스 id가 각각 없음 / Then 쓰기를 거부한다. 읽을 때는 여정만 버리고 카드·기록은 유지한다. 백업·안내는 없다.
- AC-23: v4 왕복 — paused·경과 300을 저장한 뒤 읽기 / Then 버전 4이고 값이 같다.
- AC-24: v3 출발 완료 읽기 — Then 여정이 유지되고 paused·0으로 읽힌다. 다시 저장하면 버전 4다.
- AC-25: v3 출발 대기 읽기 — Then 출발 대기가 유지되고 여행 화면에 `journey.start`가 보인다.
- AC-26: v3에 새 검증 적용 — 분 361 또는 카탈로그 밖 id / Then 여정만 버리고 카드·기록은 유지한다.
- AC-27: 낭독 값 — 경과 90 / Then `journey.timer.remaining`의 접근성 값은 "남은 시간 24분"이고 보이는 텍스트는 "24 min"이다. 0초에서는 "남은 시간 0분"이다.
- AC-28: 버튼 낭독 — Then 라벨은 진행 중 "일시정지", 일시정지 중 "재개"다. 전환할 때 "일시정지됨"·"재개됨"을 1회 알린다. 60초 진행 중 알림은 0개다.
- AC-29: 큰 글씨 — 최대 접근성 크기 / Then remaining과 pause/resume이 스크롤 없이 노출되고 누를 수 있다(44pt 이상).
- AC-30: 동작 줄이기 — Then AC-2·4·5 결과가 꺼졌을 때와 같다.
- AC-31: 완료 기록 없음 — 모든 경로에서 기록 수가 그대로다.
- AC-32: 기기 시계 변경 — 벽시계 ±1시간, 단조 시계 60초 / Then 경과는 +60이다.

- 종료 후 재실행 시 "이어가기/새 여정" 선택: W07.
지도(W06), 포기·메인 수동 재개·정리 확인(W07), 도착 안내·하차·완료 기록(W09), 로컬 알림·백그라운드 실행·잠금 화면, 실기기 QA(W14), 소리 일시정지 연동.

### 가정
- 분 하한은 현행(0 초과)을 유지한다.
- 백그라운드에서 돌아와도 자동 재개하지 않는다.
- "진도가 생김"은 출발 완료 단계를 뜻한다.
- 재실행 뒤 이 화면으로 돌아오는 경로는 W07이다.

### 사용자 결정 (설계 단계, 2026-10-15)
- 백그라운드·비활성에서도 진행(보조 도구). 앱 종료는 여정 끊김 → 재실행 시 메인, 일시정지 복원, 선택 UI는 W07.
- 타이머 화면에서 메인 이동 불가(뒤로가기·스와이프 차단).
- 도착(0분) 뒤에는 다시 시작 불가. 도착 저장 실패는 도착 화면 + `journey.timer.saveWarning`, 백그라운드 진입·재진입 때 재시도.
- 낭독: 라벨 "타이머" + 값 "남은 시간 N분".
- 도착 저장 paused=true.
- Live Activity는 별도 작업.
