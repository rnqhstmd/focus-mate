확인 질문과 선택을 기록한다. 고른 것뿐 아니라 버린 선택지도 남으므로 왜 그렇게 정했는지가 추적된다.

## 2026-10-15 19:14 · 도착지 규칙

**Q.** 1/5 — 실제 노선은 정류장 사이 시간이 제각각이라, 고른 시간(예: 25분)에 딱 맞는 정류장이 없을 수 있습니다. 도착지를 어떻게 정할까요? (타이머는 항상 고른 시간 그대로)

선택지:

- 가장 가까운 정류장+시간 맞춤 (Recommended) — ±3분 안에서 가장 가까운 정류장을 도착지로. 구간 시간을 살짝 늘리거나 줄여 고른 시간에 정확히 도착. 타이머와 지도 버스가 항상 맞음
- 가장 가까운 정류장, 시간 안 맞춤 — 타이머가 끝날 때 지도 버스가 도착지 앞이나 뒤에 있을 수 있음
- 더 엄격히(±1분) — 정확하지만 '맞는 버스가 없어요'가 자주 나옴
**→** (직접 입력) 엄격하게 해도 돼 왜냐면 정류장마다 버스 여러대 올거고 노선도 여러개 있을거니까 웬만하면 있을듯 일단 진행

**A.** 엄격하게 해도 돼 왜냐면 정류장마다 버스 여러대 올거고 노선도 여러개 있을거니까 웬만하면 있을듯 일단 진행

## 2026-10-15 19:16 · 방면 표시

**Q.** 3/5 — 이름이 같은 정류장(길 양쪽 등)을 검색 결과에서 어떻게 구분할까요? 5자리 정류장 번호는 항상 함께 보입니다.

선택지:

**→** 다음 정류장 방면 (Recommended) — 지금처럼 '○○ 방면'. 가장 많은 노선이 향하는 다음 정류장 기준
- 종점 방면 — '○○행'처럼 멀리 보여 방향은 분명하지만 노선마다 달라 대표값이 애매
- 번호+지나는 버스 목록 — 방면 없이 정류장 번호와 버스 번호들만. 정확하지만 글이 길어짐

**A.** 다음 정류장 방면 (Recommended)

## 2026-10-15 19:17 · 기존 저장

**Q.** 4/5 — 예시 데이터('성수역' 등)로 저장된 현재 정류장과 진행 중 여정은 어떻게 할까요? 카드와 완료 기록은 영향 없고, 아직 배포 전이라 개발·테스트 기기만 해당됩니다.

- 같은 이름 실제 정류장으로 자동 이전 — 수고는 없지만 길 반대편으로 잘못 옮겨질 수 있음

**A.** 비우고 다시 고르기 (Recommended)

## 2026-10-15 19:17 · 용량·속도

**Q.** 5/5 — 앱 용량·속도 한도를 어떻게 둘까요?

선택지:

**→** 10MB·검색 0.3초 (Recommended) — 데이터 10MB 이하, 검색 0.3초·후보 0.2초 이내, 앱 시작 지연 1초 이하. 사용자가 지연을 거의 못 느끼는 수준
- 더 엄격히(5MB·0.15초) — 더 점해하지만 구현 선택지가 줄어 일정이 늘 수 있음

**A.** 10MB·검색 0.3초 (Recommended)
