## 배경
앱의 버스·정류장 데이터는 예시(버스 3대, 가상 순환 정류장 9개)다. 사용자 결정(2026-10-15)으로 서울 전체 실제 데이터(정류장·노선 순서·버스·정류장 사이 시간)를 앱에 번들로 넣는다. GPS·실시간 API는 쓰지 않는다. 원천은 서울 열린데이터광장 OA-1095(서울시버스노선별정류소정보)와 OA-15066(서울시버스노선기본정보) xlsx이며 둘 다 공공누리 제1유형(서울특별시)이다. 정류장 사이 시간은 공개 자료가 없어 노선 운행시간을 정류장 사이 직선거리 비율로 나눠 계산한다.

## 요구사항 (이번 PR 범위 = 설계 구현 순서 1~11단계)
W16은 다른 세션의 W09(하차)와 정류장 id·도착지 규칙이 겹쳐 둘로 나눴다. 이번 PR은 W09와 겹치지 않는 부분만 담는다.
- 변환 스크립트 `scripts/build_route_data.py`: xlsx 두 개 → 줄 단위 JSON(노선 712·정류장 12,758·1.69MB). 가상 지점 제거, 한강·관광 노선 제외, 운행시간 비례 구간 시간(최소 30초, 합=운행시간), 운행시간이 비었거나 비현실적(직선 3km/h 미만, 예: 541번 1190분)이면 유형별 대체 속도. 실패 시 기존 산출 보존, 요약·SHA-256 출력.
- 앱 계산 모듈(새 파일만, 기존 화면 미연결): `RouteCatalog`·`RouteCatalogLoader`(번호 자연 정렬, 방면), `StationSearch`(번호·이름 단계 검색, 50건), `RouteLeg`(±1분 도착지, 회차, 고른 시간에 맞춘 비례 조정), `RouteCandidates`(차이·번호 순 20건).
- 기존 화면·저장(v5)·지도·포기 규칙 교체와 번들 포함은 W09 머지 후 W16b에서 한다. 산출 JSON은 아직 번들에 넣지 않는다(`scripts/data/out/`, gitignore).
- 실데이터 후보 0건 비율: 무작위 정류장 9.0%, 노선 1개 정류장(전체의 44%)은 16%. ±1분 규칙 유지 여부는 W16b 전에 결정.
