# 시스템 표면 후속 계획

2026-10-16 승인된 문서 계획. 앱 소스 변경·테스트 실행·실기기 렌더링 완료를 의미하지 않는다. 공식 작업 상태·의존은 [전체 계획](../plan.md), 요구사항 상태는 journey/records 원장을 따른다.

## 사용자 결정과 범위

사용자는 최초 네 작업 제안 저장을 "ㄱㄱㄱ"로 승인한 뒤 **"근데 좀 묶어서 진행해도 되지않나?"**라고 요청했다. 이 후속 결정에 따라 신규 작업을 W17·W18 두 개로 통합한다. W19·W20은 공식 작업으로 만들지 않는다. 집중 유도와 분석은 사용자가 갤러리에서 선택하는 두 계열이지만 구현·통합은 W18 한 브랜치/PR에서 진행한다.

- 1차 홈 위젯: 두 계열 각각 소형·중형. large·잠금 accessory·StandBy 전용 위젯은 약속하지 않는다.
- 차콜·오프화이트, 정보 중심. 풍선 같은 곡선 장식·앱 아이콘 반복은 제외한다.
- 확장 Island: 가로 시간 눈금과 버스 진행 위치. compact/minimal은 시간·상태 중심이다.
- Live Activity 정상 완료는 기존 즉시 종료를 유지한다. 완료 카드 체류는 범위 밖이다.
- 메모·할 일 원문은 위젯 공유 데이터에 넣지 않는다. 직접 시작·일시정지·포기 제어는 위젯에 추가하지 않는다.
- 담당 PM/PO·개발 리드·사용자 규모는 기존 ❓를 보존한다. App Group 식별자·서명 담당자도 설정 전까지 ❓이며 계정/팀을 추정하지 않는다.

## W09b 보강 — 기존 분석 작업

선행 W09. 요구사항 records FR-6(분석)·FR-7. 기존 분석 화면·인사이트 범위는 유지하며 같은 완료 기록·기간·날짜 정책을 받는 순수 집계를 이 작업에 포함한다. 위젯을 위한 별도 집계 작업은 만들지 않는다.

작업 AC 초안(착수 PRD에서 원장과 연결, 아직 실행하지 않음):

1. 주/월·태그 필터와 기존 FR-6의 분석/인사이트를 앱에서 제공하고 예시와 실제 기록을 분리한다.
2. 같은 완료 기록·기간·달력/시간대 입력이면 앱과 위젯 소비용 집계가 동일한 합계·횟수·정확히 7일의 추이·태그별 시간을 반환한다. 위젯에서 재계산하지 않는다.
3. 진행·포기·중복·예시를 제외하고 빈 기간은 정상적인 0으로 반환한다. 저장된 완료 당시 날짜와 날짜 경계·주/월 전환을 고정 입력으로 검증한다.
4. 태그 상위 항목/기타의 합은 전체와 일치하고 오래된 태그·없는 필터는 정의된 기본 분석으로 돌아온다. 화면 큰 글자·VoiceOver 경로를 점검하고 실제 청취 증거는 별도로 남긴다.

소유: records 순수 집계·분석 화면/테스트. App Group 스키마·파일 입출력·위젯 Provider/뷰는 소유하지 않는다.

## W17 — Live Activity 디자인·눈금 타임라인

도메인 journey, 요구사항 FR-14, 선행 W15. W15 완료 이력·타이머 소유권·백그라운드 시간 유지·알림 기반 갱신을 보존한다.

작업 AC 초안:

1. 확장 Island와 잠금 화면에 노선·목적지·남은 집중 시간을 차콜·오프화이트 정보 계층으로 표시한다. compact는 짧은 시간/상태, minimal은 상태 심볼로 구성하며 running/paused/stale를 구분한다.
2. 총 시간·시간 기준점·일시정지 남은 초를 사용해 `clamp(1 - remaining / total, 0…1)`의 시간 눈금/버스 위치를 표시한다. 총 30분에서 18:42 잔여는 약 37.67%, 02:15는 92.5%, paused는 위치 고정, resume는 정지 누적을 제외한다. 잘못된 총 시간은 안전한 시간/상태 표시로 대체한다.
3. GPS·실제 버스 ETA·남은 정류장으로 오인시키지 않는다. 매초 ActivityKit update를 보내지 않고 시스템 날짜 기반 표시를 유지한다. 버스 위치의 실제 갱신 제약을 확인하고 연속 이동을 보장하지 않는다. 정상 완료·취소·정리의 기존 종료 계약을 보존한다.
4. 0:05·9:59·99:59·120:00·360:00, 긴 목적지/노선, paused/stale를 미리보기에서 확인하고 카메라 여백·잘림·큰 글자·동작 줄이기·한 번만 읽히는 상태/시간을 점검한다. 실제 Island/잠금 화면·VoiceOver 청취는 별도 실기기 증거로 남기며 미확보 시 유예를 명시한다.

파일 경계: `JourneyActivityAttributes`·`JourneyActivityDisplay`·Live Activity 정책/동기화 및 `JourneyLiveActivityWidget`과 관련 테스트. records 집계·홈 위젯 Provider는 변경하지 않는다. 공유 계약 확장 시 기존 활동 정리/재시작 호환성도 설계한다.

## W18 — 홈 위젯 전체 기능

도메인 통합. 요구사항 journey FR-15·NFR-3, records FR-8·NFR-2. 선행 W07·W08·W09b. W07은 여정 안전 진입, W08은 완료 저장, W09b는 같은 분석 결과를 공급한다. 현재 W09b가 대기이므로 W18 구현·통합 착수 가능으로 표시하지 않는다.

한 브랜치/PR 내부 순서: **공유 스냅샷·갱신·안전 진입 기반 → 집중 유도 소형/중형 → 분석 소형/중형**. 별도 W 번호·PR 승인 게이트로 쪼개지 않는다. W09b 이전에는 시안·스키마 검토만 병행할 수 있다.

작업 AC 초안:

1. 앱 원본 저장소를 권위로 유지하고 App Group에 버전·생성/기준 시각을 갖는 최소 여정 상태/집계 읽기 모델만 원자적으로 게시한다. 메모·할 일 원문은 제외한다. 읽기/쓰기 실패·손상·지원하지 않는 버전은 접근 불가로 구분하고 유효하지만 오래된 값과 정상 빈 기록을 0으로 혼동하지 않는다. 공유 오류는 앱 원본을 변경하지 않는다.
2. 집중 유도 위젯은 최초 설정·새 여정 준비·진행·일시정지·도착 상태를 안내한다. 탭은 최신 앱 상태를 재검증해 기존 설정/이어가기/새 여정 확인/하차로 연결한다. 진행 여정을 덮어쓰거나 확인을 생략하지 않는다. 직접 시작 제어는 없으며 유효하지 않거나 오래된 링크는 안전한 기본 화면으로 보낸다.
3. 분석 위젯은 W09b 결과의 오늘/주간 시간·횟수, 정확히 7일의 추이와 태그별 시간을 크기에 맞춰 표시한다. 앱의 같은 기간·날짜 정책 결과와 값이 일치하고 해당 분석 맥락으로 진입한다. 없는 기간/태그 링크는 기본 분석으로 복귀한다. 공유 계층에서 집계를 중복 계산하지 않는다.
4. 앱 저장 성공 뒤에만 새 스냅샷 게시/reload를 요청하고 저장 실패에서는 미확정 데이터를 게시하지 않는다. 날짜 경계 timeline과 상태/완료 기록 변경 후 갱신을 연결하며 매초 reload하지 않는다. 갤러리에서 집중 유도/분석 두 계열을 선택하고 각 소형·중형을 추가할 수 있다. OS 갱신 요청을 즉시 표시 보장으로 설명하지 않는다.
5. 두 계열×두 크기의 정상·빈 기록·오래된 데이터·접근 불가를 미리보기/스냅샷으로 점검한다. 긴 한국어·큰 글자·색에 의존하지 않는 그래프/태그·VoiceOver 요약·동작 줄이기를 확인한다. 기기에서 실제 갤러리 등록·앱 진입·업데이트·접근성 낭독을 검증하고 자동 테스트/미리보기와 증거를 구분한다. 서명/실기기 미확보 항목은 완료로 주장하지 않는다.

파일 경계: 새로운 공유 snapshot/codec/bridge, 앱 저장 성공 후 publisher, 안전한 진입 어댑터, 홈 위젯 Provider/뷰/테스트와 App Group entitlement/등록. 원본 저장 스키마를 위젯 때문에 별도 권위로 복제하지 않는다. 정확한 파일·공용 API 이름은 착수 설계에서 확정한다.

## 실행·통합 경계

W17과 W09b는 각 선행이 완료돼 지금 병렬 착수할 수 있다. Live Activity 표시 파일과 records 집계/분석 파일을 나눠 소유한다. W18은 W09b 완료 후 착수한다. W17·W18의 공유 타입·`FocusMateWidgetsBundle`·프로젝트 등록 변경은 담당자를 정해 순차 통합한다. 두 위젯 계열은 같은 번들/Provider 기반을 쓰므로 별도 세션에서 무조건 안전하게 병렬 편집할 수 있다고 보지 않는다.

전체 계획의 W07 선머지 → W09, W16·W09 동시 진행 금지 운영 규칙은 유지한다. 기존 완료/진행 행·기존 원장 ID/AC/상태/PR은 보존하고 W16의 기존 상태 차이는 이번에 자동 동기화하지 않는다. 기존 W14 범위·의존을 바꾸지 않으며 새 기능의 검증은 각 AC에서 별도로 수행한다.
