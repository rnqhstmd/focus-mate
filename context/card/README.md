# 카드 도메인

> 구성 확정 / 담당·규모 미확인 · 2026-10-12. 코드·현재 문서로 추출한 초안이며 사용자/담당/성공 지표는 미확인입니다.

집중동행카드의 1회 발급·번호·외형·사진 꾸미기와 공통 표시를 관리하는 경계.

## 배경

같은 카드가 발급·승차·하차·마이페이지에서 이어 보이고, 사용자 외형 변경이 유지되도록 한다. 현재 웹은 발급 슬롯 모션·지원 기기 햅틱·ID 저장, 배경색과 최대 6장 JPG/PNG/WebP(파일당 8MB까지) 사진의 위치/크기/겹침·삭제·되돌리기·저장을 구현한다.

## 안 하면 어떻게 되는가

번호 불일치, 꾸미기 저장 손실, 이미지가 카드 경계를 벗어나거나 편집 취소가 저장되는 오류가 생길 수 있다. 예상 사용자 수·누적 사진 저장량·네이티브 저장 정책은 ❓.

## 사용자와 규모

대상 초안: 혼자 여행 시간을 정하고 독서·작업·쉼 등 할 일 하나를 담는 사용자. 검증된 사용자 수 ❓, 사용 빈도 ❓, 월 여정/데이터 규모 ❓.

## 성공 기준

초안 기준: 같은 발급 ID 유지, 카드 경계 clipping, 고정 칩, 저장 전 취소 확인. 네이티브 저장 용량·성능 목표는 ❓.

## 현재 상태

웹 프로토타입의 현재 동작을 정리했습니다. 도메인 경계는 확인됐고 담당자는 ❓입니다. iOS는 W01에서 카드 1회 발급·카드 ID 저장·공통 카드 뷰를 구현했습니다. 승하차 카드·LCD 표시는 W04(Phase 2), 꾸미기·마이페이지는 Phase 5 대상입니다.

journey는 카드 접촉 성공 상태를 소유한다. card는 ID·외형을 공급하며 여행 완료 여부나 기록 합계를 결정하지 않는다.
