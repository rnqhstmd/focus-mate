# 카드 도메인

> 구성 확정 / 담당·규모 미확인 · 2026-10-15. 코드·현재 문서로 확인한 상태이며 사용자/담당/성공 지표는 미확인입니다.

집중동행카드의 1회 발급·번호·외형·사진 꾸미기와 공통 표시를 관리하는 경계.

## 배경

같은 카드가 발급·승차·하차·마이페이지에서 이어 보이고, 사용자 외형 변경이 유지되도록 한다. 현재 웹은 발급 슬롯 모션·지원 기기 햅틱·ID 저장, 배경색과 최대 6장 JPG/PNG/WebP(파일당 8MB까지) 사진의 위치/크기/겹침·삭제·되돌리기·저장을 구현한다.

## 안 하면 어떻게 되는가

번호 불일치, 꾸미기 저장 손실, 이미지가 카드 경계를 벗어나거나 편집 취소가 저장되는 오류가 생길 수 있다. 예상 사용자 수·누적 사진 저장량은 ❓. iOS 사진 정책은 입력 장당 8MiB, 보존 장당 1MiB·전체 6MiB·최대 6장이다.

## 사용자와 규모

대상 초안: 혼자 여행 시간을 정하고 독서·작업·쉼 등 할 일 하나를 담는 사용자. 검증된 사용자 수 ❓, 사용 빈도 ❓, 월 여정/데이터 규모 ❓.

## 성공 기준

초안 기준: 같은 발급 ID 유지, 카드 경계 clipping, 고정 칩, 저장 전 취소 확인. iOS는 초안과 저장 외형을 분리하고 사진·외형을 함께 저장한다. 보존 용량은 위 사진 정책을 따른다. 사용자 규모에 따른 장기 성능 목표는 ❓.

## 현재 상태

도메인 경계는 확인됐고 담당자는 ❓입니다. 웹 프로토타입과 iOS 구현은 별도 범위입니다. iOS는 W01의 1회 카드 발급·ID 저장·공통 카드 뷰, W11의 마이페이지·완료 여정 수와 함께한 시간 표시, W10의 색·사진 꾸미기와 로컬 복원을 구현했습니다([#15](https://github.com/rnqhstmd/focus-mate/pull/15); PR 생성 완료, main 병합 전). 메인과 마이페이지에서 같은 저장 외형으로 편집을 시작하고 마이페이지는 공통 카드 외형을 읽습니다. 카드·처리 사진은 버전 3 로컬 스냅샷에 함께 저장하며 버전 1·2는 기본 외형으로 읽습니다. 실제 PhotosPicker·색·배치 편집·저장/재실행과 소유 Photos 원본 삭제 후 처리 사진 보존을 확인했습니다. 승하차 카드·LCD는 W04 대상이며 실제 iPhone 검증은 W14에 남아 있습니다. [카드 구현 추적](status.md)과 [W10 최종 검증](../../.dev/codex-feat-card-customization/reports/final-verification.md)에 실행 범위와 미완료 검증을 구분했습니다.

journey는 카드 접촉 성공 상태를 소유한다. card는 ID·외형을 공급하며 여행 완료 여부나 기록 합계를 결정하지 않는다.
