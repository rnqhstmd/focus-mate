# 여정 용어 사전

> 구성 확정 / 담당·규모 미확인. 코드의 이름은 현재 구현 식별자이며 향후 네이티브 명칭 확정이 아닙니다.

| 용어 | 설명 |
|---|---|
| 여정 선택 | 고른 분에 맞는 노선·도착지 조합(구간 시간 합이 고른 분 ±1분). 시간을 바꾸면 선택 해제 |
| 준비 허브 | 태그·비어 있지 않은 할 일·선택 소리를 확정하는 화면 |
| 승차 인식 | 접촉 성공에서 진행 여정 저장. 인식 1400ms + 일반 페이드 450ms 후 여행 |
| activeJourney | 진행 여정 스냅샷: 출발·도착 정류장 id와 승차 당시 이름, 노선 id·버스 번호·유형, 시간·진도·할 일·태그·소리(저장 v5) |
| checkpoint | 진도/백그라운드/중단 상태 로컬 저장 |
| 하차 접촉 | 성공에서 records 완료 기록과 다음 출발지 저장 |
| 한 바퀴 미리보기 | 12초 누적거리 등속 이동. 실제 여행 진도와 독립 |
| pendingTag / selectedTag | 편집 중/확정 태그 상태 |
| draftTask / taskText | 할 일 초안과 출발에 사용하는 확정값 |
| pendingSound / selectedSound | 편집 중/확정 소리 선택 |
| audioGeneration | 늦은 decode 재생을 막는 재생 세대 |
| 도달 정류장 | 포기·새 여정 때 노선 구간을 다시 계산해 누적 구간 초가 저장된 경과 이하인 마지막 정류장. 노선이 데이터에서 사라졌으면 출발 정류장, 출발 정류장도 없으면 정류장을 다시 고른다. 정류장 데이터를 읽는 중에는 정하지 않고 거절한다 |
| 이어가기 | 메인 카드의 '이전 여정 이어가기'. 저장된 경과로 일시정지를 풀고 1회 저장한 뒤 타이머를 바로 흐르는 상태로 연다(출발 대기 여정은 출발 안내부터, 도착 여정은 이어가기 없음) |
| 포기 | 일시정지 중에만 가능한 여정 그만두기. 확인 뒤 도달 정류장 저장·여정 삭제를 한 번에 하고 완료 기록은 만들지 않는다 |
| 새 여정 시작 | 진행 여정이 있을 때의 메인 시작 버튼. 확인 뒤 도달 정류장을 저장하고 여정을 지운 뒤 시간 선택으로 간다. 도착한 여정은 하차로만 끝낸다(W09) |
| 방면 | 정류장을 지나는 노선이 가장 많이 향하는 다음 정류장 이름 + " 방면". 검색 결과·메인·시간 선택에 보인다 |
| 정류장 데이터 | 서울 열린데이터광장 공공 데이터를 변환해 앱에 넣은 정류장·노선·구간 시간(`RouteCatalog`). 앱 시작 뒤 백그라운드에서 한 번 읽고 네트워크를 쓰지 않는다 |
| 시간 눈금 타임라인 | 계획 W17. 집중 세션의 총 시간 대비 진행률을 가로 눈금과 버스 위치로 표시한다. 정류장 간격·GPS·버스 ETA가 아니다 |
| 집중 유도 위젯 | 계획 W18. 소형·중형에서 현재 준비/여정 상태에 맞는 안내와 안전한 앱 진입을 제공한다. 위젯에서 여정을 직접 시작하지 않는다 |
| 위젯 안전 진입 | 계획 W18. 링크 입력보다 앱의 최신 저장 상태를 우선해 최초 설정·이어가기·새 여정 확인·하차 경로를 지키는 진입 계약 |
