# 기록 도메인

> 구성 확정 / 담당·규모 미확인 · 2026-10-16. 기존 구현과 승인된 후속 계획을 구분하며 사용자/담당/성공 지표는 미확인입니다.

완료한 여정·선택 메모·연간 잔디와 기간/태그별 분석을 관리하는 경계.

## 배경

사용자가 완료한 시간과 한 일을 다시 확인하고 날짜·태그별로 돌아볼 수 있도록 한다. 현재 웹은 하차 성공 완료 기록·200자 선택 메모, 날짜별 최신순 10개씩 보기, 연간 시간 잔디, 주간/월간·태그 필터 분석을 구현한다.

## 안 하면 어떻게 되는가

진행/포기 여정이 완료 통계에 섞이거나 예시 기록이 실제 기록을 덮어쓸 수 있다. 예상 기록 수·보관 기간은 ❓.

## 사용자와 규모

대상 초안: 혼자 여행 시간을 정하고 독서·작업·쉼 등 할 일 하나를 담는 사용자. 검증된 사용자 수 ❓, 사용 빈도 ❓, 월 여정/데이터 규모 ❓.

## 성공 기준

초안 기준: 하차 성공만 완료 생성, 포기 제외, 예시 분리, 메모와 여행 연결 유지. 보관/삭제/내보내기 정책과 규모 목표는 ❓.

## 현재 상태

네이티브에는 W08 완료·메모 저장, W09a 하차 연동·요약·기록·잔디가 구현됐습니다. 주/월·태그·인사이트 분석은 기존 W09b 대기이며, 앱과 위젯이 같은 결과를 사용하는 순수 집계를 이 작업에 보강했습니다. 분석형 소형·중형 홈 위젯은 W09b 이후 W18에서 공유 기반·집중 유도형과 함께 구현합니다. 홈 위젯 코드와 App Group 공유 기반은 아직 없습니다.

위젯은 앱 원본 저장소를 직접 변경하지 않습니다. 저장 성공 뒤 게시하는 버전 있는 최소 집계만 읽고 메모·할 일 원문은 공유하지 않습니다. 빈 기록·오래된 값·접근 불가를 구분하며 실제 렌더링·VoiceOver 검증은 구현 뒤 별도 증거가 필요합니다. [승인 계획](../../.dev/system-surfaces-plan/plan.md)에 범위·검증 기준을 기록했습니다.

journey의 하차 성공을 입력으로 받는다. 카드 외형이나 진행 타이머를 변경하지 않으며 완료 기록에 있는 태그/시간으로 분석한다.
