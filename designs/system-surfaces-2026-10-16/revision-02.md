# 02 — 분석 위젯과 눈금 타임라인

사용자 피드백: 풍선처럼 보이는 곡선 장식을 없앤다. 앱 아이콘 반복 대신 콘텐츠를 중심으로 한다. 기존 분석을 위젯으로 확장한다. 확장 Dynamic Island는 작은 버스와 가로 눈금으로 남은 여정을 표현한다.

## 분석 위젯

- 오늘 small: 저장된 완료 여행의 분 합계·횟수.
- 주간 medium: 주간 합계와 월…일 시간 막대.
- 태그 medium: 저장 당시 태그 이름과 시간, 상위 3개와 필요 시 기타 합계. 색 외에도 이름·숫자로 구별.
- 기록 large: 기록 활동 격자와 기간 합계. 이미지의 7×8 격자는 배치 예시이며 날짜별 정확한 셀 매핑·월 경계는 구현 시 명시한다.
- 아이콘, 곡선, 풍선 같은 장식 없음. 탭하면 해당 분석 기간/태그로 진입하는 연결을 후속 구현한다.
- 기존 분석 정책은 reports/analytics-and-alight-memo-2026-10-12.md 및 designs/final/animation-preview.html에 있다. 현재 네이티브 RecordsView는 기록·잔디·일합계를 제공하지만 같은 분석 집계가 네이티브 위젯에 연결되어 있지는 않다. 공유 집계 스냅샷/달력·시간대 기준/앱과 위젯 동기화가 필요하다.
- 예시 4시간20분=260분, 태그 130+80+50=260분. 실제 사용 기록으로 교체한다. 시연용 압축 시간을 실제 집중 성과로 오인하지 않도록 앱 분석의 집계 정책과 문구를 따른다.
- 빈 기록은 '첫 여정을 마치면 기록이 쌓여요'. 기록 없는 기간과 기록 접근 불가/동기화 대기를 같은 0으로 표시하지 않는다.

## 확장 Island

상단: 노선과 남은 시간. 카메라 영역 비우기.
하단: 출발 — 등간격 눈금 — 목적지, 현재 진행 지점 위 작은 버스.

- 눈금은 집중 세션 시간의 분할이다. 정류장·GPS 위치·실제 버스 ETA를 뜻하지 않는다.
- 진행률 = clamp(1 - remainingSeconds / totalSeconds, 0…1).
- 예시 총30분, 잔여18:42 → 진행37.67%; 잔여02:15 →92.5%.
- paused: 동일 위치 고정, 작은 pause 상태로 구분.
- 현재 attributes에는 totalSeconds/startDate가 없어 이 정보를 추가해야 한다. 일시정지 누적도 반영해야 하므로 startDate 하나만으로 단순 계산하지 않는다.
- 매초 ActivityKit update를 추가하지 않는다. 시스템 날짜 기반 시간/진행 표시와 위젯 확장의 렌더링 제약 안에서 위치 표시를 설계한다. 시안은 연속 이동/사용자 정의 매초 애니메이션을 보장하지 않는다. 필요하면 시스템 ProgressView를 우선하고 버스 위치의 갱신 주기를 실제 장치에서 검증한다.
- compact/minimal은 눈금 없이 시간·상태만 남겨 복잡도를 줄인다.
- 비율·한국어·카메라 여백은 생성 이미지 참고 수준이며 실제 SwiftUI 미리보기/장치에서 별도 검증한다.

## 생성

built-in image_gen으로 기존 보드를 참조해 새 이미지 두 장을 생성했다. 프롬프트는 ① 아이콘/장식을 제거한 무채색 분석 위젯 4종, ② 남은 시간·가로 눈금·진행 위치의 버스를 보여주는 running/paused/near-completion Island 보드다. 구현 소스는 변경하지 않았다.

산출물: `analytics-widgets-v2.png`, `island-timeline-v2.png`.

시각 확인 한계: 생성 이미지의 주간 medium은 토요일 축이 중복되어 8개 막대로 그려졌고, 첫 small에도 요일 글자 오자가 있다. 이는 데이터/구현 기준이 아니며 실제 구현은 월…일 정확히7일로 수정한다. 타임라인 이미지의 일시정지 심볼도 두 곳에 반복되므로 실제 화면에서는 상태 라벨 옆 한 개만 둔다. 상세 눈금 밀도와 큰 아일랜드 비율은 실제 기기 너비에 맞춰 줄인다.
