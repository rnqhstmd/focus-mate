## 진입·완료 기준

| Phase | 진입 조건 | 완료 기준 |
|---|---|---|
| 2 | Phase 1 완료. 승차 작업은 Phase 0의 **최신 승차 단말기** 확인, 준비 작업은 **태그 선택 중간 화면** 확인이 끝나야 착수 | 첫 발급부터 승차 인식까지 Simulator에서 이어짐. 미완성 준비는 승차 불가. 접촉 성공 시 진행 여정 1회 저장 |
| 3 | 승차 태그(진행 여정 생성) 완료 | 실제 선택 분 진행·일시정지·포기·메인 수동 재개. 앱 밖 시간 미가산을 종료/재실행 테스트로 확인 |
| 4 | 타이머·체크포인트 완료 | 하차 접촉 성공에서만 완료 1회 생성. 메모·잔디·분석이 같은 집계 정책을 따름 |
| 5 | 꾸미기·마이페이지는 카드 발급(Phase 2)·완료 기록(Phase 4) 이후. 접근성 설정·저장 복구는 선행 Phase와 독립적으로 착수 가능 | 꾸미기·마이페이지 저장/복원. 손상 데이터 화면에서 재시도·정리로 진행 가능 |
| 6 | Phase 2~5 완료, 서명·배포 정보 확정 | 실기기에서 큰 글자·VoiceOver·드래그·햅틱·오디오 청취·잠금/종료/복귀를 검증하고 [MVP 출시 판단 기준](MVP.md#출시-판단-기준)을 충족 |

모든 Phase에 공통으로 적용하는 완료 조건:

- 새 화면은 VoiceOver 라벨·Dynamic Type·시스템 동작 줄이기를 적용합니다(preferences FR-3). Phase 5는 설정 화면과 전체 점검을, Phase 6은 실기기 검증을 맡습니다.
- `python3 scripts/check-ios.py test`와 웹 회귀(`npm test`)가 0 failures입니다.
- 해당 원장 행의 상태와 PR 열을 갱신합니다. 웹 ✅를 iOS 완료로 옮겨 적지 않습니다.

저장 오류 복구는 Phase 5에서 정의합니다. 그 전까지 Phase 2~4가 추가하는 저장 데이터도 Phase 1과 같이 손상·미지원 시 원본을 보존하고 진행을 막습니다.

## 환경과 절차

Xcode 27.0 약관은 사용자가 동의했고 iOS 27 Simulator 실행을 확인했습니다. 작업 기준은 iOS 17 이상이며 출시 최소 버전·서명/배포 정보·담당·출시일은 미정입니다.

Phase 1은 사용자의 전체 과정 전환 요청에 따라 **PRD → 설계·테스트 가능성 검토 → RED·GREEN·REFACTOR → 요구사항·품질·보안 리뷰 → 검증·인수 → 커밋·PR**로 진행했습니다. 전체 과정은 개발 절차이며, Phase 2~6의 제품 기능을 Phase 1에 추가한다는 뜻은 아닙니다.

현재 웹의 30초 압축 시연을 네이티브 완료로 간주하지 않습니다. 네이티브는 실제 선택 시간을 사용하며, 실제 GPS·실시간 버스 API·클라우드 동기화는 MVP 후순위입니다.

현재 기능과 한계는 [현재 상태](CURRENT-STATE.md), 제품 범위는 [MVP](MVP.md)를 봅니다.
