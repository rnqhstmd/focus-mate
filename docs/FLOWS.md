# 화면과 상태 계약

기준: 2026-10-12. 제품 경로는 18개 논리 장면, 코드 회귀 장면은 21개, Pen은 성공·중단·오류를 포함한 42개 상태입니다. 숫자는 서로 같은 분류가 아닙니다. 최신 제품 화면은 [프로토타입](../designs/final/animation-preview.html)을 기준으로 합니다.

## 승하차 태그 화면 — 2026-10-13 갱신

승차·하차 태그 화면에는 단말기와 카드, 카드를 단말기로 가져가는 안내 동작만 둔다. 제목·출발/도착 정류장·단계 표기·하단 안내 문구·‘카드를 여기에’·단말기 상표·‘눌러서 태그하기’는 화면에 표시하지 않고, 안내 문구는 화면 낭독기용으로만 유지한다. 시간·버스·도착지는 승차 전에 이미 정했고, 도착 정보는 하차 전 도착 안내에서 보여준다. 승차 화면 왼쪽 위 뒤로가기 아이콘은 유지한다.

단말기는 카드와 비슷한 폭(274px)이고 태그 영역은 카드 크기에 가깝다(238×160). 카드를 끌어 태그 영역과 **30% 이상 겹치는 순간** 놓기를 기다리지 않고 인식하며 진동한다. 카드는 그 자리에 남고 작아지거나 영역 중앙으로 빨려 들어가지 않는다. 카드는 위아래로만 끌 수 있고(좌우는 최대 26px, 위로는 태그 영역 위쪽까지, 아래로는 20px) **그냥 터치해서는 태그되지 않는다**. 터치하면 카드가 위로 살짝 튀며 ‘카드를 위로 밀어 단말기에 대주세요’를 안내한다. 화면 낭독기·키보드 사용자는 Enter·Space로 태그할 수 있고, 이때 카드가 태그 영역 아래쪽 가장자리에 걸치도록 올라간다. 태그 화면은 지도 위로 서서히 나타나고 단말기(0.12초 뒤)와 카드(0.38초 뒤, 아래에서 위로)가 차례로 들어온다. 동작 줄이기에서는 생략한다. 처음 진입 시 카드가 단말기 쪽으로 두 번 올라갔다 돌아오는 안내 동작을 하며, 동작 줄이기에서는 생략한다. LCD는 Focus Mate·시각(하차는 버스 번호)과 ‘승차 준비’/‘하차 준비’만 보여준다.

## 태그·안내·승차권·준비 허브 — 2026-10-13 2차

- 태그 안내: 단말기 쪽 화살표만 두고, 카드 둘레에 점선 테두리를 깜빡여 ‘이 카드를 가져간다’를 알린다. 동작 줄이기에서는 깜빡이지 않는다.
- 태그 성공: LCD에 카드 이름(집중동행카드)과 체크만 표시한다. 카드 미리보기·카드 번호·태그 영역 체크·카드 위 체크 배지는 표시하지 않는다(실제 단말기의 태그 영역은 표시가 바뀌지 않는다). 하차 LCD도 ‘하차 완료’ 대신 카드 이름이다.
- 출발·도착 안내: 화면 전체를 어둡게 덮는 그라데이션 위에 아이콘과 문구 한 문장만 보여준다. 세 문장이 같은 자리에서 차례로 나타났다 사라지고(약 1.7초씩) 마지막 문장은 남는다. 그 뒤 출발은 **시작**, 도착은 **확인** 버튼이 나타나고 눌러야 이동이 시작되거나 하차 태그로 간다. 버스·정류장 정보는 표시하지 않는다. 동작 줄이기에서는 세 문장을 한꺼번에 보여준다.
- 승차권: 서울 25개 자치구 경계와 한강을 점으로 찍은 질감 위의 티켓 카드다. 출발/도착, 정류장/거리, 탑승/날짜, 태그/할 일을 모두 ‘라벨 위·값 아래, 왼쪽/오른쪽’ 같은 칸 구조로 둔다. 정류장 이름은 두 이름 중 긴 쪽 글자 수에 맞춰 같은 크기(28/24/20/17px)로 줄이고 최대 두 줄이다. 버스 번호 배지·브랜드 문구·여행 시간·바코드·절취선 점선은 없고 노치만 남긴다(여행 시간·버스는 화면 낭독기용으로 유지). 질감은 `scripts/generate-ticket-art.cjs`가 `scripts/data/seoul-municipalities-kostat-2013.json`(Apache-2.0, KOSTAT 2013)으로 생성한다.
- 카드: 기본 카드는 서울 점묘를 배경으로 깔고, 카드 번호는 어떤 화면에서도 카드 위에 표시하지 않는다. 배경색을 바꾸거나 사진을 넣으면 ‘Focus Mate’·카드 이름·문구가 사라지고 IC 칩과 비접촉 표시만 고정으로 남는다.
- 준비 허브: ‘태그 관리’를 없애고 태그 줄 끝의 **+**로 새 태그를 만든다. (소리·화면 구성은 아래 3차가 우선)

## 준비 허브·여행 소리 — 2026-10-13 3차

- 준비 허브는 제목 **‘무엇을 할까요?’** 하나만 둔다. ‘버스에서 할 일’ 제목, 버스 번호·시간·정류장 부제목, ‘여행 태그’·‘이번 여행에서 할 일’ 라벨, 하단 안내 문구는 화면에 표시하지 않는다(라벨·안내는 화면 낭독기용으로 유지).
- 태그는 태그 색으로 물든 알약형 칩(아이콘+이름)이다. 두 줄로 놓고 넘치면 **가로 스크롤**하며, 시트 가장자리까지 이어져 잘려 보인다. 선택한 칩은 태그 색 테두리와 진한 배경·흰 글자다. 마지막은 둥근 **+** 칩이다.
- 할 일은 라벨 없는 한 줄 입력(‘할 일 한 줄’)이고 태그를 고르면 나타난다. 입력 중 테두리는 선택한 태그 색이다.
- 소리는 하단 **[스피커 아이콘 소리이름]** 칩으로(소리 없음이면 음소거 스피커) ‘승차권 보기’ 왼쪽에 둔다. 누르면 소리 선택 시트가 열린다.
- 여행 소리는 **버스(기본값)·비 오는 버스·지하철·숲속·소리 없음**이고 각각 버스·비구름·지하철·나무·음소거 아이콘을 쓴다. 소리 선택 시트에는 설명 문구가 없다. 이전 핑크 노이즈·빗소리·버스 엔진 선택값으로 저장된 진행 여정은 버스·비 오는 버스로 바꿔 이어간다.
- 모든 소리는 튀는 소리·날카로운 고음이 없도록 같은 정리 과정을 거친다(30 Hz 아래 제거, 4.5 kHz부터 완만히 줄이고 12 kHz 위 제거, 30 ms 순간 음량을 400 ms 평균의 2배 이하로 제한). 출처와 수치는 [소리 출처](../designs/final/assets/audio/SOURCE.md)를 본다.

## 하차 전 도착 안내 — 2026-10-13

여행 진행이 끝나면 바로 하차 태그로 넘어가지 않고 여행 화면에 도착 안내를 띄운다. 노선(버스 번호 · 도착 정류장 도착)과 ‘곧 ○○에 도착합니다 · 버스가 멈추면 일어나주세요 · 카드를 찍고 내려주세요’, **확인** 버튼이다. 도착 시점에 하차 대기 상태로 저장하므로 안내 중 앱을 벗어나도 이어가기에서 하차 태그로 돌아온다. 안내 중에는 일시정지할 수 없고 완료 기록을 만들지 않는다. 확인하면 하차 태그 화면으로 가고 포커스는 카드에 둔다.

## 이전 승차 태그 계약 (2026-10-12, 위 절이 우선)

외부 제목·출발지·상단 태그 표기·뒤로가기·별도 수동 태그 버튼은 표시하지 않습니다. 중앙 단말기와 카드, 두 번 움직이는 올림 안내를 사용합니다. 카드 자체의 터치·Enter/Space와 드래그 접촉은 유지합니다.

LCD 상단은 Focus Mate와 실제 로컬 HH:mm이고 버스 번호를 표시하지 않습니다. 인식 후 현재 카드 이름과 ID를 보여줍니다(웹 프로토타입 기준. iOS는 카드 이름과 체크만 보여주고 번호를 표시하지 않는다 — 2026-10-13 결정, W04 구현). 일반 동작은 접촉 이동 300ms → 인식 유지 1400ms → 페이드 450ms → 여행 화면의 출발 안내입니다. **저장은 인식 접촉 성공에서 수행하며 마지막 화면 전환까지 미루지 않습니다.** 동작 줄이기는 접촉 이동·페이드·햅틱을 생략하고 인식 유지와 상태 안내를 남깁니다. 단계별 장면/token/숨김 검증으로 늦은 전환을 막고 접촉 후 저장은 보존합니다. 하차 타이밍은 이번 변경 대상이 아닙니다.

## 출발 안내 — 2026-10-13

> iOS(W04)는 이 절이 아니라 위 [2차](#태그안내승차권준비-허브--2026-10-13-2차)의 출발 안내(세 문장 약 1.7초씩, 마지막 문장과 **시작** 버튼, 노선 정보 없음)를 따른다. 최신 시안 DO8HO와 일치하기 때문이다. 이 절의 '노선 + 0.7초 간격 + 확인' 계약 정리는 별도 문서 작업으로 남긴다.

승차 인식 뒤 여행 화면으로 바뀌면 지도와 버스 위에 출발 안내 패널을 띄운다. 노선(버스 번호 · 출발 → 도착)과 ‘문을 닫습니다 · 자리에 앉아주세요 · 버스 출발합니다’ 세 줄을 0.7초 간격으로 보여주고, **확인**을 눌러야 버스가 움직이고 남은 시간이 줄어든다. 안내 중에는 하단 남은 시간·정류장·거리, 지도 도구, 일시정지·정류장 목록을 숨기고 일시정지할 수 없다. 포커스는 확인 버튼에 두고 확인 뒤 일시정지 버튼으로 옮긴다. 동작 줄이기에서는 세 줄을 한 번에 보여준다.

진행 여정은 승차 인식 접촉에서 이미 저장되므로 안내 중 앱을 벗어나도 저장은 남는다. 메인에서 이어가기로 돌아올 때 출발 대기 여정(‘시작’ 전)은 이 출발 안내부터 다시 보여 주고(저장 없음), 출발 뒤 여정은 안내 없이 바로 여행 화면으로 간다. 장면이 바뀌면 안내를 닫는다.

## 집중 화면 지도 도구와 하단 정보 — 2026-10-13

오른쪽 위에는 동그란 버튼 두 개만 세로로 둔다. 위는 **버스 따라가기**, 바로 아래는 **지도 테마**(지도 아이콘)다. 2D/3D·나침반·전체 노선 버튼은 2026-10-13 3차에서 화면에서 뺐고, 지도는 기울인 3D 시점을 기본으로 유지한다. 지도를 끌면 자유 탐색이 되고 따라가기를 누르면 버스로 돌아온다. 왼쪽 위의 일시정지·정류장 목록은 그대로다. 지도 테마 시트는 어두운 지도(기본)와 위성, 정류장 표시 켜기/끄기를 제공한다. 일시정지·장면 이탈 시 시트를 닫고 지도 도구를 비활성화한다.

하단의 남은 시간·남은 정류장·남은 거리는 라벨 위·숫자 아래로 두고 좌우 16px 여백에 붙인다. 남은 시간은 왼쪽, 남은 정류장은 가운데, 남은 거리는 오른쪽 정렬이다. 숫자는 지금 크기(30px 굵게, 흰색)를 유지하고, 라벨(12px)과 단위 min·개·km(15px)는 작게 줄여 64% 흰색(회색)으로 둔다.

iOS에서는 지도 테마 시트·버스 따라가기를 직접 구현한다. Apple 지도 표기는 남은 시간 위 왼쪽에 두고 가리지 않는다. 프로토타입의 위성은 생성 지도에 색 필터를 씌운 시연이며 실제 위성 사진이 아니다. 3D 시점은 CSS 원근 기울기로 흉내 낸다.

## iOS 승차권·승차 태그 — 2026-10-15 (W04)

- 준비 허브 '승차권 보기'는 준비(여정·태그·공백 아닌 할 일)가 완성됐을 때만 승차권을 연다. 승차권 단계는 아무것도 저장하지 않는다. 버스 번호·여행 시간은 화면 글자가 아니라 낭독 라벨에만 있다.

- 인식 0.3초 뒤 진행 여정을 1회 저장한다(승차권 보기로 확정한 준비 값). 인식 뒤에도 왼쪽 위 뒤로가기는 남고, 이탈·백그라운드는 늦은 화면 전환만 취소하며 저장은 유지한다. 백그라운드에서 돌아오면 다시 태그할 수 있다(새 인식은 진행 여정을 교체, 최대 1건). 저장 실패면 전환하지 않고 같은 화면에서 다시 태그한다.
- 1400ms 유지·450ms 페이드 뒤 여행 화면으로 바뀌며 경로에는 여행만 남는다. 출발 안내 중에는 뒤로가기가 없고, '시작'을 누르면 출발 확인을 저장하고 W05 전까지의 임시 '여행' 화면을 보여 준다(뒤로가기 → 메인).
- 진행 여정이 있으면 메인에 이어가기 카드가 뜨고(재실행·이탈 복귀 모두), 시작 버튼은 '새 여정 시작'이 되어 확인 창을 거친다. 계약은 아래 [iOS 포기·이어가기·생명주기](#ios-포기이어가기생명주기--2026-10-15-w07)를 따른다.
- 저장 형식(W04 당시 버전 3, 현재는 W05의 버전 4): `app-state.json`의 `journey.active`는 null 또는 진행 여정 1건이다(선택 입력·태그 정의·소리·승차 시각·phase·진도만, 정류장 이름·거리는 저장하지 않음). 진행 여정만 손상되면 그 여정만 버리고 카드·기록은 그대로 읽는다(“손상 데이터는 정리 전까지 보존” 원칙의 예외 — 버린 여정은 다음 저장 때 원본 사본 없이 사라진다. W05 착수 전 사본 보관을 재검토). 쓰기는 구조 검증을 통과한 값만 받는다.
- 동작 줄이기는 진입 연출·점선 깜빡임·접촉 이동·페이드·진동을 생략하고 1400ms 유지와 상태 안내는 남긴다. 출발 안내는 세 문장을 한꺼번에 보여 준다.

## iOS 실제 분 타이머·일시정지 — 2026-10-15 (W05)

> iOS는 웹 공통 규칙의 "앱 밖 시간은 진도에 추가하지 않습니다"와 여행 `focus`의 "백그라운드 정지"를 따르지 않는다. 사용자 결정(2026-10-15): 이 앱은 보조 도구라 다른 앱 사용·제어 센터·백그라운드 중에도 타이머가 흐른다.

- 출발 안내의 **시작**을 누르면 같은 화면이 타이머로 바뀐다. 남은 시간은 "N min"(올림, 초·시 표기 없음)이고 일시정지/재개 버튼 하나만 둔다. VoiceOver는 "타이머, 남은 시간 N분"으로 읽고, 값이 바뀔 때마다 자동 낭독하지 않는다. 전환에 성공하면 "일시정지됨"·"재개됨"을 1회 알린다.
- 진도는 앱 프로세스가 살아 있는 동안의 단조 시간(ContinuousClock)이다. 비활성·백그라운드·잠자기 중에도 흐르고, 기기 시계를 바꿔도 영향받지 않는다. 진행 중에는 10초마다, 일시정지·재개·백그라운드 진입·도착 때는 즉시 저장한다. 복귀하면 흐른 시간을 바로 반영하고, 그 사이 0초가 됐으면 도착 상태다.
- 앱이 종료되면 여정이 끊긴 것으로 본다. 다시 실행하면 메인으로 가고 진행 여정은 마지막 저장 진도의 일시정지 상태로 남는다(종료 중 시간 미가산, 강제 종료 손실 최대 약 10초). 메인에서 이어갈지·새 여정을 갈지 고르는 동작은 아래 W07 절이 정한다.
- 출발한 여행 화면에서는 메인으로 갈 수 없다(뒤로가기 버튼 숨김, 스와이프 뒤로가기 차단). 나가는 길은 일시정지 중 포기뿐이다(W07 절). 출발 뒤에는 승차권·승차 태그로 다시 갈 수 없고, '시작'에 성공하면 준비 확정값을 정리한다. '시작' 전 재승차는 진행 여정을 덮어쓴다.
- 0초에 도달하면 진도를 총 시간으로 저장하고 여행 화면 위에 도착 안내를 띄운다. 재개·재시작 수단은 없다. 도착 안내·하차 태그·완료 기록은 아래 W09a 절이 정한다.
- 저장 실패: 일시정지·재개·시작은 전환하지 않고 "저장하지 못했어요. 다시 눌러주세요."를 보인다. 주기·백그라운드 저장이 실패하면 타이머를 일시정지하고 "진도를 저장하지 못해 멈췄어요. 재개를 눌러주세요."를 보이며, 재개가 곧 재저장이다. 도착 저장 실패는 도착 화면에 경고를 두고 백그라운드 진입·재진입 때 다시 저장한다.
- 저장 형식은 버전 4다. 진행 여정에 `paused`가 추가됐고, 버전 3 파일은 읽을 수 있다(출발 완료는 일시정지로 읽음). 진행 여정은 분 1~360, 경과 0~분×60, 정류장·버스 id가 카탈로그 값이어야 하며, 어긋나면 그 여정만 버리고 카드·기록은 유지한다(백업·안내 없음). 카탈로그가 바뀌면 기존 여정이 조용히 버려진다.

## iOS 포기·이어가기·생명주기 — 2026-10-15 (W07)

- **메인 이어가기 카드**: 진행 여정이 있으면 임시 안내 대신 카드가 뜬다. 제목 "잠시 멈춘 여정이 있어요.", 할 일, 버스(종류·번호), "N min 남음"(타이머와 같은 올림), "{태그} · {도착지}까지", 버튼 "이전 여정 이어가기 →". 시작 버튼은 "새 여정 시작"으로 바뀐다. 진행 여정이 없으면 확인 없이 바로 시간 선택이다.
- **이어가기는 바로 흐름**: 누르는 순간 (저장된 경과, 일시정지 해제)를 1회 저장하고 타이머를 진행 중으로 연다. 흐르는 시간은 화면이 열린 시점부터 센다(메인에 머문 시간·종료 중 시간은 더하지 않음). 열릴 때 VoiceOver에 "이전 여정을 남은 시간부터 이어갑니다."를 1회 알리고 화면에는 쓰지 않는다. 저장 실패면 이동하지 않고 메인(`main.saveFailure`)에 "저장하지 못했어요. 다시 눌러주세요."를 보이며 저장값은 그대로다. 연타해도 저장·이동은 1회다.
- **새 여정**: 확인 창 "새 여정을 시작할까요?" / "이전 여정은 그만두고 새 여행을 준비해요. 완료 기록은 남기지 않아요." / "이전 여정 유지하기"(기본, 닫기만) · "새 여정 시작". 확정하면 한 번의 저장으로 현재 정류장을 그 여정의 도달 정류장으로 바꾸고 진행 여정을 지운 뒤 시간 선택으로 간다. 실패면 이동 없이 메인에 안내하고 아무것도 바꾸지 않는다.
- **포기**: 타이머가 일시정지일 때만 하단 '포기하기'(`journey.abandon`)가 있다. 진행 중(이어가기 직후 포함)·도착·출발 안내에는 없다. 확인 창 "여행을 그만둘까요?" / "지금 도달한 정류장에서 다음 여행을 시작할 수 있어요. 완료 기록은 남기지 않습니다." / "계속 여행"(기본, 일시정지 유지·포커스는 포기하기로 복귀) · "그만두기". 확정하면 한 번의 저장으로 도달 정류장을 현재 정류장(방향 유지)으로 저장하고 여정을 지운 뒤 메인에서 "{정류장}에서 여행을 마쳤어요. 완료 기록은 남기지 않았어요."를 보인다(저장하지 않는 안내, 낭독 1회). 실패면 타이머 화면에 머물고 `journey.timer.saveFailure`가 "저장하지 못했어요. 다시 눌러주세요."를 보이며 정리됐다고 안내하지 않는다. 연타해도 대화상자·저장·이동은 1회다.
- **도달 정류장**: 저장된 경과 초 ÷ (버스 정류장 간격 분 × 60)의 몫만큼 출발 정류장에서 방향대로 간 순환 정류장이다(총 정류장 수를 넘지 않음). 간격은 2014번 5분·강남02 6분·343번 8분이다. 예: 2014번 25분, 성수역 정방향 출발이면 299초는 성수역, 300초는 성수동, 1499초는 서울숲역, 1500초(도착)는 서울숲 입구다.
- **확인 창 중 백그라운드·종료**: 확정 전에는 아무것도 바꾸지 않는다. 백그라운드를 다녀와도 창과 기본 선택이 그대로이고, 종료 뒤 재실행하면 종료 중 시간 없이 마지막 저장 진도의 일시정지 여정이 카드로 남는다. 이어가기 직후 종료해도 여정은 한 벌이고 일시정지로 복원된다.
- **도착 여정**: 메인 카드는 "도착한 여정이 있어요"와 '하차하기'만 둔다(아래 W09a 절). 이어가기·새 여정으로 도착 여정을 정리하는 길은 없다.
- **출발 대기 여정**: 카드의 남은 시간은 전체 시간이다. 이어가기는 출발 안내부터 다시(저장 없음), 포기 버튼은 없다. 이어간 뒤 그만두려면 '시작' → 일시정지 → 포기의 3단계가 필요하다. 출발 안내에 포기가 없고 뒤로가기도 막혀 있기 때문이며 PRD가 정한 범위이므로 결함이 아니다.
- **손상 여정**: W05 규칙대로 조용히 버려진다. 카드도 "불러오지 못했어요" 안내도 없다.
- **나가기**: 여정을 남긴 채 메인으로 나가는 버튼은 만들지 않는다(사용자 결정). 출발 뒤 타이머 화면에서 메인으로 가는 길은 포기뿐이다.
- **포기·새 여정은 완료 기록을 만들지 않는다.** 완료 기록은 하차 태그 성공(아래 W09a 절)에서만 만든다. 저장 형식은 바뀌지 않는다(v4).
- 확인 창이 열릴 때 첫 VoiceOver 포커스가 안전한 선택에 가는지는 Simulator에서 확인하지 못해 W14 실기기 확인으로 넘겼다.

## iOS 도착 안내·하차·요약·기록 — 2026-10-15 W09a

- **도착 안내**: 타이머가 0초가 되면 여행 화면 위에 도착 안내가 뜬다. 노선은 "버스번호 · 도착지 도착"이고, 세 문장이 1.7초 간격으로 차례로 나타난다. 동작 줄이기에서는 세 문장을 한꺼번에 보인다. 도착 상태에서는 타이머·지도 내용을 그리지 않고 안내만 보인다. 확인을 누르면 하차 태그로 간다.
- **도착 저장**: 도착 저장의 주인은 타이머다. 확인 시 저장된 여정이 아직 도착 상태가 아니면 타이머가 저장을 다시 시도하고, 실패하면 안내에 머문다.
- **하차 태그**: 승차 태그와 같은 조작이다. LCD는 "하차 준비"에서 카드 이름과 체크로 바뀐다. 뒤로가기는 없고 첫 초점은 카드다.
- **하차 저장**: 접촉에 성공하면 저장 1번으로 완료 기록 생성, 도착지를 현재 정류장으로 변경(방향 유지), 진행 여정 제거를 함께 한다. 실패하면 화면에 머물고 다시 태그할 수 있다. 중복 접촉은 무시한다.
- **요약 전환**: 접촉 성공 1.4초 뒤 0.45초 전환으로 요약이 열린다. 하차 저장 뒤 백그라운드 등 어떤 중단이 있어도 요약으로 간다.
- **요약**: 한 일·시간·도착 정류장을 보이고 200자까지 선택 메모를 쓸 수 있다. '메인으로'를 누르면 메인으로 간다. 메모를 쓰지 않아도 된다.
- **재실행**: 요약은 메모리에만 있다. 요약 중 앱을 종료하면 다시 실행할 때 요약 없이 메인으로 가고, 기록은 저장돼 있다. 도착 안내나 하차 태그 중 종료하면 메인에서 도착 카드가 보인다.
- **메인 도착 카드**: "도착한 여정이 있어요"와 '하차하기' 하나만 둔다. 도착 여정이 있으면 여행 준비(새 여정) 메뉴를 숨기고 새 여정 확정도 거부한다. 임시 '새 여정 시작'과 "도착했어요" 화면은 없다.
- **기록 잔디**: 연 단위로 하루 합계에 따라 0분은 0단계, 1~30분 1단계, 31~60분 2단계, 61~120분 3단계, 121분 이상 4단계로 칠한다. 격자 전체는 VoiceOver 조정 요소 하나이고 하루씩 이동한다. 칸을 탭하면 선택되고 미래 날짜는 선택할 수 없다.
- **기록 목록**: 요약 줄은 "N회 여행 · N일 · 시간"이고 0분이면 시간을 생략한다. 선택한 날짜의 기록을 최신순 10개까지 보이고 '더 보기'로 이어 본다. 빈 안내 문구는 두 가지이고 예시 기록은 없다.
- **연도 이동**: 이전/다음 버튼과 연도 메뉴로 옮기며 올해 이후로는 갈 수 없다. 연도를 옮기면 올해는 오늘, 그 밖의 해는 그 해 가장 최근 기록일, 기록이 없으면 1월 1일이 선택된다.
- **메모 수정**: 기록에서 '메모 남기기'/'메모 수정' 시트로 200자까지 쓴다. 저장에 실패하면 입력을 유지한다.
- 저장 형식은 v4 그대로다. 분석 화면(주/월·태그·인사이트)은 W09b로 분리했다. 실기기 VoiceOver(잔디 조정·첫 초점)·햅틱·큰 글자 확인은 W14다.
