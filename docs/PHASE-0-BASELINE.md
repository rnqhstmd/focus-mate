## 자동 검사

```sh
npm run build
npm run check:baseline
npm test
```

기존 빌드는 `python` 명령이 있는 환경이 필요하다. 이번 실행은 Codex에 포함된 Python 환경으로 같은 빌드 명령을 실행했다. Node 테스트는 외부 테스트 라이브러리를 추가하지 않고 실행한다.

검사기는 필수 파일·HTML/자산 복제본, 실제 HTML의 `productSceneIds`·`sceneIds`·`requiredBaselineReviews`, 실제 뷰어의 `cases`, 레이어 상태, 내보낸 Pen 노드 연결을 검사한다. HTML/뷰어 코드를 실행하지 않으며 `.pen`은 존재만 확인한다. Pen 내용과 시각 결과는 Pencil MCP/편집기에서 확인한다.

CLI는 무인자 또는 `--root <폴더>`만 허용한다. 미지원 옵션·추가 인자·누락/없는 폴더는 JSON 오류와 exit 1을 반환하며 기본 폴더로 대신 검사하지 않는다. 원본의 필수 검토 목록과 연결표를 대조하여 검토 항목을 삭제해 완료 조건을 우회하지 못하게 한다.

정상 자료는 exit 0, 자료 오류는 파일/장면/노드가 포함된 JSON과 exit 1을 반환한다. `automationPassed`는 자료 검사이고 `phase0Complete`는 자료 통과와 수동 확인 상태를 함께 본다. `pendingReviews`가 남아 있으면 완료로 표시하지 않는다. 수동 확인 상태는 담당자가 근거를 검토해 변경하는 선언이며 자동 시각 검증 증거가 아니다.

이번 TDD는 실제 임시 파일과 CLI 실행으로 정상 자료·복제본 불일치·누락·잘못된 경로·잘못된 연결·검토 상태·기준선 파일 손상을 확인한다. 기존 VM 회귀의 승차 인식/유지·중복 접촉·장면 이탈/숨김·저장/복원을 유지한다. VM은 실제 DOM 렌더·터치·청취·실기기 검증과 구분한다.

## 남은 확인

| 항목 | 상태 | 완료에 필요한 근거 |
|---|---|---|
| 최신 승차 단말기 | 대기 | 최신 HTML의 일반/작은 화면, 드래그·터치·키보드, 인식 유지/전환·이탈 검증 |
| 태그 선택 중간 화면 | 대기 | `tags`는 제품 장면이지만 42개 상태에 독립 캡처가 없다. 제품 흐름에서 열어 화면·뒤로가기·초안 보존을 확인하고 시안/캡처를 연결 |

과거 42개 브라우저 캡처와 최신 42페이지 Pen PDF는 검증 시점·렌더러가 다르다. 후속 승차 변경 이후 브라우저 재검증으로 해석하지 않는다. 최신 승차의 VM/Pen 근거는 [승차 보고서](../reports/boarding-reader-refinement-2026-10-12.md)에 있다.

Pencil MCP로 현재 편집 파일 연결과 42개 개선 상태 노드를 확인했다. JSON 경로의 벡터 표기·기본값 정규화로 전체 레이어의 바이트 동일성을 보장하지 않으며, 이 검사도 그 동일성을 주장하지 않는다. iPhone VoiceOver·큰 글자·햅틱·오디오와 실제 앱 생명주기는 Phase 6에서 별도 검증한다.

## 갱신 규칙

제품 흐름 또는 디자인 상태를 바꾸면 연결표와 해당 화면의 검토 상태를 함께 갱신한다. 원본 HTML 변경 후에는 빌드로 실행용 자료를 다시 묶고 검사를 실행한다. 미검증 항목을 `passed`로 바꾸거나 후속 네이티브 단계의 상태를 완료로 바꾸지 않는다.
