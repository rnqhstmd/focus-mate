# 버스에서 할 일 준비 흐름

사용자 요청: 준비 제목은 '버스에서 할 일', 기본 태그를 미리 지정하지 않는다. 할 일(태그)과 소리는 별도 항목을 눌러 편집하고 돌아온 뒤 완료를 눌러 탑승 패스로 이동한다.

## 현재 결정
시간 선택 → 버스에서 할 일 허브 → 할 일(태그)/소리 편집 → 허브 완료 → 탑승 패스.

- 새 여행의 태그·할 일은 미선택으로 시작한다. 태그 선택과 비어 있지 않은 할 일을 저장해야 완료할 수 있다.
- 할 일(태그)을 누르면 태그를 고르고 내용을 입력하는 편집으로 연결한다. 최근 예시는 사용자가 눌렀을 때만 값을 채운다.
- 소리를 누르면 별도 선택 화면을 열고 확인 후 허브로 돌아온다. 소리 없음이 초기값이며 음량은 기기 음량을 사용한다.
- 태그 생성·편집 저장은 준비 편집으로 돌아간다. 태그/소리 편집 저장만으로는 탑승 패스로 가지 않는다.
- 취소는 저장된 값을 복원하고, 저장은 허브에 요약한다. 허브에서 시간 화면으로 돌아갔다가 다시 와도 이번 여행 준비값을 유지한다.
- 탑승 패스 뒤로는 허브로 돌아간다. 다음 새 여행에서는 할 일 선택을 다시 요구한다.

이번 결정은 이전의 태그·소리 선택/태그 편집 저장 후 승차권 직행 규칙을 대체한다. HTML 프로토타입 기준이며 Pen/PDF/이전 PNG는 이전 시안이다.

## 검증
새 흐름 및 기존 여행 계산·중단·접근성 회귀 결과를 구현 후 추가한다. 브라우저 접근 거절을 우회하지 않으므로 실제 화면·터치·음향 품질은 미검증이다.

## 최종 상태 검증
구문과 회귀 스크립트 직접 실행 및 독립 검증 PASS. 기본 태그·할 일 미선택/소리 없음, 준비 전 탑승 차단, 태그 생성 저장→할 일 편집, 할 일/소리 저장과 취소→허브, 완료→탑승, 시간/탑승 뒤로 값 유지, 새 여행 초기화, 미준비 카드 탭/기록 차단을 확인했다. 입력 초안과 저장된 값의 취소 경계를 추가 검사했다.

14개 화면의 196개 포커스·숨김 전환 및 392개 지연 전환 취소, 기존 정방향 173,376개/역방향 260,064개 assertion도 유지했다. 접힌 노선의 ARIA·포커스·중단 취소 상태 보존과 h/min 및 s 카운트다운도 통과했다. 실제 렌더링·터치·음향은 미검증이다.
