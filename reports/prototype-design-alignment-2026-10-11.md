# 시안과 프로토타입 시작 흐름 정합

기준: `designs/final/01-plan.png`, `screens/01.png`–`08.png`, `SCREENS.md`.
사용자 요청: 시안의 시작 흐름을 HTML 프로토타입에 구현한다.

## 수정 기준

이전 HTML은 정류장을 미리 선택하고 버스·태그를 큰 홈 패널에 합쳤다. 이번에는 시안을 기준으로 정류장 선택과 여행 준비 화면을 분리한다. 이름은 Next Step · 다음 정류장을 유지한다.

추가 사용자 요청으로 화면 문구는 '집중' 대신 '여행'으로 통일한다. 버스 번호에는 유형·아이콘·색을 더하고, 지도 경로도 선택 버스의 색으로 연결한다. 안내 글꼴은 서울시 공식 서울알림체를 사용한다. 따라서 시안의 화면 구조를 기준으로 하면서 이 추가 요청의 색상·서체·문구를 함께 적용한다.

후속 결정: 자리 선택은 제거한다. 태그와 소리는 같은 준비 화면에서 선택하며 앱 내 음량 조절은 제공하지 않는다. 기기 음량을 사용한다. 태그·소리 선택 완료 또는 태그 편집 저장 후에는 카드 태그 화면으로 바로 이동한다. 시간 단위는 25 min / 2 h / 2 h 30 min 형식으로 표시한다.

| 시안 | HTML의 동작 |
|---|---|
| 01 첫 이용 | 지도 위 브랜드와 안내 시트, 출발 정류장 선택으로 연결 |
| 03 정류장 검색 | 검색 입력·결과 선택·빈 결과·취소 |
| 02 정류장 홈 | 상단 현재 정류장 카드, 지도 핀, 하단 방면·버스 선택과 시작 버튼 |
| 05 시간 선택 | 선택한 버스의 눈금·경로·목적지와 준비 화면 연결 |
| 06 할 일 | 입력, 최근 예시, 태그 변경, 선택한 할 일로 여행 |
| 07 태그·소리 준비 | 태그 목록·새 태그 만들기와 소리 선택을 합치고 완료 시 승차권으로 연결 |
| 08 태그 편집 | 이름·아이콘·색·기본 시간, 빈 이름·중복 검증, 저장 후 승차권으로 연결 |

홈에 합쳐 놓았던 태그 선택은 제거한다. 태그의 기본 시간은 제안이며 이미 고른 이번 여행 시간을 임의로 변경하지 않는다. 뒤로·닫기·취소 시 준비 입력과 선택 상태를 보존한다. 출발 방면·정류장이 달라지면 현재·다음·도착·경로를 함께 갱신한다. 09의 자리 선택과10의 독립 소리·음량 화면은 후속 결정으로 현재 흐름에서 제외한다.

첫 이용 완료와 선택 정류장은 브라우저 로컬 설정으로 복원하되 저장 접근 실패도 정상 동작하게 처리한다. 미리보기에서 첫 이용을 다시 시작할 수 있다. 실제 위치·운행 정보·iOS 권한을 요청하는 앱은 아니며 정류장은 예시 데이터다.

## 기존 동작 유지

버스별 유효 시간, 관성 선택, 카드 터치, 여행·도착·하차, 현재 정류장 갱신, 정류장 경계 오차 보정, 지연 전환 취소, 접근성 포커스, 좁은 화면 스크롤, 이미지 대체 표시를 유지한다. 실제 버스·지도 API와 기존 전체36개 시안의 모든 화면을 구현했다고 주장하지 않는다.

## 검증 기록

최종 소스에서 `scripts/prototype-edge-qa.cjs`를 직접 실행해 PASS를 확인했다. 정방향 6,192개 조합·173,376개 assertion, 역방향 6,192개 조합·260,064개 assertion, 정확한 정류장 경계 5,658개(불일치 0), 12개 화면의 144개 포커스·숨김 전환 및 288개 지연 전환 취소를 검사했다. JavaScript 구문 검사와 독립 검증도 통과했다.

첫 이용·검색·저장소 접근 거부·할 일 입력·태그 생성/편집/취소·중복 및 빈 이름·h/min 표기·태그와 소리 선택 후 바로 탑승·선택 취소·기록의 공개 버스 번호를 검증했다. 검토 중 발견한 할 일 초안 손실과 기록의 내부 버스 번호 노출을 수정했다. 입력 오류는 해당 필드의 포커스와 aria-invalid로 연결했다. WebAudio 모형 검사에서 시작·일시정지·복귀·숨김·도착·무음 처리를 확인했다.

브라우저 접근의 저장된 거절 설정 때문에 실제 렌더링·터치·음향 품질은 미검증이다. 이번 변경은 HTML 프로토타입과 자산 기준이며 Pen·PDF·기존 화면 PNG는 이전 시안이다.

## 출발 방면 선택과 홈 목록 단순화

후속 사용자 결정에 따라 별도의 반대편 확인 화면과 홈 방향 변경 버튼을 제거했다. 검색 결과는 같은 정류장 이름 아래에 `성수동 방면` 또는 `성수사거리 방면`을 표시한다. 검색에서 선택한 승차장을 출발 버튼으로 적용하면 바로 홈으로 이동한다. 검색·홈·버스 목록의 방면은 같은 정류장 계산을 사용한다. 첫 이용 검색은 출발 정류장을 고르도록 안내하고, 이후 출발 변경 검색은 새 위치에서의 여행을 안내한다. 저장된 출발 정류장과 내부 양방향 경로 계산은 유지한다.

홈의 버스 목록은 배지·번호·방면을 묶은 최소 56px 행으로 줄였다. 홈 내용만 스크롤하고 버스 목록은 그 안에서 펼쳐지며, 앱 안 스크롤바는 숨겼다. 스크롤 영역은 키보드로 접근할 수 있고 여행 시작 버튼은 별도 고정 영역에 있다. 아래 내용을 암시하는 옅은 페이드를 적용했다.

홈 지도에도 선택한 버스의 색상 경로와 출발·예상 도착을 표시한다. 버스를 고른 뒤 목록이 닫혀도 미리보기는 유지되며, 안내에는 가상 노선 예시임을 표시한다. 홈 경로는 상단 정류장 카드와 하단 패널 사이의 별도 높이로 제한한다. 낮은 화면에서는 이 영역을 더 줄인다. 실제 화면 배치와 터치 감각은 브라우저 권한 제한으로 검증하지 못했다.

후속 최종 검증: 확인 화면을 제거한 현재 12개 화면·144개 포커스/숨김 전환·288개 지연 전환 취소를 통과했다. 방면 선택과 검색 취소/저장 복원, 3개 버스의 홈 경로·색·목적지, 단일 스크롤·compact 행·고정 CTA 정적 규칙을 추가 확인했다. 기존 정방향/역방향/경계 검증과 구문 검사, 독립 검증도 PASS다.

최신 소스에서 `node --check /tmp/next-stop-final-script.js`와 `node scripts/prototype-edge-qa.cjs`를 직접 실행해 모두 종료 코드 0을 확인했다. 기존 정방향·역방향 수치 회귀와 정류장 경계 검사는 PASS이며, 장면은 12개로 줄어 144개 포커스·숨김 전환과 288개 전환 취소가 PASS했다. 새 검사는 같은 이름의 방면별 승차장 선택, 검색 취소·저장 복원, 최초 설정/출발 변경 문구, 별도 확인 제거, 세 버스의 홈 경로 색상·목적지, 단일 스크롤·compact 행·고정 CTA의 정적 규칙을 확인했다. CSS 규칙 검사는 실제 렌더링 확인을 대체하지 않는다.
