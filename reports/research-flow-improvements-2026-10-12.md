# 조사 기준을 반영한 시안 개선

기준일: 2026-10-12. 입력은 [상세 비교 조사](pageflows-appshots-spotted-review-2026-10-12.md)이며, 사용자의 “이 MD를 바탕으로 시안을 개선·수정” 요청을 제작 승인으로 삼았다. 핵심 범위로 진행했다. 기존 지도·검정 화면·서울 버스 색·카드 승하차의 정체성을 보존했다.

## 제작 목표와 전략

화면 목적은 사용자가 여행을 준비하고 진행하는 **업무 수행**이다. 최신 HTML의 제품 규칙을 기준으로 Pen과 게시 프로토타입을 통일하고, 준비 단계의 왕복과 완료 후 기록 찾기를 줄인다. 별도의 브랜드 리뉴얼이나 기능 확장은 하지 않는다.

보고서가 이미 제안한 “기준 통일 → 준비 허브 → 카드 전환”을 적용했다. 기존 외형과 동작을 보존하는 최소 개입을 선택했다. 전면 리뉴얼은 승인된 범위보다 넓으므로 채택하지 않았다. 새 리서치는 중복하지 않고 기존 조사에 연결했다.

## 변경 전·후와 근거

| 변경 전 | 변경 후 | 진단·개선 목표 |
|---|---|---|
| Pen·게시 뷰어 36개와 최신 16장면 규칙이 다름 | 최신 제품 규칙을 공유하는 HTML·Pen·프로토타입. 과거 화면은 별도 보존 | P0 기준 통일 |
| 준비 → 태그 → 할 일 → 준비 왕복 | 준비 안에서 태그를 고르고 입력 영역을 바로 펼침 | P1 준비 허브 통합 |
| 준비 확정 버튼 ‘준비 완료’ | 결과가 명확한 ‘승차권 보기’ | 다음 행동의 발견 가능성 |

| 지도 실패 복구 안내 없음 | 초안을 유지하는 다시 불러오기 | P2 오류 복구 |
| 여행 중 소리 실패는 설명만 | 다시 재생·소리 없이 계속. 여행 진도 유지 | P2 오류 복구 |
| 장면 전환에서 화면 전체 축소·깜빡임 | 짧은 덮개 전환, 카드만 승하차 순간 강조 | 한 조작에 주요 전환 하나 |

## IA와 화면 목적

```text
지도 메인 → 첫 이용만 소개·출발 정류장 검색
          → 현재 정류장·버스 → 시간·도착지
          → 준비 허브〔태그 → 할 일 / 선택 소리〕
          → 승차권 → 카드 터치 → 여행 지도
                                ├ 정류장·지도 탐색
                                ├ 멈춤 → 재개 / 종료 확인
                                └ 도착 → 카드 하차 → 갱신된 지도 메인
                                                     └ 기록 → 선택 메모
```

15개 논리 장면과 추가 상태를 포함한 22개 시안이다. 독립 할 일 화면을 준비 허브로 합쳤다. 시연용 화면 선택·자동 재생은 폰 바깥에 있고 제품 흐름에 포함하지 않는다.

| 화면 | 목적·핵심 과업 | 구조·상태 |
|---|---|---|
| 메인·현재 정류장·버스 | 현재 위치 확인과 다음 여행 시작 | 지도, 현재 정류장, 버스 목록, 단일 시작 행동 |
| 시간·도착지 | 선택 시간의 도착 결과 이해 | 지도와 시간 눈금, 간결한 도착 수치, 미리보기 |
| 준비 | 태그를 먼저 선택하고 할 일 입력 | 태그 버튼, 입력의 점진적 펼침, 선택 소리, 고정 확정 버튼 |
| 태그·소리 편집 | 선택을 변경하고 준비로 복귀 | 이름 중복 오류, 취소 복귀, 미리 듣기·무음 |
| 승차권·성공 | 카드 한 번으로 여행 시작 | 버스·출발/도착·수치, 카드의 누름·성공·자동 이동 |
| 여행·정류장·멈춤·종료 | 진행 확인과 제어 | 지도, 좌측 멈춤·목록, 우측 지도 도구, 총 분 단위 시간 |
| 도착·하차 후 홈 | 하차하고 새 위치로 다음 여행 준비 | 간결한 도착과 카드, 홈 저장 확인 |
| 기록 | 방금 완료한 여행 확인과 선택 메모 | 할 일·출발/도착·태그/시간, 같은 자리 메모 |
| 지도·소리 실패 | 준비·진도를 잃지 않고 복구 | 다시 불러오기·다시 재생·무음 진행 |

## 제작 명세

- 현행 색상: 배경 `#090909`, 덮개 `#0A0A0A`, 보조 글자 `#B5B5BA`, 입력 포커스 `#D7B378`. 버스 유형 색과 기존 카드·지도 자산 유지.
- 웹 서체는 기존 서울알림체. Pen의 편집 가능한 문자에는 지원되는 Noto Sans KR을 사용해 약간의 서체 차이가 있다.
- 기존 간격과 터치 기준을 유지하고, 추가 조작은 최소 44px. 입력은 16px로 브라우저 확대를 방지한다.
- 태그 미선택·할 일 공백·소리 없음으로 시작한다. 최근 할 일 예시, 좌석 선택, 태그 기본 시간, 출발지 재검색을 추가하지 않는다.
- 승하차가 중복 실행되지 않는다. 시간·위치는 멈춤에서 함께 정지한다. 중도 종료에는 완료 기록이 생기지 않는다.
- 톤 다이얼: VARIANCE 2 / MOTION 3 / DENSITY 4. 기존 외형을 유지하고 동작 피드백과 정보 조직만 정리한다.
- 연구 사이트의 화면 자산이나 영상을 복사하지 않았다. 참고는 단계 구분·지도 연속성·카드 의미에 한정했다.

## 자체 검수와 수용 체크

- 축 A: 조사 목표와 현행 규칙 유지. 외부 앱의 좌석·결제·회원 흐름을 섞지 않음.
- 축 B: 실제 브라우저 모바일/데스크톱, 입력·터치·오류·모션 감소, Pen의 크기·잘림·문자 편집을 검수.
- 축 C: 준비 왕복 축소, 도착 결과 표시, 카드 자동 연결, 홈에서 기록 발견, 실패 상태에서 값 보존.
- 한 번의 태그 선택 뒤 같은 허브에서 할 일을 입력할 수 있어야 한다.
- 새 태그·소리 편집 후 초안이 유지되고 탑승으로 직행하지 않아야 한다.
- 필수 준비가 없으면 승차권으로 이동하지 않아야 한다.
- 완료 기록은 한 번 생기고 중도 종료는 완료 기록을 남기지 않아야 한다.
- 지도·소리 오류 뒤에도 여행과 준비를 이어갈 수 있어야 한다.
- Pen에 현재 화면과 과거 화면이 명확하게 구분돼야 한다.

검수에서 소리 복구 조작이 숨겨진 제목 영역 안에 들어간 결함과 PDF의 기록 구분선 마스크가 흰 면으로 변환된 결함을 발견해 수정했다. 소리 복구는 브라우저 조작으로, 기록은 Pen 렌더로 재확인했다. 축 A·B·C의 현재 범위에서 Critical/Major 0건이다. Minor로 남기는 차이는 웹의 서울알림체와 Pen의 Noto Sans KR 서체 차이다. 성능 수치나 실제 사용자 전환율은 측정하지 않았다.

남은 검증 한계: 실제 iPhone의 소프트 키보드·VoiceOver·햅틱·MapKit·실제 버스 정보, 합성 소리의 청취 품질과 사용자 성과는 이 작업으로 검증하지 않았다. 기록·메모는 이번 미리보기 세션 범위이며 기기 간 동기화는 없다. 참고 사이트의 성과 수치를 우리 앱의 개선 효과로 주장하지 않는다.
